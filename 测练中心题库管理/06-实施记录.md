## 2. 实施决策与偏差（相对 01~04 文档）

1. **包名**：用户先建了 `examservice` 包的空壳——以其为准（实施侧曾误建 `exam` 包，已迁移三配置类并删除，记偏差提醒后续 FP 保持 `jack.digityhuman.examservice`）。
2. **超管判定占位**：`isSuperAdmin = userId=="1"`（正式权限码体系未接入本应用）——影响题库删除权/保密库编辑权/分类管理权的超管分支；接入正式权限后替换（已在 AGENTS.md 标注）。
3. **共享范围部门维度**：`sharedLibIdsOf` 按用户部门名反查部门 id 匹配（OrgQueryService 无"按用户查部门 id"契约，走 listUsersByIds→deptName→listAllDepartments 比对）——两步查询，量大时可推动 StaffManagement-api 加契约方法。
4. **分类过滤实现**：`catalog_id IN (前缀下全部分类 id)` 单表 IN 查询（02 §4.2 的 `routing_path LIKE` 适用于 catalog 表本身；lib 表无 routing_path 列，按 id 集合过滤语义等价）。
5. **导出数据/正确率菜单**：置 toast 提示"待 FP-13/FP-16 实施"（施工序安排，非本批次范围）。
6. **树接口 StackOverflow 修复**：种子 root 行 `parent_id='root'` 自指——toNode 递归时 root 成为自己的 child。修法：建 byParent 映射时跳过自指根（冒烟实测发现）。
7. **批量新建管理员语义**：抽屉管理员应用于整批新建的所有分类（原平台截图03 未明确，按最直观语义实施；如与原平台实测不符后续调整）。
