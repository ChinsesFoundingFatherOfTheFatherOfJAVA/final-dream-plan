# 旧数据迁移执行说明

> 版本：v1.0 ｜ 日期：2026-10-30
> 目标：把“设置与内容共用一个版本”的旧数据迁移为“全局设置 + 隐藏工作 v0 + 已发布内容版本”。
> 可执行 SQL：`10-旧数据迁移执行.sql`

## 1. 迁移前置

1. 备份 `final_dream` 数据库。
2. 停止 AtualCombatTraining 写入，或至少暂停主题创建、保存、确认和发布。
3. 先执行 `05-建表SQL.md` 中的新增表与索引。
4. 检查以下表存在：
   - `act_theme`
   - `act_theme_version`
   - `act_scenario_unit`
   - `act_evaluation_dimension`
   - `act_theme_settings`
5. 在预发库执行迁移和验证 SQL。
6. 迁移未通过前不得部署新版应用。

## 2. 旧数据归类

| 主题状态 | 旧 current_version_no | 新规则 |
|---|---|---|
| 已发布/暂停/结束 | `n >= 1` | `working=n`、`published=n` |
| 从未发布但有内容 | `n >= 1` | 复制为隐藏 v0，`working=0`、`published=null` |
| 从未发布且已有 v0 | `0` | 保持 v0 |

所有 `v0` 都是内部工作版本，不进版本历史，不对学员返回。

## 3. 脚本执行内容

`10-旧数据迁移执行.sql` 会：

1. 创建迁移前备份表：
   - `act_migration_backup_theme_v1`
   - `act_migration_backup_version_v1`
   - `act_migration_backup_material_v1`
2. 条件增加新列。
3. 创建全局设置表。
4. 为从未发布主题创建 v0 版本行。
5. 将旧 current version 的场景复制为 v0 场景。
6. 按 `sort_order` 将评估维度映射到 v0 场景。
7. 从旧 current version 回填全局设置。
8. 回填 `working_version_no/published_version_no/first_published_at`。
9. 输出迁移统计。

## 4. 场景和维度映射

旧版本：

```text
act_scenario_unit(theme_id, version_no, sort_order, id)
act_evaluation_dimension(scenario_unit_id, dimension_name, weight, sort_order)
```

迁移映射：

```text
oldUnit(theme,current,sortOrder)
  -> newUnit(theme,0,sortOrder)
  -> copy dimensions from oldUnit.id to newUnit.id
```

使用 `sort_order` 是因为复制场景会生成新主键，不能继续使用旧 `scenario_unit_id`。

## 5. 全局设置迁移

旧 `act_theme_version` 中：

- `plan_start_time/plan_end_time`
- `total_drill_count/per_scene_limit/join_mode`
- `training_mode_enabled/assessment_mode_enabled`
- `coach_review_enabled/suggestion_enabled`
- `practice_methods/difficulty/allow_custom_difficulty`
- `face_check_* / screen_switch_*`
- `scene_pass_type/scene_pass_count`

迁入 `act_theme_settings`。

旧 `face_check_stage` 只有 before/ongoing 单值，因此初始回填会把两个新开关都置为旧布尔值，迁移后由管理员校正。

## 6. 迁移后验证

执行 SQL 文件末尾的验证查询，必须全部满足：

- 每个主题都有一行 `act_theme_settings`。
- 每个从未发布主题都有 v0。
- 未发布主题 `published_version_no is null`。
- 已发布/暂停/结束主题 `published_version_no=current_version_no`。
- v0 场景数等于源 current version 场景数。
- v0 维度数等于源 current version 维度数。
- 没有任何非发布主题把 current version 直接暴露为 published。

## 7. 应用切换

迁移完成后同时部署：

- 新 `ThemeSettingsService`：只写 `act_theme_settings`。
- 新 `ContentVersionService`：首次发布创建 v1；发布后 AI 确认创建下一版。
- 新 `ConfirmServiceImpl`：首次发布前写 v0；已发布后直接发布新版本。
- 新 `ProductProfileService`：使用 `content_version_no=0` 表示工作区。
- 新 attempt 服务：只读 `published_version_no`。

旧 `ThemeVersionServiceImpl.saveSettings` 必须停用；不能与新设置服务并行写。

## 8. 回滚

只允许在业务尚未写入新版 attempt/report 时回滚。回滚 SQL 在可执行文件末尾，注释形式提供：

- 删除迁移生成的 v0 场景和维度。
- 删除 `source_type='legacy_working'` 的 v0。
- 新指针恢复为旧 `current_version_no`。
- `act_theme_settings` 和新增列保留，避免再次迁移丢失。

若新版业务已产生 attempt/report，禁止通过删除 v0 回滚；应修复前滚而不是倒数据。

## 9. 验证命令

```powershell
# 仅在测试库执行；连接参数从环境变量读取，不写死密码
mysql --host=$env:ACT_DB_HOST --user=$env:ACT_DB_USER --password=$env:ACT_DB_PASSWORD final_dream < "10-旧数据迁移执行.sql"
```

生产环境若没有 mysql CLI，使用现有 JDBC 迁移器执行同一 SQL，并记录：

- migration version
- 开始/结束时间
- affected theme/version/unit/dimension counts
- 错误信息
