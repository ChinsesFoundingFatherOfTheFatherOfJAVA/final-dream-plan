## 实现顺序

### 阶段 1：迁移与版本拆分

- 增加 `act_theme_settings` 和新版本指针。
- 停止保存设置时 `version+1`。
- 首次发布前只维护内部隐藏 `v0`，不创建可见版本。
- 严格按 `10-旧数据迁移执行.sql` 在测试库验证 v0、场景和维度映射。
- 首次发布创建 v1。
- 已发布后的 AI 确认创建并发布下一版本。
- 发布快照复制产品档案和材料。

完成标志：版本/设置单元测试覆盖所有 D15~D17 规则。

### 阶段 2：参与关系和学员只读

- `act_theme_participant`。
- 学员首页、主题详情、公开加入、练习历程。
- 管理端学员列表和添加/移除。
- 统计从真实 attempt/report 聚合。

完成标志：不同用户隔离，公开加入幂等，计划和状态过滤正确。

### 阶段 3：Attempt 与准备

- preflight。
- attempt 快照和 activeKey。
- 案例脚本复用、随机/自定义脚本生成。
- AIGentService 脚本遵循 `drill-script-v1`。
- 准备事件持久化。

完成标志：准备失败不扣次数；同时只能一场活动 attempt；刷新恢复。

### 阶段 4：训练 WS 与语音

- `/api/act/ws/drill`。
- 消息、事件、心跳、幂等、重连。
- AIGentService drill 接口。
- SpeechTraining 内部 ASR/TTS 适配。
- 教练点评与建议。
- AIGentService SSE 与报告遵循 `08-训考运行态接口与JSON-Schema.md`。

完成标志：一轮消息不会重复落库，断线恢复不重复生成回复。

### 阶段 5：计时、结束、报告

- 正式开始事务扣次。
- deadline、暂停、到时、手动退出、轮次上限。
- 结构化评分与结果判定。
- 一个 attempt 只产生一份报告。
- 再练一次。

完成标志：并发 finish、重复 report、进程重启后的超时恢复均幂等。

### 阶段 6：考核与防作弊

- 训练解锁考核。
- 最大考核次数和追加配额。
- 切屏事件、人脸抓拍、provider 适配。
- 违规结束。

完成标志：禁用考核不能创建、门槛未到不能创建、次数用尽不能创建；考核无教练点评/建议。

### 阶段 7：产品档案与材料

- 产品档案 CRUD 和工作区/发布快照。
- 场景关联。
- 产品档案 artifact 映射遵循 `09-产品档案artifact契约.md`。
- 在线课堂材料 parse-file 卡片事件。
- 学员材料 viewer context 和本地流。
- Office 预览按 `11-本地材料查看方案.md` 实现 PDF/文本双模式。

完成标志：发布后学员只看到冻结内容；跨主题访问返回 403。

## 必需测试

- 版本：首次发布 v1、发布后确认 v2、设置保存不升版。
- 参与：指派/公开、重复加入、移除后历史保留。
- preflight：计划时间、模式、次数、门槛、活动 attempt。
- 扣次：准备失败不扣；正式 start 只扣一次。
- WS：心跳、乱序、重复 clientMessageId、断线恢复。
- 计时：到时由服务端结束，浏览器停表不影响。
- 报告：主动退出 passed=false，目标达成与总分分字段。
- 文件：跨主题越权、未发布材料、Range 请求。
- AI 材料：在线课堂去重、parse-file 消息与材料 tab 同步。
- 运行态 Schema：非法 `drill-script-v1/drill-report-v1` 被拒绝，合法输出可落库。
- 产品档案：稳定 profileKey、引用完整性、发布快照与跨主题 403。
- 数据迁移：v0 场景/维度数量与源版本一致，脚本可重复执行。
- Office：转换成功进入 pdf 模式；无 provider 时进入 text_only 且不阻塞发布。

## API 与代码边界

- 不复制原平台 `xuiappserver` 的接口结构。
- 旧 `ThemeVersionServiceImpl.saveSettings` 必须迁移，不允许双重版本逻辑并存。
- 旧 `ConfirmServiceImpl` 的“覆盖当前版本”需按发布状态分支。
- 旧 `PublishInitServiceImpl` 的“发布完成再建版本”需迁移为“首次发布创建 v1”。
- 前端展示文案不在后端拼 HTML。
- 报告 JSON 必须结构化，不把 Markdown 当作唯一数据源。
