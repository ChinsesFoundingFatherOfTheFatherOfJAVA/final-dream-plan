# 观察记录：AI实战训练场学员端与训考闭环

> 观察时间：2026-10-29
> 原平台：`https://train.chinajack.com/sparring/#/web/drillmate`
> 方式：Ego Browser 实测 ✅、DOM/网络抓包 🧪、用户截图 📸、用户陈述 🧑、当前代码核对 💻
> 说明：本记录合并 Codex 与 DSH 两路勘探结论；只保留清洗后的抓包。

## 1. 核心复现路径

```text
学员端顶部 AI实战训练场
  -> 首页
  -> 我的训练主题
  -> 主题详情
  -> 场景准备
  -> 实战案例 / 随机练习 / 自定义练习
  -> 训练或考核选择
  -> 四步 AI 准备
  -> 练习准备页
  -> 正式对练
  -> 训练报告
  -> 再练一次 / 练习历程
```

管理端路径：

```text
训练主题 -> 主题详情 -> 主题设置
  -> 训练策略 / 混合模式
  -> AI 设计助手 / 产品档案
  -> 学员管理
  -> 学员详情 / 对练记录
```

## 2. 学员首页

### 2.1 布局 ✅

- 浅灰页面背景，顶部保留学员端导航。
- 1200px 内容区三栏：
  - 左：学员概览 280px。
  - 中：快捷入口、我的训练主题、更多学习机会。
  - 右：最近练习 320px。
- 白卡 12px 圆角、24px 内边距。
- 主题卡和最近练习卡 8px 圆角、`#e9e9e9` 边框、16px 内边距。

### 2.2 学员概览 🧑

- 头像、姓名、部门、岗位。
- 四项统计：累计学时、练习次数、参与主题、总荣誉分。
- 不展示“青铜”等段位。
- 总荣誉分首期写死展示。

### 2.3 快捷入口 🧑

- 展示竞技场、荣誉榜、练习历程三个入口样式。
- 竞技场与荣誉榜不做业务，后续可能启用。

### 2.4 我的训练主题 🧪

- 数据来自学员参与关系，不是直接查全部已发布主题。
- 卡片展示场景数、已通过数、进度。
- 最多默认展示 4 个，可展开更多。

### 2.5 更多学习机会 🧪

- 来源是当前学员可加入的主题。
- 首页 `limit=6`。
- 公开加入与申请加入在原平台共用动作；本项目只做公开直接加入。
- 只展示已发布、计划期内、公开且未加入的主题。

### 2.6 最近练习 🧪

- 与练习历程共用数据源。
- 首期取最新 1 条。
- 字段：场景名、状态、主题名、得分、相对时间。
- 点击整卡进入报告；点击查看全部进入练习历程。

## 3. 主题详情

### 3.1 结构 ✅

- Banner：模式、难度、主题名、描述、场景数、已通过数、进度。
- 左栏全部场景卡片，右栏评估标准、学习资料、产品档案、我的训练记录。
- 场景卡展示两位序号、名称、状态、适用人群、练习次数、最高分与操作。

### 3.2 场景状态与动作 ✅

| 原平台条件 | 原平台动作 |
|---|---|
| 已通过/未通过 | 再练一次 |
| 进行中 | 继续练习 |
| 其他 | 开始练习 |

本系统不照抄 `studyStatus/passed` 的含混组合，统一使用 attempt 状态。

### 3.3 最近记录与抽屉 ✅

- 原组件最多显示最近 3 条；用户要求改成最近 1 条作为概览。
- 点击记录或“查看全部”打开 900px 抽屉。
- 抽屉有状态、场景筛选和记录表格。
- 本项目补充学习模式列，并采用服务端分页；详情抽屉默认最近 10 条。

## 4. 场景准备

### 4.1 主弹窗 ✅

- 约 800px 宽。
- 展示场景名、状态、标签、练习次数、最高分、难度、限时。
- 实战案例卡含角色、背景、开场白、难度和开始按钮。
- 展示产品档案、业务目标、影响、失败代价、冲突、失败模式和禁止行为。
- 展示评估维度与权重。
- 底部按主题设置展示随机练习和自定义练习。

### 4.2 案例确认 ✅

- 点击案例“开始练习”后执行资格检查。
- 480px 确认弹窗展示限时、模式说明、教练点评和成绩计入。
- 混合模式同时有训练/考核时展示两条轨道和选择入口。

### 4.3 随机练习 ✅

- 800px 弹窗，选择难度。
- 简单/中等/困难三卡，展示“角色抵触强度”和荣誉分。
- 难度受“允许学员自定义难度”控制。
- 难度不改变场景范围，只改变 AI 角色强度和生成情境。

### 4.4 自定义练习 ✅

- 五步动态向导，左侧步骤栏，右侧内容，底部常驻按钮。
- 关联产品档案。
- 还原场景必填。
- 丰富角色：快捷画像、角色名、身份、性格、背景。
- 选择难度。
- 预览确认。

设置关闭产品档案或自定义难度时，对应步骤会跳过，所以实现必须是动态步骤而不是写死五步。

## 5. 准备与正式训练

### 5.1 跳转与准备 ✅🧪

原平台从 `/sparring` 跨到 `/drillmate`。本项目改为同路由族 `/sparring/web/drillmate/attempt/:attemptId`。

原平台准备页展示四阶段：

1. 分析场景信息。
2. 构建对话剧本。
3. 生成角色身份。
4. 准备就绪。

抓包结论：

- 进度来自 WS 推送，不是 REST 轮询。
- 案例、随机、自定义均生成同一类可用脚本。
- HTTP 只剩会话初始化、历史消息和计时器存档。

### 5.2 练习准备页 ✅

展示：

- 练习目标。
- 沟通指南。
- 业务背景。
- 学员角色。
- AI 演员角色。
- 评估标准。
- 预计用时。
- 开始练习。

### 5.3 限时确认 ✅

- 480px 弹窗。
- 明确点击确认后立即计时，到时自动结束并生成报告。
- 场景限时随场景变化，样例有 15、20 分钟。

### 5.4 对练界面 ✅

- 深色全屏，AI 角色形象和场景旁白。
- 顶部剩余时间、目标达成度、对话方式、聊天记录。
- 右侧背景介绍抽屉 324px，可关闭。
- 底部文字输入、播报、录音和发送。
- AI 台词带 TTS，场景旁白和角色台词区分。

### 5.5 训练教练点评 ✅🧪

- 每轮学员发言后，训练模式先出现教练点评，再出现角色台词。
- 点评按需触发，不是每轮必出现。
- `suggestionEnabled` 时可主动生成建议。
- 考核模式没有教练点评和建议。

### 5.6 语音 🧪

- ASR 用于把录音转文字，文字回填后由学员确认发送。
- TTS 供应商在服务端。
- 原平台抓包出现火山 TTS query `api_key`，该值属于敏感测试凭证，本契约不保留该值。
- 当前系统已存在 SpeechTraining TTS/ASR，优先复用，供应商可替换。

### 5.7 到时与主动结束 ✅

- 服务端时间到自动结束。
- 原平台结束弹窗曾先显示“时间超限，未达成/未通过”，最终报告可能因总分超过通过线而显示已通过，存在短暂口径冲突。
- 本项目把 timeout、targetReached、passed 分开，不复制冲突。
- 手动结束可生成报告，但 passed=false。

## 6. 报告

### 6.1 报告结构 ✅

- 场景、主题、学员、时间、时长、轮次、学习模式和练习类型。
- 已通过/未通过。
- 是否达成目标。
- 综合分与通过线。
- 总体评价。
- 维度得分、权重、公式和证据。
- 优秀表现、改进建议、关键对话、推荐下一步。
- 完整对话回放。

### 6.2 “再练一次” ✅🧪

- 原平台创建新 conversationId，不复用旧会话。
- 进入新的四步准备页。
- 本项目创建新 attempt，继续遵守次数、计划时间和解锁规则。

## 7. 考核与混合模式

### 7.1 管理端设置 ✅

观察样本：

- 训练模式开、考核模式开。
- 训考一体。
- 专家模式。
- 教练点评开，应对建议关。
- 语音对话、文字对话均启用。
- 人脸识别开。
- 切屏不允许。
- 至少训练 1 次解锁考核。
- 最大考核次数 0，含义不限。
- 案例、自定义、随机三种练习均开。
- 主体难度“正常”，允许自定义难度。

规则：

- 训练/考核至少开一个，可同时开。
- 发布后模式开关锁定。
- AI 辅助和防作弊后续修改只影响新 attempt。
- 训练成绩不计入主题通过，考核计入。

### 7.2 学员端表现 ✅

- 混合模式首页和详情显示“训考一体”。
- 训练前考核锁定，提示完成 N 次训练后解锁。
- 完成后“开始考核”可用。
- 考核使用相同准备和对练框架，但没有教练点评。
- 考核报告同样生成结构化维度与目标判定。

### 7.3 防作弊 ✅

- 人脸识别：考核前验证，考核中每 5 分钟抓拍。
- 切屏检测：不允许或允许 N 次，超限自动结束提交。

## 8. 练习历程与管理端

### 8.1 练习历程 ✅

- 四项统计。
- 全部/已通过/未通过/练习中 Tab。
- 所属主题下拉只列有记录的主题。
- 表格：记录、状态、得分、用时、开始时间、操作。
- 本项目增加学习模式和真实服务端分页。

### 8.2 管理端学员列表 ✅

样本字段：

- 状态：进行中。
- 场景通过：0/3。
- 练习次数：2。
- 平均分：87.05。
- 训练均分：86.3。
- 考核均分：87.8。

结论：同一学员的训练和考核分别统计，并共同形成平均分。

### 8.3 学员详情 ✅

- 综合分析。
- 对练记录。
- 场景分布。
- 对练记录有全部/训练/考核筛选，每条带模式标签。

### 8.4 添加学员抽屉 ✅

- 部门树筛选。
- 姓名/账号/工号搜索。
- 分页。
- 已选区域和已选人数。
- 原平台有更多选人模式，但用户明确当前只要求“快速选人”；本项目实现快速选人，并复用现有部门树和分页人员列表。

## 9. 产品档案

### 9.1 学员端详情 ✅🧪

产品档案从 artifact 单独读取，结构为：

- `profile_name`
- `category`
- `descr`
- `detail` Markdown
- `extension` 自定义字段

样例：

- 名称：成套智联2.0智能化平台。
- 分类：服装智能制造软硬件一体化解决方案。
- 自定义字段：品牌、产品状态、核心价值、典型客户、技术特点、适用品类。
- 产品详情为完整 Markdown。

### 9.2 管理端编辑 ✅

- 右侧面板可返回产品档案列表并打开详情。
- 有“编辑”按钮。
- 编辑区包含简介、自定义字段和产品详情。
- 当前现有实现只有 artifact 预留，没有完整持久化和版本快照。

## 13. 已关闭的冲突

| 冲突 | 结论 |
|---|---|
| 版本是保存设置时 +1 | 错误。设置不升版，内容发布才升版 |
| 主题创建就有 v1 | 错误。首次发布才显示 v1 |
| AI 确认后需要再次发布 | 首次发布前确认只保留工作内容；v1 后确认直接发布下一版 |
| 到时结束与最终 passed 矛盾 | 拆分 timeout/targetReached/passed |
| 原 `passed=1/studyStatus=20` 与“未通过”矛盾 | 本系统不使用该组合作为业务枚举 |
| 随机练习靠 randomScript 轮询 | 原站不同链路表现不一致；本系统统一 attempt 准备事件 |
| 产品档案只是 artifact 文本 | 改为业务实体 + 发布快照 |
| 添加学员只需单页简单列表 | 快速选人必须有部门、搜索和分页 |

## 14. 信息完整性
