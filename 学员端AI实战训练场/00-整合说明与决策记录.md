# AI实战训练场学员端整合说明与决策记录

> 版本：v1.1 ｜ 日期：2026-10-30
> 来源：原平台实测 ✅、页面 DOM/网络抓包 🧪、用户截图 📸、用户决策 🧑、当前代码核对 💻
> 目的：把管理端、AI 设计助手、学员端两路勘探和现有代码收束成一套可施工规则。

## 1. 任务范围

本期不是只补几个学员页面，而是补齐“主题生产 -> 发布 -> 学员参与 -> 训练/考核 -> 报告 -> 学员运营”的闭环。交付范围包括：

- 学员端首页、主题详情、场景准备、练习历程、文件查看。
- 实战案例、随机练习、自定义练习三类入口，共用一个 attempt/runtime。
- 普通训练、正式考核、训考一体的运行与报告。
- 管理端学员管理、产品档案、全局设置、内容版本和发布快照。
- 在线课堂文档素材进入 AI 设计助手及学员学习资料。

本期不包含：知识空间、审批式加入、竞技场、荣誉榜、实时口型驱动、分享/游客体系。

## 2. 证据与权威顺序

发生冲突时按以下顺序取值：

1. 本文件的用户决策和覆盖规则。
2. `01-需求文档.md` 的体验与验收。
3. `03-技术实现方案-后端.md` 和 `05-建表SQL.md` 的数据规则。
4. 当前已运行代码。
5. 旧管理端和 AI 助手契约。
6. 原平台抓包与 DOM。

抓包只证明原平台“曾经怎样”，不要求本系统复制其接口、字段名或跨应用跳转。

## 3. 当前系统基线

已存在并可复用：

- `front-end`：Vue 3.5、TypeScript、Vite、Element Plus、Pinia、vue-router。
- `AtualCombatTraining`：主题、场景、评估维度、AI 助手、artifact、发布和剧本雏形。
- `AIGentService`：统一智能体运行时、内部流式会话和 native workflow。
- `SpeechTraining`：ASR、CosyVoice TTS、录音与音频缓存能力。
- `OnlineClassroom`：已发布课件查询、文档抽取、在线课堂素材选择。
- `StaffManagement`：员工、部门、岗位查询和组织选择基础能力。

主要缺口：

- 学员端入口和 `drillmate` 路由族未实现。
- 无主题参与关系、attempt、消息、报告、场景统计和学员管理持久化。
- 现有 `act_theme_version` 同时保存内容与设置，版本语义错误。
- 产品档案只有占位字段或 artifact 片段，没有完整 CRUD、版本快照和学员读取。
- 场景案例在发布后可消费，但随机/自定义脚本、运行时、评分和报告未闭环。

## 4. 已确认决策

| D02 | 加入方式只做“管理员指定”和“完全公开直接加入”；不做申请审批。 |

| D17 | 设置页的修改对所有内容版本生效，不产生新版本；attempt 仍按开始时的设置快照执行。 |

| D20 | 训练成绩不参与主题最终通过；考核成绩参与。主题通过要求全部场景按通过标准通过。 |

| D22 | “再练一次”创建新 attempt，遵守次数、时间和模式解锁限制，不复用旧会话。 |

| D24 | 在线课堂选择器“有效期”无数据时显示 `--`；AI 出题已有素材文本时，提取知识点先二次确认再覆盖。 |

| D26 | AIGentService 训考运行态采用版本化 JSON Schema：`drill-script-v1`、`drill-report-v1`、`drill-suggest-v1`。 |

| D28 | 旧数据迁移使用可重复执行的 SQL：未发布主题先复制为隐藏 v0，再迁移全局设置。 |
| D29 | ACT 本地 Office 材料优先异步转 PDF；转换器缺失/失败时回退为提取文本阅读，不阻塞上传、发布和训练。 |

## 5. 对旧契约的明确覆盖

| 旧规则 | 新规则 |
|---|---|
| 主题设置每次保存 `version+1` | 设置是主题级全局配置，保存不升内容版本。 |
| 主题创建时就有 `v1` | 首次发布前无公开版本；首次发布才产生 `v1`。 |
| AI 确认只覆盖当前版本，重新发布再 +1 | `v1` 后 AI 确认立即创建并发布下一版本；首次发布前确认只更新工作内容。 |
| 产品档案仅是 artifact 预留字段 | 产品档案成为可编辑、可关联、可版本快照的业务实体。 |
| 学员管理是静态壳 | 学员关系、来源、状态、次数、均分、记录和配额调整真实持久化。 |
| 防作弊只展示 | 考核运行需执行已启用的防作弊策略。 |
| 学员端不在范围 | 学员端、训练、考核、报告和练习历程全部纳入本期。 |
| 数据分析和统计全部占位 | 与学员 attempt/report 有关的统计从真实业务表聚合；其余未定义分析仍可后置。 |

## 6. 关键产品规则

### 6.1 内容版本

- `working_version_no` 指向当前隐藏/可编辑工作内容；从未发布时为内部 `v0`，发布后为当前公开版本。
- `published_version_no` 指向当前上线内容，首次发布前为空。
- AI 编辑只操作 artifact 工作区。
- 首次发布：冻结工作内容，创建 `v1`，写入 `published_version_no`。
- `v1` 后点击“确认”：校验 artifact，新增下一版本，原子发布并切换指针。
- 版本历史只列已经正式发布的版本。

### 6.2 训练与考核

- `study_mode=1` 训练，`study_mode=2` 考核。
- `practice_type=case/random/custom` 与 `study_mode` 正交。
- 混合模式只允许先训练后考核；达到训练门槛后才可创建考核 attempt。
- 训练和考核各有自己的次数上限与平均分口径。
- 同一用户、同一主题同一时刻最多一场活动 attempt。

### 6.3 结束状态

| 字段 | 含义 |
|---|---|
| `end_reason` | `timeout/manual_exit/target_reached/round_limit/screen_violation/plan_ended/system_failed` |
| `timed_out` | 是否因时长到点结束 |
| `passed` | 本次结果是否通过；主动退出和防作弊违规强制 `false` |
| `target_reached` | AI 是否判定完成本场练习目标 |
| `target_reason` | AI 判定依据，必须持久化 |

结束页只显示客观事实，例如“本次练习已结束”；最终通过状态以报告为准。

## 7. 施工顺序

1. 数据迁移与版本/设置拆分。
2. 发布快照、产品档案和参与关系。
3. 学员首页、主题详情和练习历程。
4. attempt 创建、准备、WS 运行时和三类练习。
5. 训练报告与重练。
6. 考核解锁、防作弊和考核报告。
7. 管理端学员管理与真实统计。
8. 在线课堂素材和统一文件查看。
9. 全链路回归、并发/断线/到时/跨日测试。
