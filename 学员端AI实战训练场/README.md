## 发布旧口径（继承自管理端契约，勿改）

以下三条是**已经落地的实现口径**，与旧契约（`../AI实战训练场管理端复刻/`）一致，
本目录作为新权威**继承不推翻**。改这三条会破坏已发布主题的数据形态：

1. **每案例一行**：发布初始化时，每个已确认案例原样落 `act_drill_script` **一行**，
   不在发布时再拼一份"场景摘要"冒充正文。学员端消费的是案例生成时的正文
   （见 `03-技术实现方案-后端.md` 的发布主链路）。
2. **本地进度 `total` = 案例数**：`GET /admin/theme/{id}/script-progress` 的 `total` 是
   **案例总数**，不是场景数。场景进度另由 `sceneTotal` / `sceneCompleted` 表达
   （"某场景下还有未 compiled 的案例，该场景就不算完成"）。
   线上脚本是成对产物（Markdown + JSON），本地只存一份，所以本地进度按案例计。
3. **无案例运行时拒绝发布**：未生成/未确认任何实战案例时，发布接口直接拒绝
   （提示"请先在 AI 助手中生成并确认实战案例"），不产出空主题。

> 为什么在此重复记录：这三条在旧契约正文里，新目录早期未继承，导致有人以为可以按
> "按场景落库 / 进度按场景计"改实现。此处固化为不可覆盖的基线。
