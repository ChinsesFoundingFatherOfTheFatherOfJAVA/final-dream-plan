# AI实战训练场学员端与训考闭环技术实现方案（后端）

> 版本：v1.1 ｜ 日期：2026-10-30
> 主服务：`AtualCombatTraining`（8082）
> 协作服务：`AIGentService`（8086）、`SpeechTraining`、`OnlineClassroom`、`StaffManagement`

## 1. 架构结论

```text
Vue 学员端
  ├─ HTTP /api/act/student/**
  └─ WS   /api/act/ws/drill?attemptId=...
             │
             ▼
AtualCombatTraining
  ├─ 学员主题/参与关系/attempt/报告/文件
  ├─ 内容版本/设置/发布快照/产品档案
  ├─ DrillRuntimeService + DrillWsHandler
  ├─ AdminStudentService + 统计查询
  ├─ NativeDrillClient ──HTTP/SSE──> AIGentService
  ├─ SpeechClient ───────HTTP────────> SpeechTraining
  └─ KngAiSourceClient ──HTTP────────> OnlineClassroom
```

职责边界：

- `AtualCombatTraining`：业务事实源、权限、快照、次数、状态机、报告持久化和 WS 协议。
- `AIGentService`：脚本生成、角色回应、教练点评、建议和报告生成，不直接读写 ACT 业务表。
- `SpeechTraining`：ASR、TTS 和音频缓存；ACT 不复制语音供应商逻辑。
- `OnlineClassroom`：课件列表、文档抽取、课件查看上下文和源文件流。
- `StaffManagement`：员工、部门、岗位查询。

## 2. 复刻边界与取舍

### 2.1 对齐的体验

- 三类练习的准备、生成、对练和报告阶段。
- 训练教练点评与可选建议。
- 混合模式先训练后考核。
- 到时、退出、报告和重练。
- 学员管理中的来源、状态、场景通过、训练/考核分栏统计。

### 2.2 自定实现

- 采用独立 `act_practice_attempt` 和 `act_practice_report`，不复制原站聊天消息即报告的结构。
- `target_reached`、`passed`、`timed_out` 独立持久化。
- 随机/自定义脚本通过统一 AIGentService workflow 生成。
- 参与关系、次数、快照和材料均使用 ACT 自有表。
- 原站跨应用 token/URL 不复刻。

## 4. 数据与版本模型

完整 DDL 见 `05-建表SQL.md`。

### 4.1 主题指针

`act_theme` 增加：

- `working_version_no`：当前工作内容版本；首次发布前为内部隐藏 `v0`，首次发布后为当前公开版本。
- `published_version_no`：当前线上内容版本，首次发布前为 null。
- `first_published_at`。

`current_version_no` 只作为迁移兼容列，新代码不把它当作公开版本。

### 4.2 内容版本

`act_theme_version` 的新语义：

- 只代表可发布内容快照。
- `version_no=0` 是从未发布主题的内部工作快照，任何用户接口都不返回。
- `version_no>=1` 是已发布内容版本。
- 每行对应一个 artifact 确认结果。
- 首次发布创建 `v1`。
- 之后每次 AI 助手点击确认且内容有差异，创建 `max(version_no)+1` 并立即发布。
- 版本历史只返回已发布版本。

版本行保留 `theme_name/theme_desc` 仅作为历史显示快照，不决定主题当前名称。

### 4.3 全局设置

新增 `act_theme_settings`，一主题一行。字段包括：

- 计划时间、负责人、访问方式、总演练次数。
- 场景次数和主题通过标准。
- 训练/考核开关、AI 响应、AI 辅助。
- `dialog_modes`：`voice,text` 的子集，至少保留一种。
- 练习方式、主题难度、自定义难度。
- 人脸、切屏防作弊。
- `min_train_count_to_unlock_exam`。
- `max_exam_count`，0=不限。

保存设置只更新这一行，不创建内容版本。

### 4.4 发布快照

发布事务冻结：

- 内容版本行。
- 场景、评估维度。
- 案例脚本/随机生成配置。
- 产品档案及场景关联。
- 学员可见材料。
- 对后续 attempt 生效的全局设置。

已创建 attempt 不再读取这些实时表，而是读取自己的 `*_snapshot_json` 和关联快照。

## 5. 版本与发布流程

### 5.1 首次发布

```text
校验 working artifact 与隐藏 v0
  -> 创建 act_theme_version(version_no=1, published=true)
  -> 从 v0 复制场景/维度/案例/产品档案/材料快照
  -> 设置 working_version_no=1, published_version_no=1
  -> status=published
```

### 5.2 首次发布前点击 AI“确认”

- 允许确认工作内容。
- 仅更新 artifact 状态和隐藏 `v0` 内容表。
- 不创建用户可见版本。
- 不改变 `published_version_no=null`。

### 5.3 已发布后点击 AI“确认”

在同一事务内：

1. 校验 artifact。
2. 比较内容 hash，相同则幂等返回。
3. 创建 `version_no=max+1`。
4. 固化为正式版本。
5. 复制快照。
6. 切换 `published_version_no` 和 `working_version_no`。
7. 推送 `content.version.published`。

不存在用户可编辑的 `v2 draft`。

### 5.4 设置后修改

- 训练/考核开关：首次发布后禁止修改。
- 其他设置：允许修改，写全局表。
- 修改只影响之后的 attempt；运行中 attempt 使用快照。

## 6. 参与关系与学员首页

### 6.1 参与关系

`act_theme_participant`：

- `source=assigned/public`。
- `status=active/removed`。
- `extra_exam_attempt_count`：管理员追加的考核次数。
- `joined_at`、`removed_at`。

管理员删除为软删除，历史 attempt 保留。

### 6.2 我的主题

只查当前学员 `status=active` 的参与关系，按最近活动倒序。

场景通过数从 `act_student_scenario_stat` 聚合。主题通过规则：

- 全部场景达到设置要求。
- 仅统计考核 attempt；纯训练主题按训练结果统计。

### 6.3 更多学习机会

SQL 条件：

```text
theme.status = published
plan_start_time is null or <= now
plan_end_time is null or > now
join_mode allows public
not exists active participant
```

默认 limit 6，按发布时间/更新时间倒序。

公开加入需用唯一键防重复。

## 7. Attempt 状态机

### 7.1 状态

```text
preparing -> ready -> in_progress -> report_generating -> completed
     |         |            |
     └ failed  └ cancelled  └ failed
```

终态：`completed/failed/cancelled`。

### 7.2 创建与预占

`preflight` 只读检查，不写 attempt。

`createAttempt`：

1. 再次执行 preflight。
2. 生成 `attemptId`。
3. 计算并保存内容、设置、场景、档案和材料快照。
4. 设置 `active_key={`${themeId}:${userId}`}`。
5. 状态 `preparing`。
6. 触发脚本生成。

`active_key` 有唯一索引；所有终态把它置 null，保证同一用户同主题只有一场活动 attempt。

### 7.3 次数规则

两类计数：

- `theme total_drill_count`：企业/主题总容量。
- `per_scene_limit` + `extra_count`：单场景次数。
- 混合模式训练门槛。
- 最大考核次数 + 管理员追加次数。

正式开始事务：

1. 锁定 attempt。
2. 校验状态为 `ready`。
3. 再次校验时间、次数和解锁。
4. 增加场景统计 `formal_count`。
5. 扣主题总容量。
6. attempt 置 `in_progress`，写 `started_at/deadline_at`。

准备失败、创建后取消、准备页退出都不进入此事务，不扣次数。

### 7.4 次数统计

`act_student_scenario_stat` 按 `user_id + theme_id + scenario_id + study_mode` 存：

- formal_count。
- completed_count。
- passed_count。
- consecutive_passed_count。
- highest_score。
- latest_score。
- last_attempt_at。

通过标准计算时优先读统计表；历史重新核验仍可回放 attempt/report。

## 8. 脚本准备

### 8.1 案例练习

- 从发布快照的 `act_drill_script` 读取。
- 复制为 attempt `script_snapshot_json`。
- 不走 LLM。

### 8.2 随机练习

请求 AIGentService（具体字段以 `08-训考运行态接口与JSON-Schema.md` 为准）：

```json
{
  "sessionId": "attempt-id",
  "traceId": "trace-id",
  "inputs": {
    "attempt_id": "attempt-id",
    "scenario_json": "{...}",
    "practice_type": "random",
    "difficulty": "2",
    "product_profiles_json": "[]",
    "materials_summary_text": "..."
  }
}
```

结果必须包含：

- 客户/角色姓名、身份、性格、目标、隐藏信息、行为模式。
- 业务背景、开场白、阶段目标。
- 沟通指南。
- 禁止行为、失败信号。
- 评估维度引用和权重。
- 最大时长。

### 8.3 自定义练习

同随机练习，额外输入：

- 场景背景。
- 角色名、身份、性格、背景。
- 产品档案 `profileKey` 列表。
- 难度。

### 8.4 准备事件

ACT 解析 AIGentService 流或阶段回调，向 WS 推送四阶段：

1. `analyze_scene`
2. `build_script`
3. `build_actor`
4. `ready`

事件持久化到 `act_attempt_event`，刷新可重放。

## 9. 对练运行时

### 9.1 WS 协议

端点：`/api/act/ws/drill`

连接鉴权：

- 使用现有 JWT。
- 服务端校验 attempt 属于当前用户。
- 同一 attempt 允许多连接观察，但只有最新有效 `writerToken` 可发送消息。

帧结构：

```json
{
  "type": "event",
  "event": "assistant.delta",
  "seq": 42,
  "attemptId": "...",
  "data": {}
}
```

客户端每帧带 `clientMessageId`。服务端按 attempt 维度串行处理，数据库唯一键做幂等。

### 9.2 一轮训练

```text
学员消息落库
  -> ack
  -> 训练模式：请求教练点评
  -> 请求角色回应
  -> 更新目标达成度/轮次/剩余时间
  -> 生成 TTS
  -> turn.finished
```

考核模式跳过教练点评和建议。

### 9.3 AIGentService 扩展

完整请求、SSE 事件、DrillScript/Report JSON Schema 和重试规则以
`08-训考运行态接口与JSON-Schema.md` 为准。

建议新增内部端点，复用现有 SSE/LLM 基础设施：

| 端点 | 用途 |
|---|---|
| `POST /internal/agent/drill/script` | 生成随机/自定义脚本 |
| `POST /internal/agent/drill/chat` | 流式生成角色回应和训练点评 |
| `POST /internal/agent/drill/suggest` | 生成训练建议 |
| `POST /internal/agent/drill/report` | 生成结构化报告 |

不改现有 AI 设计助手端点的语义。

输入必须包含冻结脚本、角色状态、最近消息、完整关键事实和 attempt 设置快照。

AIGentService 返回结构化 JSON 或 SSE 事件，ACT 负责转换成本系统 WS 协议。

### 9.4 语音

ACT 暴露学员接口：

- `POST /student/attempts/{id}/voice/transcribe`
- `POST /student/attempts/{id}/tts`

ACT 调用 SpeechTraining 内部接口：

- ASR：音频 -> `{text, durationMs, words}`。
- TTS：`{text, voiceId, speed}` -> `{audioUrl, durationMs}`。

语音供应商适配器不进入浏览器。TTS 相同文本、声音和语速走缓存。

## 10. 计时、暂停与结束

### 10.1 计时

- `deadline_at = started_at + max_duration - paused_duration`。
- 服务端每 5 秒扫描 `in_progress` 且已过期 attempt。
- 同时提供延迟消息/调度补偿，扫描负责兜底。

### 10.2 暂停

- 训练模式允许暂停时，记录 `paused_at`。
- 恢复时累加 `paused_duration_ms` 并重算 deadline。
- 考核默认禁止暂停。

### 10.3 结束

`finishAttempt(attemptId, reason)` 用幂等锁：

- 只能从 `in_progress` 到 `report_generating`。
- 写 `ended_at/end_reason/timed_out`。
- 关闭 WS 写权限。
- 记录主动退出、切屏违规或计划结束。
- 触发报告。

任何重复调用返回同一结果。

## 11. 评分与报告

### 11.1 评分

AI 返回每个维度的：

- `dimensionId`。
- `score`。
- `weight`。
- `evidence[]`。
- `strength`、`improvement`、`reason`。

服务端重新计算：

```text
totalScore = sum(score * weight / 100)
```

权重必须与 attempt 快照一致；不一致则报告生成失败并告警。

### 11.2 结果判定

- `target_reached`：AI 按目标/指南/关键行为给出布尔值和理由。
- `passed`：
  - 主动退出或防作弊违规：false。
  - 其他：`totalScore >= passScore && targetReached`。
- `timed_out`：独立事实，不直接决定 passed。

### 11.3 报告持久化

`act_practice_report`：

- 结果字段。
- 总体评价、建议、关键对话。
- 完整 JSON。

`act_report_dimension`：

- 每维度分数、权重、证据、改进建议。

报告生成可重试。attempt 已有完整报告时幂等返回。

## 12. 防作弊

### 12.1 切屏

- 前端上报 `screen.hidden`。
- 服务端记录事件。
- `forbid` 模式第 1 次即结束。
- `allow` 模式超过 limit 后结束。

### 12.2 人脸

- `FaceVerificationProvider` 配置化 HTTP 适配器。
- 开始前抓拍并比对。
- 进行中每 5 分钟抓拍，服务端保存证据和结果。
- 人脸 provider 未配置时，主题设置不允许启用；运行前仍二次校验。
- 不把 provider key 下放前端。

### 12.3 证据

- 抓拍和事件属于敏感数据。
- 只允许管理员通过学员详情查看判定结果，不默认展示完整照片。
- 保留期限配置化，首期建议 30 天。

## 13. 文件与内容访问

ACT 本地 Office 材料的 PDF/文本双模式以 `11-本地材料查看方案.md` 为准。

### 13.1 ACT 本地材料

`GET /api/act/student/materials/{materialId}/stream`

校验：

- 当前用户能访问对应发布主题。
- 材料在当前 published snapshot 中且 visibility=student。
- materialId 不能越权引用其他主题。

支持 Range 请求。返回 `Content-Disposition: inline`。

### 13.2 在线课堂材料

ACT 返回受控的 `viewerContext`：

- `sourceType=onlineClassroom`
- `coursewareId`
- 允许使用的在线课堂 viewer 类型。

前端进入在线课堂 viewer；文件流仍由 OnlineClassroom 校验权限，不转发绝对路径。

## 14. 管理端统计

### 14.1 学员列表

聚合字段：

- 状态：进行中/已完成/未开始。
- `passedScenarioCount / scenarioCount`。
- 训练次数、考核次数。
- 平均分。
- 训练均分、考核均分。
- 最近活跃。

只统计 completed 报告的分值；进行中、准备失败、报告失败不计入平均分。

### 14.2 场景分布

按场景返回：

- 训练次数、考核次数。
- 通过率。
- 最高分、平均分。
- 最近一次结果。

### 14.3 学员对练记录

支持 `studyMode` 筛选，返回报告摘要并链接详情。

## 18. 风险与对策

| 风险 | 对策 |
|---|---|
| 当前版本实现与旧契约冲突 | 按本契约做迁移脚本，禁止继续复用保存设置升版逻辑 |
| 双重点击导致重复扣次 | attempt 行锁 + 状态 CAS + 统计唯一键 |
| 报告重复生成 | attempt/report 幂等键，报告生成在一个事务中收口 |
| AIGentService 超时 | attempt 保留、可重试；不把失败算作已完成 |
| 原 LLM 输出不符合维度 | 结构化输出 + schema 校验 + 1 次重试 |
