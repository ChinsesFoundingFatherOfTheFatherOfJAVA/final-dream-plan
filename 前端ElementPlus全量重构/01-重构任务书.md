## 1. 背景与目标

front-end 工程虽在 `package.json` 中声明了 `element-plus@^2.14.5` 与 `@element-plus/icons-vue`，但
`src/main.ts` 从未注册、无自动导入插件、全工程零引用——所有页面均为手写 SCSS 自绘组件。
后续迭代中手写表格/表单/弹窗/分页成本高、风格易漂移，经拍板决定**全量一次性重构为 Element Plus**。

**目标**：全站通用控件统一替换为 Element Plus，同时**视觉严格对齐现有手写版**（重构前后截图肉眼不可辨差异）。

**非目标**（明确不做）：

- 不改任何业务逻辑、API 调用、路由结构、状态管理——本次是**纯表现层重构**；
- 不替换定制交互组件（清单见 §4.2 保留清单）；
- 不做响应式/移动端适配改造。

## 5. 技术方案

### 5.1 接入方式

- `main.ts`：`app.use(ElementPlus)` 全量注册 + 引入 `element-plus/dist/index.css`。
  - 理由：全量重构+深度主题定制场景下，全量引入对构建产物体积的损失可接受（管理端 SPA），避免按需导入与全局主题覆盖的组合复杂度；
  - 中文 locale：`app.use(ElementPlus, { locale: zhCn })`（日期选择器、分页文案为中文）。
- 图标：`@element-plus/icons-vue` 全局注册或按需导入，由 code agent 统一按一种方式实施并在 PR 说明。
- **不引入** unplugin-vue-components / unplugin-auto-import（全量注册后无必要，减少一层构建魔法）。

### 5.2 主题定制（本次重构工作量主体）

新建 `src/assets/styles/element-theme.scss`，在 EP 样式之后引入，内容分两层：

**第一层：EP CSS Variables 映射**（覆盖 `--el-color-primary` 系列、`--el-border-radius-*`、`--el-font-size-*`、`--el-text-color-*` 等），值一律取自 §3.2 设计令牌，逐项映射：

| EP 变量 | 取值 |
|---|---|
| --el-color-primary 及 light/dark 阶 | #1890ff / #e6f7ff / #096dd9（按 EP 阶梯算法补齐 3~8 阶） |
| --el-color-success / warning / danger / error / info | #52c41a / #faad14 / #f5222d / #f5222d / #1890ff |
| --el-text-color-primary / regular / secondary / placeholder | #333333 / #333333 / #666666 / #999999 |
| --el-border-color 系列 | #e8e8e8 |
| --el-fill-color / light 系列 | #f5f5f5 / #fafafa |
| --el-font-size-base | 14px（正文） |
| --el-border-radius-base / round | 4px（对齐 --radius-sm，按钮/输入框圆角现状为小圆角） |
| --el-box-shadow 系列 | 对齐 --shadow-sm/md |

**第二层：字号标准落位**（EP 无对应变量的部分用组件级覆盖）：

- 页标题 22px：页面标题属页面模板，不进主题；在 `element-theme.scss` 中以 `.page-title` 约定类或沿用各页现有 h1/h2 选择器覆盖；
- 卡片标题 16px / 按钮 15px / 统计数字 28px：逐组件微调时用 `:deep()` 局部覆盖，规则见 §7.1。

**密度对齐**：EP 默认表格行高/表单行距与现有手写版不同，须逐模块实测调整（el-table 的 `size`、cell padding 覆盖）。这是"视觉严格对齐"的验收重点，见 §8。

### 5.3 字号与全局样式融合

- `variables.scss` 保留不删，并在 P1 由 `element-theme.scss` 显式引入；当前全工程无 import（页面直接用硬编码色值），P1 起把页面色值逐步收敛到令牌，引用归零后再由后续迭代清理；
- `reset.scss` 与 EP 样式的冲突排查：重点核对 body 字号、盒模型、滚动条样式三类，EP 引入后全局走查一遍。

### 5.4 命名与结构约定

- 不新建额外目录；EP 相关仅新增 `element-theme.scss` 一个文件；
- 组件内样式继续 SCSS + `scoped`，对 EP 内部类覆盖必须用 `:deep()`，禁止全局裸覆盖 EP 类（element-theme.scss 除外）。

## 7. 关键约束与坑（必读）

### 7.1 视觉对齐纪律

- **对齐基准 = P0 基线截图**（现有手写版），不是 EP 默认样式，也不是本任务书文字描述；
- 每页迁移完成后，与基线截图并排对比：字号、行高、间距、圆角、颜色、hover 态六项逐项核；
- 允许 ≤2px 级别的不可避免的渲染差异；超出视为不达标，用 `:deep()` 调整。

### 7.2 布局机制不可破坏

- `route.meta.fullBleed` 撑满机制（AdminLayout `height:100vh` + main flex 列 + 子页 `flex:1 + min-height:0` 链式撑满）**原样保留**——历史教训：flex basis/百分比高度互相覆盖会算出 0 高度；
- 验收"铺满"必须用 JS 实测（content 高度 == 窗口 - 顶栏，body.scrollHeight ≤ innerHeight），**勿信截图目测**（白底叠白底会骗过目测）。

### 7.3 请求与资产铁律不变

重构期间 AGENTS.md 第 3 节铁律全部有效：请求走 `request.ts`、`resolveAssetUrl()`、ID 全 string、分页双形状历史包袱照旧。

### 7.4 既有 UI 约定延续

- 空数据行必须保留标识信息（如维度名称+均分"—"），再显示"暂无数据"——用 el-empty 时同样遵守，**不允许整行只剩一句占位文案**；
- 字号标准见 §3.2，EP 化后不得回退到 EP 默认 12/13px 正文。
