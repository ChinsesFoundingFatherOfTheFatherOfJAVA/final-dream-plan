### 1.3 创建项目

**POST** `/admin/training-project`

支持两种提交方式，**根据 `Content-Type` 自动区分**：

#### 方式一：JSON（`application/json`）

**请求体**:
```json
{
  "name": "AI-10话术练习",
  "projectType": 0,
  "code": "AI-10",
  "description": "话术练习项目",
  "startTime": "2026-04-21T00:00:00",
  "endTime": "2026-05-31T00:00:00",
  "completionStandard": 1,
  "responsiblePerson": "user001",
  "responsiblePersonName": "管理员",
  "coverImage": "/coverImage/xxx.png",
  "dialogueMode": 0,
  "scoringDimensions": [
    {
      "dimensionName": "话术一致性",
      "weight": 40,
      "enabled": 1,
      "ruleType": 2,
      "scoringRule": "按照标准话术的要点表达即可"
    }
  ],
  "virtualTrainer": {
    "trainerName": "云小白",
    "language": "mandarin",
    "voiceId": "voice001",
    "speed": 30,
    "inputLanguage": "mandarin",
    "forbiddenWords": "脏话"
  }
}
```

> - `coverImage` 传图片访问路径字符串（如 `/coverImage/xxx.png`，由方式二上传得到或已存在的路径）
> - `startTime`/`endTime` 同时兼容 `2026-04-21T00:00:00` 和 `2026-04-21 00:00:00` 两种格式
> - `ruleType` 兼容数字（1=精准逐字匹配, 2=要点表达, 3=混合模式）和字符串（`exact`/`keypoints`/`mixed`/`grade`/`formula`/`deduction`）

#### 方式二：FormData（`multipart/form-data`，支持上传封面图片）

前端用 `FormData` 提交，**封面图片以文件形式上传**，后端保存到服务器 `/coverImage` 目录，数据库 `cover_image` 字段只存访问路径。

有两种字段组织方式，后端均可解析：

**A. 整体JSON字段（推荐）**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| data | string | 是 | 项目完整JSON字符串（同方式一的请求体，`coverImage` 留空） |
| coverImage | file | 否 | 封面图片文件 |

```js
const fd = new FormData()
fd.append('data', JSON.stringify(payload))
fd.append('coverImage', file)
```

**B. 逐字段提交**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| name | string | 是 | 项目名称 |
| code | string | 否 | 项目编号 |
| description | string | 是 | 说明信息 |
| startTime | string | 是 | 开始时间 |
| endTime | string | 是 | 结束时间 |
| projectType | int | 是 | 0=日常训练, 1=通关考试 |
| completionStandard | int | 条件 | 完成标准（日常训练） |
| passScore | int | 条件 | 达标分数（通关考试） |
| passStrategy | int | 条件 | 通关策略: 1=单次, 2=累计, 3=连续 |
| passStrategyN | int | 条件 | 通关策略N值 |
| dialogueMode | int | 是 | 0=语音, 1=文字 |
| scoringDimensions | string | 是 | 评分维度JSON数组字符串 |
| virtualTrainer | string | 是 | 虚拟陪练者设置JSON对象字符串 |
| coverImage | file/string | 否 | 封面图片文件（也可传已存在的路径字符串） |

> 文件字段名优先识别 `coverImage`，也兼容 `cover` / `file` / `image`；未上传文件时 `cover_image` 保持不变。

**响应**:
```json
{
  "code": 0,
  "data": 1304796610522828851
}
```

> **封面图片说明**
> - 存储目录：服务器 `/coverImage`（可通过 `app.upload.cover-image-dir` 配置；Windows 下 `/coverImage` 按当前盘符根目录解析，如 `D:\coverImage`）
> - 数据库 `cover_image` 字段存储的是**相对访问路径**，如 `/coverImage/a1b2c3d4.png`（不含域名）
> - 图片可通过 `GET {baseUrl}/api/coverImage/{filename}` 访问（与接口一致，经网关 `/api` 前缀转发）
> - 直连后端时也可通过 `GET {baseUrl}/coverImage/{filename}` 访问
> - 前端渲染时需要把该相对路径拼上接口基地址，例如 `http://localhost:8080/api` + `/coverImage/a1b2c3d4.png`

### 2.2 保存项目流程数据

**POST** `/admin/training-project/{id}/nodes`

**请求体**:
```json
{
  "nodes": [
    {
      "id": null,
      "nodeType": 1,
      "nodeName": "开始",
      "positionX": 100,
      "positionY": 100,
      "sortOrder": 0
    }
  ],
  "edges": [
    {
      "sourceNodeId": 1,
      "targetNodeId": 2,
      "weight": 1
    }
  ]
}
```

**响应**:
```json
{"code": 0, "data": null}
```

> **关于 `nodes[].id` 与 `edges` 的引用**
> - `nodes[].id` 是**前端临时ID**（通常为 1、2、3…），仅用于与 `edges` 建立引用关系，**不会**作为主键写入数据库。
> - 后端会忽略该临时ID，为每个节点重新分配自增主键，并自动把 `edges` 中的 `sourceNodeId`/`targetNodeId` 映射为真实节点ID。
> - 因此重复保存同一份流程不会主键冲突；保存会整体替换该项目的旧节点与连线。

**错误响应** (存在环):
```json
{
  "code": 1,
  "message": "流程图中存在环，请检查连线"
}
```

## 四、AI功能

### 4.1 AI生成话术

**POST** `/admin/ai/generate-script`

**请求体**:
```json
{
  "description": "保险销售电话开场白，客户是年轻妈妈",
  "rounds": 5,
  "firstSpeaker": "trainer"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| description | string | 是 | 对话场景描述 |
| rounds | int | 是 | 对话轮次 |
| firstSpeaker | string | 否 | 先说话的一方：`trainer`=陪练者先说（默认，大节点为 `nodeType=2`「陪练者问学员说」），`student`=学员先说（大节点为 `nodeType=3`「学员问陪练者说」） |

**响应**:
```json
{
  "code": 0,
  "data": {
    "nodes": [
      {"nodeType": 1, "nodeName": "开始", "positionX": 300, "positionY": 100},
      {
        "nodeType": 2,
        "nodeName": "陪练者问学员说",
        "trainerQuestion": "陪练者第1轮的话术",
        "standardScript": "学员第1轮标准话术",
        "keyPoints": [{"id": "kp-0-0", "content": "要点1", "order": 1}],
        "analysis": "第1轮话术解析",
        "positionX": 300,
        "positionY": 360
      },
      {
        "nodeType": 2,
        "nodeName": "陪练者问学员说",
        "trainerQuestion": "陪练者第2轮的话术",
        "standardScript": "学员第2轮标准话术",
        "keyPoints": [{"id": "kp-1-0", "content": "要点1", "order": 1}],
        "analysis": "第2轮话术解析",
        "positionX": 300,
        "positionY": 620
      },
      {"nodeType": 4, "nodeName": "结束", "positionX": 300, "positionY": 880}
    ],
    "edges": [
      {"source": 0, "target": 1, "weight": 1},
      {"source": 1, "target": 2, "weight": 1},
      {"source": 2, "target": 3, "weight": 1}
    ]
  }
}
```

> **节点结构说明**
> - 每一轮对话是**一个** `nodeType=2` 的节点（前端画布上呈现为一个大节点）：
>   - `trainerQuestion`：该轮陪练者的话术（陪练者问）
>   - `standardScript`/`keyPoints`/`analysis`：该轮学员的标准话术、要点、解析
> - `rounds` 为几轮，就生成几个 `nodeType=2` 节点，首尾为 `nodeType=1`（开始）和 `nodeType=4`（结束）。
> - `keyPoints[].id` 由智能体按 `kp-{轮次索引}-{要点索引}` 生成，可直接作为前端要点 ID 使用。
> - 节点 `id` 由后端在保存流程时分配，AI 生成接口返回的节点没有 `id` 字段。
> - `edges` 中的 `source`/`target` 是 `nodes` 数组下标（0 起），落库时由保存流程接口映射为真实节点 ID。
> - 大节点的 `nodeType`/`nodeName` 由 `firstSpeaker` 决定：`trainer`（默认）为 `2`/「陪练者问学员说」，`student` 为 `3`/「学员问陪练者说」。大节点内始终同时包含 `trainerQuestion` 与 `standardScript`/`keyPoints`/`analysis`。
