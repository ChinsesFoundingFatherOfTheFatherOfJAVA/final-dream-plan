## 一、t3 判分与结果：可直接复用的现成能力

### 1.1 `QuestionGrader` 已就绪（**不要重写判分**）

`service/QuestionGrader.java` 接口：

```java
GradeResult grade(GradeInput input);

record GradeInput(
    Integer type,              // 0单选 1多选 2判断 3填空 4问答 5组合
    String content,            // 题干
    String answerContent,      // 标准答案
    String judgeAnswer,        // 判断题答案
    Integer noOrderMark,       // 填空不分先后
    Integer blankScoreMark,    // 填空按空给分
    List<BlankScore> blankScores,
    List<String> answerKeywords, // 问答关键词
    BigDecimal fullScore,
    BigDecimal missScore,      // 多选漏选得分
    Integer missScoreType,     // 0不得分 1统一 2均分 3自定义
    List<OptionScore> optionScores,
    String userAnswer
);

record GradeResult(int correctFlag, BigDecimal score, BigDecimal maxScore) {
    static GradeResult full(BigDecimal maxScore)     // → correctFlag=1 正确
    static GradeResult zero(BigDecimal maxScore)     // → correctFlag=0 错误
    static GradeResult partial(BigDecimal score, BigDecimal maxScore) // → 2 半对
    static GradeResult pending(BigDecimal maxScore)  // → 3 待批阅
}
```

**四个工厂方法正好对应 `exam_attempt_answer.correct_flag` 四种状态**，判分后直接写库即可。

### 1.3 判分分流逻辑（`03 §10B.6`）

```
交卷 → 提交事务 → 投递判分任务（异步）
  ↓
① 客观题（0单选/1多选/2判断）→ 同步判，写 correct_flag/score/max_score
② 主观题
   ├ autoGradeFill/Qa = 0 → correct_flag=3（待批阅），等人工
   └ autoGradeFill/Qa = 1
        ├ aiGradeQa = 0 → QuestionGrader 关键词规则判
        └ aiGradeQa = 1 → AIGentService 异步 LLM（本期可先按关键词走，留 TODO）
  ↓
全部题 correct_flag 非空？→ 是：attempt.status=3 收口；否：保持 status=2
```

**关键约束**：
- **单题判分异常 → 该题 `correct_flag=3`（转人工）**，不影响其他题
- 整卷任务失败 → 保留 status=2，由补偿任务重试
- **判分前检查该题是否已判**（`correct_flag != null` 则跳过），保证重复执行幂等

### 1.4 结果页要点

- **DER-03**：交卷先返回客观题分。`graded=false` 时 `score`/`passed`/`rankNo` 全为 `null`
- 分数字段：`objectiveScore` / `objectiveFullScore` / `subjectivePending`
- `pointScores` 受 `answerView.viewPointScore` 控制；`typeStats` 受 `analysis_enabled` 控制
- 组合题统计**按父题聚合子题**（不是子题平铺）

### 1.5 答卷详情要点

- **`viewAnswerTimeRange` 四值语义**（勘误过的重点）：
  | 值 | 含义 |
  |---|---|
  | 0 | 不允许查看 |
  | 1 | **考试通过后**查看（分数达通过分；未通过一直不可看） |
  | 2 | **考试整体结束后**查看（不是交卷后！） |
  | 3 | **交卷后在指定时间窗内**查看（`answerViewStartAt` ~ `answerViewEndAt`） |
- 不可见时返回 `40055`，`message` 给出与 tooltip 一致的原因（如「考试结束后允许查看」）
- **`wrongOnly=1` 是真过滤**：只返回有错题的大题，连大题标题都不出现
- `answerContent` 仅当 `viewAnswer=1` 下发；`analysis` 仅当 `viewAnalysis=1` 下发

| `controller/MarkController.java` | 5 个端点（§11B.1-11B.5） |

### 2.2 关键约束

- **DER-08**：批阅人本期只做 **创建人 + 指定批阅人**。
  部门经理/直属经理「谁算部门经理」口径未定义，不做。
- **提交后重算**：`exam_attempt.score` / `passStatus` / `rank_no`，并写 `grader_names` / `graded_at`
- **全部题判完 → status 由 2 改 3**
- **`invalid=true` 走 `status=4 已作废`**，不参与统计与通过率
- **重新批阅**：允许重复提交，但**重算不累加**（不能把两次分数相加）
- **DER-14**：v1 **不支持按空打分**，只按 `quesId` 提交；批阅页不显示该单选组

### 2.3 待批阅计数的口径

`pendingQty` = 该考试下 `markStatus=0` 的答卷数，即存在 `correct_flag=3` 的题或 `attempt.status=2`。

**注意**：不要用 `exam_attempt_answer` 逐行 count，一处 15 万行的答卷表上做全表聚合会慢；
建议 `attempt.status=2` + 索引即可。若必须精确，用「该 exam 下 exit 着的 attempt 数」。

## 三、给 be-core / be-mark 的环境告诫

- 若确实需要长时间跑（如全量测试），先告知 captain 协调，避免与其他成员并发
