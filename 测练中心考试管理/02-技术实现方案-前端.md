# 测练中心·考试管理复刻 前端技术实现方案

> 版本：v1.0 ｜ 日期：2026-10-14  
> 配套：`01-需求文档.md`、`03-技术实现方案-后端.md`、`04-接口文档.md`  
> 工程：`D:\JACK\final_dream\front-end`  
> 技术栈：Vue 3 + TypeScript + SCSS + Pinia + Vue Router + ECharts。  
> UI 路线：本模块不启用 Element Plus，继续复用现有手写 SCSS 组件与交互封装。

> 现状校验：工程当前全部页面仍是手写 SCSS，`element-plus` 已声明依赖但 `main.ts` 未注册。用户确认：如果使用 EP 会导致已有组件不能复用，则本模块先不用 EP。
>
> 工程当前 `ExamLayout.vue` 中「考试管理」指向 `/exam/exam-mgmt` 的 PlaceholderPage；本模块直接替换该占位路由。试卷页面已位于 `src/views/exam/paper/`，新增考试页面放 `src/views/exam/arrange/`。

## 1. 技术选型与理由

| 项 | 选型 | 理由 |
|---|---|---|
| 框架 | Vue 3 + TS | 现有工程基线，路由、构建、请求封装已成熟 |
| UI | 现有手写 SCSS 组件 | 直接复用 CatalogTree/UserPickerDrawer/ConfirmDialog/DatePicker 等，避免重写 |
| 状态 | Pinia | 用于列设置、筛选缓存、当前考试上下文；页面数据优先局部状态 |
| 图表 | ECharts | 现有统计图表方案；考试分析使用柱状图和指标卡，不新增图表库 |
| 二维码 | `qrcode.vue` | 考试链接抽屉需要二维码下载；MIT，轻量 |
| 拖拽 | SortableJS 或工程既有拖拽实现 | 列字段排序；若试卷模块已有 DnD，直接复用 |
| 请求 | 工程 `request.ts` | 统一 token、错误处理、base URL、文件流 |
| 日期时间 | 现有 `DatePicker` / 手写日期组件 | 需要精确到分钟时优先扩展现有组件 |

## 2. 已有实现调研与选型

完整候选表见 `观察素材/已有实现调研.md`。

**直接采用**

- `echarts`：Apache-2.0；统计分析图表。
- `qrcode.vue`：MIT；考试链接二维码。

**暂不采用**

- `element-plus`：保留为未来全量重构方向；为复用现有手写组件，本模块不注册、不用于功能实现。

**改造采用**

- `sortablejs`：MIT；用于列设置和后续题目排序。若工程已有同类实现，则不得新增第二套。

**不采用**

- `didi/xiaoju-survey`：Apache-2.0，但领域是问卷/表单平台，数据模型和权限体系接入成本过高。
- `HUSANGT/Online-Examination-System`、`gongruiyang/Online_Exam_System`：功能层级与本平台不匹配。
- 无 LICENSE 的考试系统：许可证红线。

## 4. 状态设计

### 4.1 全局

建议仅新增一个考试共用的 Pinia store：`useExamArrangeStore`。

```ts
interface ArrangeStoreState {
  currentArrangeId: string
  currentArrange: ArrangeDetail | null
  columnSetting: StudentColumnSetting[]
  createDraft: {
    examType: 'onlineExam'
    paperId: string
    paperMode: 'new' | 'select' | 'import' | ''
    publishForm: ArrangePublishForm
  }
}
```

- `columnSetting` 按用户维度可持久化到 localStorage 或后端用户设置；后端实现优先使用 `exam_user_setting`。
- `createDraft` 只在创建向导存活；刷新时以 `examId` 从后端草稿详情恢复，避免只依赖内存。
- 列表筛选保留在页面或 keep-alive 路由 query；避免全局 store 存所有列表数据。

### 4.2 页面状态

- 列表：`loading / list / total / query / selectedIds`。
- 详情：`detail / activeTab / studentQuery / questionQuery / analysisDimension`。
- 考生 tab：`columns / visibleColumns / selectedRows / drawers`。
- 发布配置：表单 `model / rules / lastSavedAt / dirty`。
- 统计：`overview / scoreStats / correctRateByType / correctRateByLevel / correctRateByPoint`。

## 5. 关键实现思路

### F1-F5 列表、分类与操作

组件结构：

```text
ArrangeListPage
├── ArrangeCatalogPanel
└── right pane
    ├── ArrangeFilterBar
    ├── ArrangeTable
    └── Pagination
```

数据流：

```text
选择分类 → query.catalogId/routingPath → POST /arrange/list
更改筛选 → debounce 300ms → 重置 page=1
点击名称/管理 → /exam/exam-mgmt/detail?arrangeId=...
点击更多 → menu 权限按 permissions 字段置灰
```

关键处理：

- 搜索请求带请求序号 `requestId`，旧响应不得覆盖新响应。
- 分类树选择同步更新 query，切换「包含子分类 / 仅当前分类」；后者传 `routingPath=""` 并只按 `catalogId`。
- 批量操作前计算 `selectedIds`；空选择禁用。
- 列表导出传当前 query 和选中范围，文件流由 request 封装处理。
- 更多菜单通过 `permissions.canDelete/canEdit/canEnd/canPublish` 控制，不在前端猜角色。

依据：原站列表页分类与筛选布局见 `页面素材/01-考试管理-列表页.png`；更多菜单见 `页面素材/28-考试操作更多菜单.png`。

实测差异约束：

- 原站 `status` 为 0 未发布、2 进行中、3 已结束；前端不得再用 `publishStatus` 单独猜状态。
- 原站 `auditStatus` 为 0/2；审核通过或未发布要分别显示，不与 `status` 合并。
- 原站 `passRate` 是 0~1，统一通过 `formatRate` 乘 100。
- 原站 `principalNames` 是分号字符串，进入前端后转数组显示；本平台接口出参应返回数组，避免组件内拆字符串。

### F6-F12 考试详情与考生管理

详细页默认请求：

```text
GET /arrange/{arrangeId}
GET /arrange/{arrangeId}/student/list  (tab=student)
```

学生筛选参数：

```ts
interface StudentQuery {
  keyword: string
  accountStatus: number | -1
  examStatus: number | -1
  passStatus: number | -1
  joinType: number | -1
  deptIds: string[]
  positionIds: string[]
  startAt: string
  endAt: string
  page: number
  size: number
}
```

组件：

- `StudentFilterBar` 使用 `el-input` 防抖、`el-select` 枚举、`el-date-picker type="datetime" format="YYYY-MM-DD HH:mm"`。
- 部门/岗位点击打开抽屉；抽屉内表格分页，确认后把名称回显到筛选条。
- `StudentPickerDrawer` 是简化选人：部门下拉、关键词、分页表格、右侧已选。禁止显示 5 个 tab。
- `StudentColumnSettingPopover` 使用 drag handle 排序；保存列顺序时从右到左或按 key 排序均可，但后端存数组顺序。
- 表格固定操作列在右侧；无权限时按钮置灰。
- 补考、分析、删除确认统一走 `ConfirmDialog`。
- 签名记录图片加载失败时显示占位，时间显示到秒。

依据：`页面素材/04-考试详情-基本信息与tab.png`、`05-添加学员抽屉.png`、`11-签名记录抽屉.png`。

### F13-F14 试题分析与统计

试题分析：

```text
POST /arrange/{id}/question/list
GET /arrange/{id}/question/{quesId}/view
GET /arrange/{id}/question/{quesId}/answer-detail
```

- 正确率字段从后端返回 `decimal` 或数值，前端统一 `formatRate` 显示 `100% / 0% / --`。
- 试题查看、答题详情均为右侧抽屉，抽屉内部保留底部上一题/下一题时需要页面传当前列表顺序与 index。

统计分析：

```text
GET /arrange/{id}/analysis/overview
GET /arrange/{id}/analysis/score
GET /arrange/{id}/analysis/correct-rate?dimension=type|level|point
```

- `AnalysisOverviewTab` 布局为 4 指标卡 + 分值统计卡 + 图表。
- 正确率图使用 ECharts 柱状图；横轴不足 4 项时柱宽固定，不随容器拉伸。
- 切换维度只请求对应接口并缓存；切换时保留当前考试上下文。
- 空数据时保留卡片和坐标轴，数值显示 0 或 `--`。

### F15-F18 创建与发布流程

`ArrangeCreateWizard.vue` 使用 `el-steps`，三步状态与 URL query 同步：

```text
step=1 paper
step=2 question
step=3 publish
```

步骤 1：

- 类型选择弹层只显示线上考试。
- `ArrangePaperStep` 采用 segmented tabs / cards 展示三种方式。
- 新建试卷直接复用 `PaperFormDrawer`，成功后取得 `paperId`。
- 选择试卷复用 `PaperPickDrawer`；抽屉本身在试卷模块已有，需支持选择模式回调。
- 导入试卷复用 `PaperImportDrawer`。

步骤 2：

- 根据 `paper.buildType` 跳转到试卷模块编辑路由并带 `arrangeId`。
- 考试模块不重复实现题目/策略编辑器。
- 下一步前调用试卷模块的发布校验接口或 `GET /paper/{id}` 检查是否有题/分值，后端仍需校验。

步骤 3：

- 页面左右两栏，左侧基本信息，右侧通知设置；底部更多设置按 section 分块。
- 表单值统一存 `publishForm`：

```ts
interface ArrangePublishForm {
  name: string
  important: boolean
  secrecy: boolean
  catalogId: string
  code: string
  loopEnabled: boolean
  entryStartAt: string
  entryEndAt: string
  requiredType: 1 | 2
  passScoreType: 1 | 2
  passScore: number
  rewardType: 0 | 1 | 2
  notifySettings: Record<string, boolean>
  advancedSettings: Record<string, unknown>
}
```

- 保存按钮在 dirty 时可用，保存中 loading；成功后显示最后保存时间。
- 已发布编辑页不显示模板细分，只显示开关。
- 已发布编辑规则：
  - 步骤 1/2 只读，只允许通过上一步/下一步查看。
  - 步骤 3 允许修改考试名称、重要考试、保密、分类、入场时间、优秀分数、使用试卷、说明、负责人、批阅人、通知设置和定时消息。
  - 「获得证书」「防作弊限制」「学习任务限制」不显示编辑能力。
  - 其余更多设置按可编辑处理。

### F19-F20 链接与变更通知

`ArrangeLinkDrawer.vue`：

- 使用 `qrcode.vue` 渲染二维码。
- 复制链接优先 `navigator.clipboard`，降级 `document.execCommand('copy')`。
- 下载二维码：将 QR 组件 canvas 导出为 dataURL，按 200/400/800 生成下载。
- 考试链接由后端返回短期可访问 URL，不在前端拼明文 ID。

`ArrangeChangeNoticeDrawer.vue`：

- 载入变更摘要和后端预填通知正文。
- 使用 `el-input type="textarea"` 编辑，支持变量预览：`{examName}`、`{entryTime}`、`{link}`、`{paperName}`。
- 发送前预览学生看到的内容；确认后调用发送接口。
- 接口成功不等于送达，抽屉内展示「已创建通知记录，学员端可查看」。
- 通知不再使用考试私有学员表，统一通过通用通知服务发布事件；详见 `08-通用通知通道设计.md`。

### F21 答卷详情

- `ExamResultDetailPage` 根据 `ueId` 请求答卷。
- 页面使用普通文档式布局，不使用卡片嵌套卡片；顶部摘要白底，题目按 section 分块。
- 导出 PDF 走后端文件流；按钮 loading 防止重复点击。
- 题目媒体沿用试卷模块的媒体渲染组件或 HTML 渲染器。

### F22-F23 列设置与权限

- `StudentColumnSettingPopover` 维护 `allColumns`、`visibleKeys`、`orderedKeys`。
- 不可隐藏列：`account`、`fullname`、`operation`。
- 顺序保存到后端；刷新后加载。
- 所有写操作按钮读取 `permissions`，无权限时置灰并提供 tooltip 原因。

## 6. 动效与视觉落地

| 场景 | 动效 | 参数建议 |
|---|---|---|
| 抽屉 | 从右滑入 | 复用现有抽屉组件约 300ms |
| 弹窗 | 缩放 + 淡入 | 复用现有确认/弹窗组件 |
| 菜单 | 下拉出现 | 复用现有下拉菜单 |
| 行 hover | 背景变浅灰 | `#f5f7fa` |
| 状态点 | 无动画 | 静态点 |
| 图表切换 | 数据过渡 | ECharts 默认 300ms |
| 拖拽排序 | 元素浮起 + 占位 | opacity 0.7，拖动时显示抓手 |

设计令牌：

- 不新增全站主题；复用 `variables.scss` 与 `element-theme.scss`。
- 页面专用 SCSS 放组件内 `<style scoped lang="scss">`；延续现有变量与样式规范。
- 所有固定工具栏、操作列、标签、状态点设置稳定尺寸，避免 hover 或数据变化导致布局跳动。
- 不使用低对比度浅蓝文字；状态色必须同时有文字，不能只靠颜色区分。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 未来全量 UI 重构 | 当前手写组件可能后续迁移 | 本模块先保证复用与交付，不在本次切换 UI 体系 |
| 试卷模块组件不可直接复用 | 创建流程重复实现 | 优先把 `PaperFormDrawer/PaperPickDrawer/PaperImportDrawer` 做成可回调组件 |
| 列表筛选竞态 | 快速切换筛选时数据错乱 | 请求序号 / cancel token |
| 列设置本地持久化丢数据 | 不同设备不一致 | 后端 `exam_user_setting` 持久化 |
| 二维码链接过期 | 学员无法加入 | 后端返回短期 URL + 刷新链接按钮 |
| 问卷/考试状态枚举不明 | UI 与后端不一致 | 抓包授权后校对；之前统一枚举常量文件 |
| 大文件导出阻塞 | 页面卡顿 | 后端文件流，前端使用 blob download |
