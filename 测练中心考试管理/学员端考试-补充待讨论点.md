## B. 有缺口，需要你决策（7 项）

### B1. 题目标记（flag）没有存储位置 ⚠️

原平台每道题有「标记」按钮（标记不确定的题，答题卡可快速定位）。
但 `exam_attempt_answer` **没有任何 flag 字段**。

- 方案 a：加列 `marked tinyint`（简单，标记跟着答案走）
- 方案 b：存进 `answerJson`（不加列，但查询/统计麻烦）
- 方案 c：本期不做标记功能（第 3 批再说）

**我的建议：a**。一个 tinyint 而已，语义清晰，将来「只看标记题」也好查。

### B2. 考试时长的配置键还没定 ❓

原平台有「统一考试时长」。我们的 `exam_arrange` 只有 `publishSettings`/`advancedSettings` 两个 JSON 列，
**没有明确的时长键**。我查了契约 04 也没写清。

需要定：时长放哪个 JSON 的哪个 key？叫 `limitMinutes` 还是 `examDuration`？
**建议**：`publishSettings.limitMinutes`（分钟，0 或 null = 不限），并写进契约。

### B3. 「考生作答时能否看到已用时间/剩余时间」❓

原平台答题页顶部有倒计时（限时考试才有）。我们：
- 限时考试：显示「剩余 12:34」倒计时；
- 不限时：显示什么？空白、还是「不限时」？

**建议**：不限时显示「不限时」，不要留白让学员猜。

### B4. 断线/刷新后如何恢复答题状态 ❓

学员答到一半关掉浏览器，再进来：
- 已答的题要能回显（从 `exam_attempt_answer` 读）；
- 倒计时要继续（按 `attempt.startAt` 推算，不是前端本地计时）。

这是必须明确的行为。**建议**：重进即续答，用服务端时间校正，不做本地计时。

### B5. 交卷后能否修改？❓

原平台交卷后不可改（只能「再次考试」）。
但「未交卷但关闭页面」的情况，再进来是续答还是重新开始？

**建议**：未交卷=续答（同一 attempt），交卷=终态不可改。这也符合「答题次数」的语义。

### B6. 考试进行中，管理员改了考试配置（如延长时长）怎么办？❓

因为快照冻结的是**试卷内容**，不是**考试配置**。

- 方案 a：进行中的 attempt 沿用开始时的配置（更公平，但要存快照）
- 方案 b：实时读最新配置（管理员改了时长立刻生效）

**建议：a**。给 `exam_attempt` 存一份开考时的关键配置快照（时长、通过分）。
理由：考试中途改规则对学员不公平，也容易产生「为什么我的时间变短了」的争议。

### B7. 成绩发布（成绩下发通知）的时机 ❓

批阅完成后：
- 立即通知学员？
- 还是管理员手动「发布成绩」？

原平台有「成绩下发通知」开关。**建议**：按配置走——开了就批阅完自动发通知，没开就不发。
本期先做「批阅完成即更新状态，学员刷新可见」，通知延后到第三批。

## C. 需要确认的边界（5 项）

### C1. 组合题的分值与小分

原平台：组合题父题有总分（9分），子题各自有分（1/2/1/2/3=9）。
- 判分时子题独立判，父题分数=子题之和；
- 学员看到的得分是父题总分还是子题明细？

**建议**：答题页显示子题各自分值，结果页按父题汇总 + 可展开看子题得分。

### C2. 「仅支持查看错题」与「显示正确答案」的组合

原平台答卷详情页有三个筛选：只看错题 / 显示正确答案 / 展开所有解析。
当「只看错题」+「不显示正确答案」同时开启时，页面还剩什么？

**建议**：只看错题过滤的是**题目**，显示正确答案控制的是**该题的答案行**。
两者独立，同时开会看到「只列错题、但每题不显示正确答案」。

### C3. 填空多空的判分在学员端的呈现

我们已实现按空给分。学员答 3 个空对 2 个，结果页怎么显示？
- 显示「得 6.6/10」？
- 还是显示「对 2/3 空」？

**建议**：显示得分 + 「答对 2/3 空」，让学员知道错在哪。

### C4. 人脸核验失败的处理 ❓

如果核验不通过（不是本人）：
- 直接禁止考试？
- 允许重试 N 次？
- 记录但不阻拦（只留证据）？

原平台这个行为**我们没有观察到**（没跑过这个开关）。
**建议**：允许重试 3 次，仍失败则禁止开始并记录。这是行业常见做法，但需要你确认。

### C5. 考试列表的排序规则 ❓

学员考试列表按什么排？
- 按入场结束时间（快过期的在前）？
- 按发布时间倒序？
- 按状态（待考优先）？

**建议**：待考在前，组内按入场结束时间升序（最紧急的在前）。已完成的按提交时间倒序。

# E. 人脸核验的完整设计（已定稿 2026-11-10）

> 原平台未提供参照（勘探时未开启该开关实测），交互由本轮设计决定，
> 需记入 `09-实施偏差与决策记录.md` 作为**自主设计项**。

## E1. 设计原则

**核验是证据采集，不是准入闸门。**

理由：我们无法可靠区分「摄像头故障」与「故意遮挡/替考」。把核验做成硬闸门，
会因设备问题误伤正常学员；做成纯放行又失去了威慑与取证意义。
因此：**一律不阻断考试，只记录结果并标记，交卷后由批阅人核对。**

## E2. 三层结构

### 第一层：设备可用性检查（不阻断）

点「开始考试」后先探测摄像头：
- 可用 → 正常进入核验
- 不可用 → 提示「摄像头不可用，无法完成身份核验。你可以继续考试，但本次会被标记为『待人工核对』」
  学员可选择【继续考试】或【解决设备问题】。
- **不强制解决摄像头**，不禁止开考。

### 第二层：核验结果只记录，不判定

三种结果全部落库，**均不阻断**：

| 结果 | 含义 |
|---|---|
| `pass` | 比对通过（相似度 ≥ 阈值） |
| `fail` | 比对不通过（相似度 < 阈值） |
| `error` | 无法核验（摄像头故障、超时、服务不可用） |

### 第三层：异常标记进已有批阅链路（不新建功能）

- 有核验异常的答卷在 `exam_attempt` 打身份标记；
- 批阅列表 M2 该行显示「⚠ 身份待核对」标记；
- 批阅人打开 M3 时可见**核验抓拍图 + 异常原因**；
- 批阅人按常规流程处理：正常判分，或在评语中注明「身份异常，建议作废」；
- 需要作废时走**已有的 `exam_attempt.status=4 已作废`** 能力，不新造流程。

> 为什么搭车而不新做独立页面：M1/M2/M3 本来就要做，批阅人本来就要逐份看卷。
> 挂在批阅动作上等于零新增页面、零新增状态机；单独做「身份异常处理页」会是
> 又一套列表+状态+入口，而实际使用者还是批阅人。

## E3. 数据与接口

**表结构（`exam_attempt` 新增两列）**

| 列 | 类型 | 说明 |
|---|---|---|
| `identity_status` | tinyint | 0 未核验 1 通过 2 不通过 3 无法核验 |
| `identity_evidence` | varchar(512) | 核验抓拍图 URL（复用签名/头像同一个文件存储） |

> 不新增独立表：一份答卷只需一张核验图与一个状态，放主表最短路径。

## E4. 交互稿

**核验弹窗（正常态）**
```
┌──────────────────────────┐
│  身份核验                 │
│  ┌────────────────────┐  │
│  │   （摄像头预览）    │  │
│  └────────────────────┘  │
│  请正对摄像头             │
│  [重新拍照]   [开始考试]  │
│  ──────────────────────  │
│  ⓘ 若核验未通过，本次考试  │
│    将被标记待人工核对      │
└──────────────────────────┘
```

**核验失败（不阻断）**
```
身份核验未通过
本次考试仍可继续，但会被标记为「待人工核对」，
批阅时需要你配合确认身份。

[继续考试]   [再试一次]
```

**摄像头不可用**
```
无法使用摄像头
你仍可以继续考试，但本次会被标记为「待人工核对」，
建议先检查浏览器权限或设备。

[继续考试]   [我知道了]
```

## E5. 仍需在实施时定的参数

| 参数 | 建议值 | 说明 |
|---|---|---|
| 比对相似度阈值 | 0.85（CompreFace 默认区间 0.8~0.9） | 实施时用真实抓拍调，可配 |
| 重试次数 | 3 次 | 超过则直接按 `fail` 记录并放行 |
| 抓拍图保存位置 | 复用 `/exam/files/**` | 与签名图一致 |

> **DEF-01 仍然成立**：首次建档方案防不住首次替考。本设计只解决「后续考试换人」与「异常取证」。

# F. 补充待讨论点 · 最终结论（2026-11-10 定稿）

| 编号 | 问题 | 结论 |
|---|---|---|
| B1 | 题目标记存储 | **加列** `exam_attempt_answer.marked tinyint`（0未标记 1已标记） |
| B2 | 考试时长配置键 | **`publishSettings.limitMinutes`**（分钟；0 或 null = 不限），写进契约 |
| B3 | 不限时显示 | 显示「不限时」，不留白 |
| B4 | 断线恢复 | 重进即续答；倒计时按服务端 `attempt.startAt` 推算，**不做本地计时** |
| B5 | 未交卷重进 | 续答（同一 attempt）；交卷即终态不可改 |
| B6 | 中途改配置 | **开考时快照配置**：`exam_attempt` 存 `config_snapshot`（时长、通过分）<br>进行中的卷沿用开考配置，避免「我的时间怎么变短了」 |
| B7 | 成绩发布 | 本期：批阅完成即更新状态，学员刷新可见；**通知延后到第三批** |
| C1 | 组合题得分呈现 | 答题页显示子题各自分值；结果页按父题汇总，可展开看子题得分 |
| C2 | 只看错题 + 不显示答案 | 两者**独立**：只看错题过滤题目，显示正确答案控制该题的答案行。可同时生效 |
| C3 | 填空多空呈现 | 显示得分 + 「答对 2/3 空」 |
| C4 | 人脸核验失败 | **不断考**，只记录 + 标记待人工核对（详见 E 节） |
| C5 | 列表排序 | 待考在前，组内按入场结束时间升序；已完成按提交时间倒序 |
