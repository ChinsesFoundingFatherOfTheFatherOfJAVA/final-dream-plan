# 测练中心·考试管理复刻 接口文档

> 版本：v1.1 ｜ 日期：2026-10-14  
> Base URL：`http://<gateway>:8080/api/exam`  
> 鉴权：当前工程沿用登录后 JWT，前端请求头 `token: <jwt>`；网关统一校验，业务服务从 `AuthContext` 取当前用户。  
> 响应包裹：`{ "code": 0, "message": "success", "data": ... }`；`code != 0` 为业务失败。  
> 分页：`current`（默认 1）、`limit`（默认 10，可选 10/20/50/100）。**分页响应形状按服务归属区分**：ExamService 的接口（API-01~43、API-46~49）返回 `data = { records, total }`（公共类 `PageResult`）；StaffManagement 的接口（API-44/45，通知域）返回 `data = { list, total, page, size }`（`PageVo`）。依据见 `09-实施偏差与决策记录.md` D-01。  
> 时间格式：`yyyy-MM-dd HH:mm:ss`。  
> 来源说明：已完成原站核心读接口抓包。以下文档定义的是**本平台 `/api/exam` 实现契约**；原站真实路径与字段映射见 `观察素材/抓包/实测接口与字段.md`。

## 0. 与原站实测契约的关系

### 0.1 实测结论

- 原站 API 主机：`https://api-phx-ali.yunxuetang.cn`
- 原站业务前缀：`/ote/`
- 原站列表响应：`{ datas: [], paging: { limit, offset, pages, count } }`
- 本平台保持架构总纲统一契约：`{ code, message, data }`；分页形状按服务归属分两种（ExamService `{records,total}` / StaffManagement `{list,total,page,size}`），见 D-01
- 本平台路径继续走 `/api/exam/**` 网关，不把 `/ote/**` 硬编码进业务服务。

### 0.3 字段名原则

- 读接口字段名优先对齐原站实测：`name/status/auditStatus/entryStartTime/entryEndTime/totalQty/submitQty/passedQty/passRate/principalIds/principalNames`。
- 本平台已有试卷模块使用 `paper`，原站称 `exam`；对外接口仍使用 `paperId`，内部转换。
- 原站 `passed=2` 表示未知/未判定；本平台 `passStatus=-1` 表示未知，转换时映射为 `passed=2`。
- 原站列表分页用 `datas/paging`；本平台 ExamService 返回 `records/total`，StaffManagement 通知域返回 `list/total/page/size`（D-01）。
- 原站 `correctRate/answerQtyRate/passRate` 都是 0~1 小数；前端乘 100 显示百分比。

## 2. 通用错误码

| code | message | 场景 |
|---|---|---|
| 0 | success | 成功 |
| 40001 | 参数校验失败 | 必填项缺失、时间非法 |
| 40002 | 考试不存在 | arrangeId 无效或已删除 |
| 40003 | 无操作权限 | 当前用户不能执行操作 |
| 40004 | 考试状态不允许 | 已结束考试继续安排学员等 |
| 40005 | 试卷不可用 | 试卷不存在或未发布 |
| 40010 | 考试名称不能为空 | 创建/发布校验 |
| 40011 | 入场时间不能早于当前时间 | 创建/发布校验 |
| 40012 | 入场结束时间必须晚于开始时间 | 创建/发布校验 |
| 40013 | 通过分数不合法 | 通过分/比例校验 |
| 40020 | 考生已存在 | 添加学员时可跳过并返回明细 |
| 40021 | 补考只能安排一次 | 补考校验 |
| 40022 | 考生无作答记录 | 同步/补考条件不满足 |
| 40023 | 考生不存在或不在本场考试 | 考生 id 无效或不属于该考试 |
| 40024 | 答卷不存在或已删除 | 答卷 id 无效 |
| 40030 | 通知没有可发送对象 | 考试未安排学员 |
| 40040 | 导出任务创建失败 | 文件系统/参数问题 |
| 40101 | 未登录或 token 过期 | **仅网关**（考试域不再使用 401xx） |
| 40301 | 权限不足 | StaffManagement 权限快照 |
| 50020 | 导出文件生成失败 | POI/PDFBox 异常 |
| 50030 | 试卷快照生成失败 | 试卷数据异常 |
| 50040 | 通知通道不可用 | 通知投递/撤销失败 |

> 考试域（API-01~49）统一使用 `400xx/500xx`；`40101` 只由网关在未登录/过期时返回，
> 避免前端把"考试不存在"误判成"登录失效"。对照见 `09-实施偏差与决策记录.md` D-37。

## 3. 考试分类

### API-01 GET `/arrange/catalog/tree`

- 说明：读取考试分类树。
- 入参：`includeDisabled`（boolean，默认 true）。
- 出参：`data: ArrangeCatalogNode`
- 来源：🤔 设计值，交互对齐试卷模块。

### API-02 GET `/arrange/catalog/{id}`

- 说明：分类详情。
- 出参：单个 `ArrangeCatalogNode` + `createUser`、`createdAt`。

### API-03 POST `/arrange/catalog`

- 说明：批量创建分类。
- 入参：

```json
{
  "parentId": "root",
  "catalogText": "分类A\n 子分类A1",
  "adminUserIds": ["u1"],
  "inheritParentAuth": 0,
  "childInheritCurrentAuth": 0
}
```

- 出参：`{ "createdCount": 2, "errors": [] }`
- 错误：40001、40003。

### API-04 PUT `/arrange/catalog/{id}`

- 说明：编辑分类。
- 入参：`{ "name": "", "adminUserIds": [], "inheritParentAuth": 0, "childInheritCurrentAuth": 0 }`

### API-05 PUT `/arrange/catalog/{id}/move`

- 说明：移动分类。
- 入参：`{ "targetParentId": "uuid" }`
- 规则：目标不能是自身或子孙；层级 ≤10。

### API-06 PUT `/arrange/catalog/{id}/disable`

- 说明：禁用/启用分类。
- 入参：`{ "disabled": 1 }`

### API-07 DELETE `/arrange/catalog/{id}`

- 说明：删除分类。
- 错误：分类下有子分类或考试时 40001。

### API-08 POST `/arrange/list?current=1&limit=10&orderby=createdAt&direction=desc`

- 说明：考试列表。
- 入参：

```json
{
  "queryType": 1,
  "keyword": "",
  "catalogId": "1",
  "routingPath": "",
  "createUserId": "",
  "createUserIds": [],
  "publishStatus": -1,
```

- 说明：考试详情。

- 说明：创建考试草稿或直接创建。
- 入参：

```json
  "name": "默认考试",
```

### API-11 PUT `/arrange/{id}`

- 说明：更新草稿配置，不发布；已发布考试也走同一接口做部分更新。
- 入参：`ArrangePublishForm` 的字段子集。
- 出参：`{}`。
- 已发布允许字段白名单（以 `ArrangeServiceImpl.update()` 实际上写字段为准）：
  `name/important/secrecy/catalogId/entryStartAt/entryEndAt/passScore/passRatio/ownerUserIds/ownerNames/notifySettings/advancedSettings/publishSettings`
- 已发布禁止字段：
  `paperId/paperName/paperBuildType/paperCatalogId/paperSecrecy/paperQuestions/paperStrategy/antiCheatSettings/learningTaskSettings`
- 「使用试卷」发布后锁定：请求携带与当前不同的 `paperId` 返回 `ERR_STATE`（已发布考试不可更换试卷，见 09 D-31）。
- 「获得证书」不接收；旧字段请求忽略。

### API-12 POST `/arrange/{id}/publish`

- 说明：发布考试。
- 入参：`ArrangePublishForm` 可选，若传则先保存再发布。
- 出参：`ApiResponse<Void>`（`data: null`）；发布状态与快照需要重新查 API-09。
- 规则：
  - 校验试卷存在、试卷已发布。
  - 生成 `exam_paper_snapshot`。
  - 更新 `exam_paper_use` 与 `exam_paper.used_qty`。
  - 若已有考生则只更新配置，历史 attempt 不变。
- 来源：✅ 原站实测 `POST /ote/arrange/fast-publish`；真实请求体与响应见 `观察素材/抓包/实测接口与字段.md` §3。
- 原站一次提交基本发布信息 + `examArrangeControl4Put` + `notifyConfig4Put`；响应返回最终 `arrangeId/examId`。

- 说明：结束考试。
- 出参：`{ "publishStatus": 2, "endedAt": "..." }`

### 11.5b 人脸核验结果落库（2026-11-11 新增，DER-29）

`POST /student/attempts/{attemptId}/face-verify`

```json
{
  "identityStatus": 2,
  "identityEvidence": "/api/exam/files/2026/11/face-xxx.jpg",
  "identityMethod": 2,
  "identityScore": 0.87
}
```

- `identityStatus`：**1 通过 / 2 不通过 / 3 无法核验**（前端传 pass/fail/error，由后端映射）。
- `identityMethod`（2026-11-13 新增，DER-34）：**1 仅活体 / 2 活体+基准照比对**。
  缺省按 1 记——前端不传时不能凭空声称「比对过了」，否则批阅人会高估证据强度。
- `identityScore`：比对相似度 `0..1`，未做比对时不传。
  **不论比对是否通过都应上报**：批阅人需要看到「差多少」才能分清是光线/角度导致的不像，还是真换了人。
  > 相似度由**前端计算**上报，后端不重算——这是方案 A 的既定取舍。事后防不住能改前端的人，
  > 该风险已计入 DER-34；本接口不假装能防。
- `identityEvidence`：抓拍图 URL，复用 `/api/exam/files/**`；可为空，为空时保留原值。
  > ⚠ **必须存带 `/api` 的完整路径**。前端有个 `normalizeExamFileUrl()` 会去掉 `/api`，
  > 那是给 `<img src>` 显示用的（相对路径由 axios 基址补全）；存库时误用它会导致
  > 按该 URL 取图 404。2026-11-12 已因此踩过一次。
- 响应：`{}`（空 data）。

**本接口永不返回业务失败来阻断考试**（DER-07「核验只采集证据、绝不阻断」）：

| 情况 | 行为 |
|---|---|
| 答卷不存在 | 静默返回成功，不报错 |
| `identityStatus` 非法或缺失 | 按「无法核验(3)」记录 |
| 抓拍图为空 | 保留原 `identity_evidence` 值 |
| 非本人答卷 | 静默丢弃 + 打 warn 日志，不回 403 |
| `identityScore` 越界（<0 或 >1） | 忽略该值，不报错（核验接口不因数据问题阻断） |
| `identityMethod=1` 却传了 score | 忽略 score，防脏数据拼出「没比对却有相似度」的矛盾组合 |

**为什么是独立接口而不是并入 `§11.6 start`**：核验语义与「闸门」相反
（start 的 `signId`/`declareAccepted` 缺失会拒绝开考，而核验无论成败都放行）。
混进 start 会让后来人误以为核验失败会挡住开考，进而把 DER-07 改成硬闸门。

> 前端调用时用 `silent: true`，上报失败不打扰学员。

### 11.5c 人脸基准照（2026-11-12 新增，DER-33）

用于缓解 DEF-01：动作式活体只能证明「屏幕前是活人」，证明不了「是本人」。
学员自愿录入一张基准照后，后续才能做 1:1 比对，把「换了一个人」检出来。

**能力边界（必须同时写进 UI 文案）**：基准照由学员自己拍，**首次就可以是别人**。
它只能检测「这次与上次不是同一人」，**不是身份认证**，不得对学员宣传成“已确认本人”。

#### 查询是否已录入

`GET /student/face-baseline`

```json
{ "hasBaseline": true, "imageUrl": "/api/exam/files/2026/11/face-xxx.jpg" }
```

- 返回 `imageUrl` 而非只返回布尔值：前端要显示缩略图让学员确认拍对了，
  只给 `hasBaseline` 的话学员看不到拍的是什么，拍歪/拍错无法纠正。

#### 录入 / 重录

`POST /student/face-baseline`

```json
{ "imageUrl": "/api/exam/files/2026/11/face-xxx.jpg" }
```

- `imageUrl` 由前端先传到 `POST /exam/file/upload` 得到（与签名图共用存储，不重复造上传通道）。
- **只接受 `/api/exam/files/` 前缀**，其它一律驳回（避免外站地址落库后取图被防盗链/跨域挡住）。
- 一个学员只保留一张（`uk_user`），**重录即覆盖**：比对时永远只有唯一基准。
- 响应：`{ "hasBaseline": true, "imageUrl": "..." }`。

#### 为什么不强制、为什么放考试列表页

| 决定 | 理由 |
|---|---|
| 选填，跳过入口常驻 | 强制采集人脸在多数场景需单独告知与同意；设备/隐私条件不具备时强拦会把正常学员挡在门外 |
| 提示条而非弹窗 | 弹窗只有「确定/取消」，两个都是压力；提示条可关，关了本次不再烦 |
| 放考试列表页而非登录后 | 学员登录是来用平台的，不是来填资料的；一登录就弹容易让人以为是病毒或强制采集 |
| 录入不做活体动作 | 录入阶段本来就是本人在给自己建档；真正防「拿照片冒充」的判定发生在考试前那一刻 |
| 查询失败静默当已录入 | 接口挂了不应变成对学员的骚扰，也不该让页面看起来像报错 |

### 11.11 交卷

`PUT /student/attempts/{attemptId}/submit`

#### 排名字段口径（2026-11-13 补）

原平台「本次考试情况分析」有三处排名，都会在页面上直接展示，**全部限定在「同场考试已出分考生」范围内**：

| 字段 | 含义 | 算法 |
|---|---|---|
| `rankNo` | 总分排名 | 按 `score` 降序；并列取同名次（1,1,3） |
| `usedTimeRank` | 用时排名 | 按 `usedSeconds` **升序**（用时少的靠前）；`usedSeconds` 为 null 的答卷不参与排名 |
| `usedTimeRankTotal` | 参与用时排名的人数 | 同上口径 |
| `typeStats[].rank` | 该题型排名 | 按该题型 **正确率** 降序（不是答对数——随机卷题量不同，按对数排不公平）；并列取同名次 |
| `typeStats[].rankTotal` | 该题型参与排名人数 | 与 `rankNo` 同口径 |

**为什么按正确率而不是答对数**：随机卷每人抽到的题量可能不同，答对 3/5 与答对 3/10 不是一个水平，按对数排名会低估题多的人。

**`graded=false` 时所有排名字段为 `null`**，与 `score` 一致——还没出分就没有名次可言，给 0 会误导成「最后一名」。

- `pointScores` 受 `answerView.viewPointScore` 控制；`typeStats` 受 `analysis_enabled` 控制。
- `history` 为该学员在该场考试的全部作答记录（按提交时间倒序）。

### 11B.4 提交批阅

`POST /mark/paper/{attemptId}`

```json
{
  "grades": [{
    "quesId": "b3ac...",
    "correctFlag": 1,
    "score": 2.00,
    "comment": "回答完整"
```

## 11C. 判分与批阅流（口径）

```
交卷（PUT /submit）
  ↓ 同步：落 answers、status=2（批阅中）、返回客观题分
  ↓ 异步：判分任务
      ├ 客观题（单选/多选/判断）→ 立即判，写 correct_flag/score
      └ 主观题（填空/问答）
           ├ autoGradeFill/Qa = 关 → correct_flag=3（待批阅）
           └ = 开
                ├ aiGradeQa = 关 → 关键词规则判分（QuestionGrader）
                └ aiGradeQa = 开 → AI 语义判分（异步 LLM）
  ↓ 全部判完？→ 是：status=3、算总分/通过/排名；否：保持 status=2
  ↓ 待批阅答卷进入批阅人队列（M1/M2/M4）
```

> **关键**：AI 判分不是独立大道，它是「自动批阅已开启」下的**手段选择**。
> 无论哪条路，异常与申诉都靠批阅人「重新批阅」兜底。
