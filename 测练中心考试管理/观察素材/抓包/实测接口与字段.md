# 考试管理原站实测接口与字段

> 采集时间：2026-10-14  
> 采集方式：复制 Chrome 用户资料到临时目录，用 Codex 内置 Playwright 启动独立 Chrome 实例，复用已登录会话。  
> 动作范围：只读导航与页面加载；未提交考试、未删除、未发送通知、未导入文件。  
> 抓包原件：`live-capture.json`；前端 JS 原件：`js/`；写接口探针未产生实际写请求。  
> 敏感信息：未保存 Cookie、Authorization、token 等鉴权头。

## 1. 真实 API 基础信息

| 项 | 实测值 | 证据 |
|---|---|---|
| 页面域名 | `https://train.chinajack.com/ote/` | ✅ |

| 业务前缀 | `/ote/` | ✅ |
| 应用/版本 | `otepc` / `7.5.001-deploy` | ✅ |
| 分页列表响应 | `{ datas: [], paging: { limit, offset, pages, count } }` | ✅ |
| 单对象响应 | 顶层直接返回业务对象，没有 `code/data/message` 包装 | ✅ |
| 列表请求分页 | URL query `current/limit/orderby/direction`，筛选条件同时放在 body 和部分 query | ✅ |
| 列表字段 | camelCase | ✅ |

### 2.1 考试分类

| 用途 | Method | 真实路径 | 关键入参 | 关键响应 |
|---|---|---|---|---|
| 按父节点取分类树 | POST | `/ote/api/mgr/utree/node/list/by-pnode-id` | `dataPermsCode=examination_exam_classify_extent`、`navCode=ote_arrange_mgmt`、`treeId=ote-arrange`、`pnodeId=1`、`useDataScope=true` | `{treeId,sortable,node:{nodeId,pnodeId,nodeName,depth,inheritFromParent,applyToChildren,forceInherit,hasChild,children}}` |
| 分类详情 | GET | `/ote/api/mgr/utree/node/detail/by-node-id` | `treeId=ote-arrange&nodeId=1` | `{nodeId,nodeNameI18nKey,name,depth,managers}` |

结论：

- 考试分类树与题库/试卷分类树共用通用树服务，只是 `treeId`、`navCode`、权限码不同。
- 根节点 `nodeId=1`，名称「默认分类」。

### 2.12 已发布考试编辑范围（用户第二批 Browser Comment）

- 创建试卷阶段
- 编辑试题阶段

步骤 3「发布考试」可修改：

- 考试名称
- 重要考试
- 是否保密
- 考试分类
- 入场开始/结束时间
- 优秀分数/总分比例
- 使用试卷
- 批阅人
- 负责人（最多 50）
- 考试说明
- 考试安排通知、安排取消通知、定时消息
- 除「防作弊限制」和「学习任务限制」外的其他更多设置

不实现/不可改：

- 获得证书配置：不实现
- 防作弊限制：已发布后不可改
- 学习任务限制：已发布后不可改

## 6. 本次抓包对原设计的修正

| 原设计 | 实测修正 |
|---|---|
| API Base 使用页面域名 | 实际为 `api-phx-ali.yunxuetang.cn` |
| 分类接口 `/arrange/catalog/tree` | 实际为通用树服务 `/ote/api/mgr/utree/...`，参数 `treeId=ote-arrange` |
| 列表返回 `data.list` | 实际为 `datas[] + paging` |
| 考试主状态只标未发布/进行中/已结束 | 实测 `status=0/2/3`；`auditStatus=0/2` |
| 考生筛选字段叫 `examStatus` | 实际请求字段为 `status`、`passed`、`userStatus`、`joinMethod` |
| 考生通过状态 `passStatus` | 实际字段为 `passed`，0/1/2 |
| 试题分析返回 `answerQty/correctQty` | 实际为 `submitQty/correctQty/correctRate` |
| 分析接口返回扁平字段 | 实际为 `baseInfo/scoreInfo/accuracyRate` 三段 |
| 答卷接口 `/result/{ueId}` | 实际为 `/ote/ue/{ueId}/result/admin/view` |
| `totalScore` 直接显示 | 原站统计 `averageScore`/`averageTime` 都是浮点数，前端需格式化 |

## 7. 结论

- 原站的核心读接口和字段已足以支撑考试管理的需求文档、后端模型和前端联调。
- 创建/发布写接口的真实 payload 未通过提交触发，当前以编辑态响应和 JS 中的 API 封装为准，标记 🤔。
- 复刻自己的系统时应优先使用本平台的 `/api/exam` 网关契约、`ApiResponse` 和 `{list,total,page,size}` 分页；在原站字段与自建字段之间以本文件的映射表转换。
