# 观察记录：学员端考试（答题流程）

> 模块：测练中心·考试管理 → 学员端答题
> 观察时间：2026-11-10
> 来源：`https://train.chinajack.com/` 学员端「测练中心」（原平台绚星云学习 OTE）
> 观察方式：ego 浏览器实机操作 + 页面内 fetch/XHR 记录 + performance 资源清单
> 说明：本轮为**勘探记录**，尚未形成契约；字段含义待与管理端契约和用户确认对齐。

## 1. 入口链路

学员端首页 `train.chinajack.com/study/#/userhome` → 「待学习」列表里出现 `考试` 卡片（标签「考试」+ 名称「默认考试」+ 有效期）
→ 点击进入 `ote/#/stu/examentry?arrangeId={arrangeId}`（**考试预览/入场页**）
→ 点「开始考试」→ **考前签名弹窗** → 确认 → `ote/#/stu/userexam?arrId=&signId=&uemId=`（**答题页**）

> 注意：入口是「待学习」任务列表里的考试卡片，不是独立的考试列表页。学员端没有单独的考试列表菜单。

## 2. 入场页（examentry）内容

文案顺序（实测）：
- 面包屑：我的学习 / 测练中心 / 考试预览
- 考试名：默认考试
- 字段：入场时间、试卷总分、试题总数、考试限时、交卷时间、通过分数、优秀分数、考试次数、考生姓名
- 「答卷须知」：说明标记按钮（不确定的题可标记、可快速定位）、限时考试倒计时结束自动交卷、点「开始考试」即开始计时
- 按钮：开始考试

实测值示例：总分 10 分 / 5 题 / 不限时 / 通过分 6 / 考试次数 0/1 次。

## 3. 考前签名（重要交互）

点击开始考试后**先弹签名框**（因为该考试开启了「签名确认」）：
- 标题：考前签名
- 说明：本考试开启了"签名确认"，请在下面的签名框内按住鼠标拖动进行签名。
- 控件：`canvas` 手写签名区
- 按钮：清除重签 / 取消 / 确认

技术事实：签名是 canvas 画布，提交时导出 PNG 上传（见 §5 上传链路）。

## 4. 答题页（userexam）结构

左侧/顶部固定信息：退出按钮、考试名、考生（姓名+账号）、工号、部门、总分、通过分数。

题目区按**大题分节**，每节标题形如「一、单选题 （本题共1小题，共1分）」，节内每题：
- 题号 + 题干 + （X分）
- 单选：4 个 radio 选项 A/B/C/D
- 多选：4 个 checkbox 选项 A/B/C/D
- 判断：2 个 radio（正确 / 错误）
- 填空：文本输入（实测 1 个 input:text），题干带空位
- 问答：`textarea`，右下角计数「0/2000」

右侧固定区（答题卡）：
- 进度 `0/5`
- 答题卡：按大题分组列出题号，图标状态「未做 / 已做 / 当前」
- 标记：每题可标记（对应须知里的"标记不确定的试题"）
- 底部「提交考试」

实测控件统计：radio 6、checkbox 4、input:text 1、textarea 1。

## 5. 接口清单（实测）

| 阶段 | 方法 | 路径 | 说明 |
|---|---|---|---|

| 入场页 | GET | `/ote/uem/{arrangeId}/pre-check/external?orgId=` | 考前校验 |

## 7. 作答与提交接口（实测补齐）

### 7.1 单题即时保存（关键设计）

**每答一题立即调用一次保存接口**，不等交卷。实测点选单选 A 后立刻发出：

```
POST /ote/ue/single/answer
{
  "answers": [{
    "quesId": "0a9e7999-...",       // 题目 id
    "quesType": 0,                  // 0单选
    "lastSubmitTime": 1794282263082,
    "answer": ["d8984f23-..."]      // 注意：是"选项 id 数组"，不是字母 "A"
  }],
  "isH5Exam": 0,
  "submitType": 0,
  "uniqueId": "940c4a33-...",       // 前端生成的会话唯一 id
  "orgId": "...",
  "arrangeId": "f0fed0c3-...",
  "ueId": "3dacb442-...",
  "uemId": "b121daa1-..."
}
→ 200 {"forbidExit":0,"exitTimes":0}
```

> **要点**：答案存的是**选项 id**（exam_question_item.id），不是选项字母；我们现有 `exam_attempt_answer.answer_json` 需要按这个口径设计。
> `forbidExit` / `exitTimes` 用于防作弊退出控制。

### 7.2 拉取已答答案

```
GET /ote/ue/{ueId}/answer/result?orgId=
→ [{"quesId":"...","quesType":0,"answer":["d8984f23-..."],"attach":null,"lastSubmitTime":1794282263082}]
```

### 7.3 交卷

```
PUT /ote/ue/{ueId}/submit
{"isH5Exam":0,"submitType":0,"uniqueId":"940c4a33-...","usedTime":6,"orgId":"..."}
→ 204 No Content
```

`usedTime` 单位是**秒**，由前端计时上报。

### 7.4 交卷后结果

```
GET /ote/ue/{ueId}/finished?orgId=
```
关键字段：
- `submitTime`、`arrStatus`:2、`userStatus`:4、`userExamTimes`:1
- `repeated`、`repeatTimes`
- **成绩可见性开关**：`viewResult`、`viewResultScore`、`viewResultPoint`、`allowViewResultPassed`、`allowViewResultDetail`、`allowViewResultDetailType`、`allowViewResultDetailStartTime`、`allowViewResultDetailEndTime`
  → 对应管理端 `advancedSettings.answerView` / `analysis_enabled`，学员端据此决定能不能看分数、能不能看解析

### 7.5 考试控制项（4Stu）

```
GET /ote/arrange/{arrangeId}/control4Stu
→ {"id":null,"allowSubmitAllFinish":0,"shortUsedTimesCtrl":0,"shortUsedTimesLen":0,
   "questionFeedbackEnabled":0,"notifyQuestionFeedback":0}
```
`allowSubmitAllFinish` = 是否必须全部做完才能交卷（本场为 0，所以未做完也能交）。

## 8. 交互要点汇总（供契约使用）

| 交互 | 实测行为 |
|---|---|
| 交卷前校验 | 有未做题时弹「还有 N 道题未做，是否确认交卷？」取消/确定 |
| 交卷后 | 页面停在原答题页并显示「您已成功交卷！」+「已提交」水印 |
| 考后签名 | 若开启「考后电子签名确认」，提示「本考试已开启"考后电子签名确认"，请完成电子签名，以确认本次考试由您本人完成」+「前往签名」按钮 |
| 考前签名 | 若开启「签名确认」，点开始考试先弹 canvas 签名框（清除重签/取消/确认） |
| 标记 | 每题有标记按钮，用于标记不确定题并快速定位；答题卡图例：未做/已做/当前 |
| 答题卡 | 按大题分组列题号，右侧固定；显示进度 N/总题数 |
| 心跳 | `PUT /ote/ue/{ueId}/exam/time` 轮询，返回服务端当前时间与剩余时间；用于校正倒计时与强制交卷判断 |
| 水印 | `GET /ote/watermark?appCode=ote` 控制整页水印 |

# 第二轮勘探（2026-11-10，全覆盖题型）

> 考试：`内部测试用考试试卷`，arrangeId `d385dba2-bc43-4fa1-8e7f-c762414564c1`
> 配置：18 分 / 10 题 / 不限时 / 通过分 10.8 / **不限次数** / 开启考前+考后签名
> 题型覆盖：单选、多选、判断、填空、问答、**组合题（内含 5 个小题，覆盖五种题型）**

## 10. 答案格式（全部实测，最关键）

统一走 `POST /ote/ue/single/answer`，`answers[]` 每一项：

| 题型 | quesType | answer 形状 | 实测样例 |
|---|---|---|---|
| 单选 | 0 | `["选项id"]` | `["f44cc325-70ae-..."]` |
| 多选 | 1 | `["选项id","选项id",...]` | `["25f85cca-...","6084176d-..."]` |
| 判断 | 2 | 选项 id 数组（同单选） | 2 个 radio：正确/错误 |
| 填空 | 3 | `["第1空答案","第2空答案",...]` | `["测试答案一"]` |
| 问答 | 4 | `["答案文本"]` + `"attach":[]` | `["这是问答..."]` |

**要点**：
1. 单选/多选/判断存的是**选项 id**（`exam_question_item.id`），不是字母 A/B/C。
2. 填空/问答存的是**文本数组**；填空按空顺序逐项，问答固定 1 项。
3. 问答题多一个 `attach` 字段（附件数组），本项目首期可不做附件。
4. **组合题的子题各自独立提交**：每个子题用自己的 `quesId` + 真实 `quesType` 提交，
   没有"组合题父题"这一条答案。父题只负责分组与分值汇总。

## 11. 组合题（实测结构）

- 答题页展示为大题「六、组合题（本题共5小题，共9分）」，先显示**组合题父题干**，
  下面依次是 5 个子题，每个子题有自己的题号、题型、（X分）。
- 答题卡里组合题的下方直接平铺 5 个题号 `1 2 3 4 5`，**子题占用总题数**
  （本题 10 题 = 5 个独立大题 + 组合题 5 个子题）。
- 提交时子题各自一条 `answers`，`quesId` 是子题的 id。

## 12. 交卷前后

- 交卷前弹窗：**「还有 N 道题未做，是否确认交卷？」**；全做完时显示「还有 0 道题未做」，同样弹一次。
- 交卷接口：`PUT /ote/ue/{ueId}/submit`，body 只有 `isH5Exam/submitType/uniqueId/usedTime/orgId`，`usedTime` 秒。
- 交卷后页面**不跳转**，留在答题页并加「已提交」角标，弹出「您已成功交卷！」。
- 若开启**考后电子签名**：弹窗提示需完成签名确认本人作答，入口「前往签名」。
  本次实测该企业**未授权签名服务**，提示「当前企业未授权签名服务，请联系平台管理员」，
  导致无法完成考后签名、也就无法正常退出到成绩页——属环境限制，成绩页仍未观察到。
- 未完成考后签名时点「退出」→ 提示「当前考试未交卷，是否确定退出？」。

## 13. 答题卡状态实现（前端可照抄）

题号元素类名 `uexam-answer-card`，状态用附加类区分：
- `answered` = 已做（蓝色实心）
- `answering` = 当前题（蓝色描边）
- 无附加类 = 未做（灰色）
- 标记态另有独立图标，图例：未做 / 已做 / 当前 / 标记（红旗）

右侧答题卡含顶部进度条与 `N/总题数` 文本。

## 14. 仍待补

1. **成绩页/答案解析页**仍未看到（被考后签名授权限制挡住）。需要：
   - 关闭「考后签名」的考试，或企业授权签名服务；
   - 且开启「允许查看答卷详情」（`allowViewResultDetail=1`）。
   要观察：分数展示、通过/未通过、每题对错标注、正确答案、解析、得分明细。
2. **多空填空题**仍未观察到：本题填空只有 1 个空。需专门建一道 3 空填空
   （且建议开启「按空得分」）来确认 `answer` 数组是否逐空一项、以及按空给分在结果里的呈现。
3. 「退出」按钮在未交卷时的完整行为（是否计次、是否保存草稿）。

## 16. 「批阅中」状态的成因（关键映射）

本场管理端配置：
- 批阅设置里「填空题自动批阅 / 问答题自动批阅」**未开启**（默认关闭）
- 因此交卷后主观题进入人工批阅队列 → 学员端状态为「批阅中」，
  成绩与是否通过均不显示，答卷详情按钮禁用。

**结论**：学员端必须支持「待批阅 / 批阅中」这一中间状态，
并把自动批阅开关作为配置读取，不能假定交卷即出分。

## 17. 再次考试

结果页右上角有「再次考试」按钮（本场配置为不限次数，所以可用）。
若配置了限制次数，此处应受次数约束。

# 第四轮勘探：配置项对学员端的实测影响（2026-11-10）

## 19. PC端作答样式 → 两种答题布局（已实测）

| 配置 | 学员端表现 |
|---|---|
| **所有试题显示在一页**（默认） | 左侧全部题目纵向平铺，滚动查看；无「上一题/下一题」 |
| **每页仅显示一题** | 左侧**只渲染当前一道题**，底部出现「下一题」；回退后出现「上一题」；右侧答题卡不变，可直接跳题 |

实测切换后答题页仍显示大题标题（如「二、多选题（本题共1小题，共3分）」），
说明分页粒度是**逐题**，不是逐大题。进度显示不受翻页影响（未答时仍 0/10）。

> 契约要求：作答样式必须作为配置读取，两种都要实现。

## 20. 「批阅中」与自动批阅的关系（已定位成因）

第一次交卷时：**填空自动批阅 = 关、问答自动批阅 = 关**
→ 结果页状态「批阅中」，是否通过 / 成绩 / 排名 均为 `--`，「查看答卷详情」按钮禁用。

随后开启这两个开关并重新发布（对已交答卷不追溯），下一次交卷应直接出分。
**结论**：学员端必须实现「待批阅」中间态，不能假定交卷即出分。

## 31. 答卷可见性三选项的真实语义（用户确认 + 实测）

之前反复失败是因为语义理解错了。三个平行选项：

| 选项 | 语义 |
|---|---|
| 考试通过后查看 | **分数达到通过分之后**才能看；未通过则一直不可看 |
| 考试结束后查看 | **考试整体结束**（入场/考试期结束）后才能看，**不是交卷后** |
| 限制时间内查看 | **交卷后**在指定时间窗口内即可看 ← 要交卷后立即看必须选这个 |

> 这也解释了为什么本场入场期到 2030 年、交卷后按钮一直禁用（当时选的是"考试结束后查看"）。

## 40. 对「批阅人」配置的印证（重要）
