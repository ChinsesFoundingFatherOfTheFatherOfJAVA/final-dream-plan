## 二、8 个问题 · 最终结论

### Q1 考试列表页形态
**要左侧统计栏**，但只放三项：**待考 / 进行中 / 已完成**。
不追求更多指标——学员真正关心「还有几场要考」。

### Q2 学习任务卡

**① 考过但没通过：显示，按三档分组。**
分组：`未开始` / `未通过（可重考）` / `已通过`。
理由：若未通过就消失，学员会以为考试被取消，产生困惑。原平台结果页本身就有「再次考试」与「考试历史」，承认多次作答。
次数已用完的未通过记录仍保留在「未通过」组，可查看成绩但不可再考。

**② 话术训练 / 实战训练任务卡：加，但 v1 只展示各自现有数据。**
已核实：两模块**都没有任务分配实体**（话术=StudentProjectController 直接列项目；实战=act_theme_participant 参与关系）。
因此 v1 卡片内容为：
- 话术训练卡：我参与的项目 + 完成状态
- 实战训练卡：我参与的主题 + 通过情况
**不做新的任务派发机制**（指派、截止时间、催办等）。待原平台这块勘探清楚后再补。

### Q3 交卷后成绩呈现
**先出客观题分，标注主观题待批阅。**
- 客观题分立即展示，形如「客观题 4/9 分」
- 主观题标注「待批阅」
- **最终总分、是否通过、排名在批阅完成后才出**
> 与原平台（全部 `--`）不同，属**有意改进**，需记入偏差记录。

### Q4 批阅入口
**两个都做**：
- 管理端「考试批阅」全局视角（M1→M2→M3）
- 学员端「我的陪练 → 教学任务 → 考试批阅」批阅人视角（只看自己负责的）

### Q5 批阅人范围
**本期只做「创建人 + 指定批阅人」两种。**
不做部门经理/直属经理：技术可实现，但**「谁算部门经理」的判定口径未定义**（一个部门可能多个负责人），口径不定就是猜。先做两种语义明确的。

### Q6 AI 判分时机
**异步。** 交卷后立即返回，后台异步判分；学员先看到「待批阅」，判完刷新可见。
技术上复用现有异步线程池与 AIGentService 工作流通道。

### Q7 打乱题序/选项序
**不做，仅保留配置项与字段，标注「本期未实现」。**
理由：
1. 防作弊价值低——线上考试无邻座，真要作弊是拍照外传，乱序拦不住；
2. 实现代价高——需服务端固化随机种子、保证重进一致、答题卡映射、判分反查题号，任一处错就是答案错位；
3. 负体验——两次进入顺序不同会让学员怀疑数据出错。

### Q8 历史数据处理
**不做任何数据迁移。** 状态按 `exam_attempt`（arrangeId/userId/score/submitAt/passStatus）实时推算。
- 理由：数据已够用；推算只读零风险；学员端是全新页面无兼容包袱。
- **已知现象**：历史答卷的 `exam_attempt_answer.correct_flag` 为 null（判分本轮才实现），
  打开历史答卷会显示「未判分」。这是**正确表现，不是 bug**。
- **不给历史答卷补判分**：那是重新判历史成绩，风险远大于收益。

## 三、实现顺序（五批）

```
第一批（最小闭环）：P1 入场 + P2 答题 + F2 逐题保存 + F3/F4 交卷 + P4 结果（含 Q3 客观分）
第二批：P5 答卷详情 + M1/M2/M3 批阅（复用 ResultPage 加打分模式）
第三批：P3 单题分页、F5/F6 签名、F7 标记、F8 倒计时心跳
第四批：配置项接入（作答样式、批阅开关、答卷可见性、防作弊、信息安全）
第五批：人脸核验、AI 批阅（依赖外部服务，风险最高）
```

前三批跑完即有「考完 → 看结果 → 人工批阅」完整闭环。
