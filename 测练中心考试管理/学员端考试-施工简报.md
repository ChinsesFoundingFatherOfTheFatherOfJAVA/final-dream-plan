## 〇、开工前必读（违反即返工）

### 1. 前端样式是重点，禁止脑补

> 用户原话：「前端页面的实现，一定要细心，不要偷懒，必要时完全可以去原平台看看样式和排版不要自己脑补，
> 之前在做完 AI 实战学员端之后因为样式问题专门大动干戈修复了一圈。」

**强制要求**：
- 每个新页面上线前，**必须打开原平台对应页面截图比对**，不得凭印象排版。
- 原平台 URL 与登录态见下节；比对的截图存 `观察素材/施工比对/`。
- 样式基线：主题色 `--el-color-primary: #1890ff`；表格/弹窗/按钮一律 Element Plus，不手写通用控件。
- 参照现有对练页 `front-end/src/views/student/AICombat/Drillmate/`（左侧信息栏 + 右侧主区的分屏惯例）。
- 表单抽屉 ≥560px；纯图标按钮补 `aria-label`；不用 `transition: all`。

### 3. ego 使用约束（血的教训）

- **一个 task space 只能一个 agent**：多人共用同名空间会互相导航抢页面。
  命名规则：`probe-<成员名>` 查页面，`e2e-<成员名>-<任务号>` 跑流程。
- 每完成一步**立即落盘证据**（截图/接口响应），不要攒到最后——单回合 token 预算耗尽会导致"证据在、报告没写"。
- 点击用真实鼠标（`click('@ref')` 或 CSS 选择器），**不要用 JS `element.click()`** 做路由跳转。

## 一、开工前必须完成的前置动作

### 1. 数据库迁移（阻塞项）

新列**当前不存在**，必须先跑 `07-建表SQL.md` 附录 C 的迁移：

```sql
-- exam_attempt: config_snapshot / identity_status / identity_evidence
-- exam_attempt_answer: marked
-- 新增 exam_face_baseline 表
-- exam_attempt_answer 唯一键 uk_attempt_ques
```

**执行前先查重**：
```sql
SELECT attempt_id, ques_id, COUNT(*) c FROM exam_attempt_answer
GROUP BY attempt_id, ques_id HAVING c > 1;
```
有重复则先清理，否则加唯一键失败。

### 2. 契约与代码的已知冲突（已核，需知会）

| 项 | 现状 | 处理 |
|---|---|---|
| `answer_json` 格式 | 现有 `ArrangeStatServiceImpl.parseAnswer` 兼容 `"AC"`/`["A","C"]`/`[0,2]`/`{"selected":[0,2]}` 四种旧形状 | **不冲突**：契约的 `{"answer":[...],"attach":[]}` 落在兼容范围内（它已读 `answer` 字段）。新代码按契约写即可，不改旧解析 |
| `exam_attempt.status=4` | 实体注释已有「已作废」 | 直接用，不新造 |
| 判分引擎 | `QuestionGrader` 已实现客观题+关键词判分 | 直接复用，不重写 |

## 二、任务拆分（按契约章节对齐）

### T1 · 后端：数据库迁移 + 实体补字段

- 跑迁移脚本；`ExamAttempt` 加 `configSnapshot`/`identityStatus`/`identityEvidence`；
  `ExamAttemptAnswer` 加 `marked`；新建 `ExamFaceBaseline` 实体+mapper。
- 契约：`07` 附录 C、`03` §10B.3
- 验收：`mvnw.cmd -o test` 绿；字段可读写。

### T2 · 后端：学员端只读接口（列表/入场/开始）

- `StudentExamService`：`listMyExams` / `entry` / `start`。
- 契约：`04` §11.2/11.3/11.6、`03` §10B.2
- 关键：状态由 `exam_attempt` 实时推算（DER-12）；`start` 支持续答；写 `config_snapshot`（DER-06）。
- 验收：单元测试覆盖「续答不重复计次」「次数用尽拒绝」「config_snapshot 落库」。

### T3 · 后端：答题接口（取卷/保存/标记/心跳/交卷）

- `StudentAnswerService`：`paper` / `saveAnswers` / `flag` / `time` / `antiCheat` / `submit`。
- 契约：`04` §11.7–11.11、`03` §10B.5（答案格式）
- 关键：**答案存选项 id 数组**；组合题子题各自一行；逐题 upsert（唯一键）；交卷前置校验顺序（时长→未答完）。
- 验收：幂等测试（重复提交/重复交卷）。

### T4 · 后端：判分调度 + 结果 + 答卷详情

- `ExamGradingService`（同步客观题 + 异步主观题）、`StudentResultService`。
- 契约：`04` §11.12/11.13、`11C`、`03` §10B.6
- 关键：交卷先返回客观题分（DER-03）；`viewAnswerTimeRange` 四值语义；只看错题真过滤。
- 验收：`graded=false` 时总分/通过/排名为 null；详情可见性校验正确。

### T5 · 后端：批阅模块

- `MarkService` + `MarkController`：列表/答卷列表/答卷详情/提交批阅/学员待办。
- 契约：`04` §11B.1–11B.5
- 关键：批阅人 = 创建人 / 指定人（DER-08）；提交后重算总分/通过/排名；支持重新批阅；
  `invalid=true` 走 `status=4`；身份异常答卷在列表显示标记（DER-07）。
- 验收：批阅后 M1 待批阅计数减少；重新批阅不累加。

### T6 · 前端：考试列表页 + 顶部导航入口

- `ExamListPage.vue` + `StudentTopNav.vue` 加「考试」。
- 契约：`01` §S1、`02` §8B.1
- **样式必做**：对照原平台列表页/对练列表页截图；左侧统计（待考/进行中/已完成）+ 右侧卡片。
- 验收：`npm run type-check`；截图比对通过。

### T7 · 前端：入场页 + 前置流程（声明/签名/人脸）

- `ExamEntryPage.vue` + `PreExamSignDialog.vue` + `FaceVerifyDialog.vue`。
- 契约：`01` §S2/§S3、`02` §8B.4
- **样式必做**：入场页字段顺序与分组对照原平台；签名 canvas 尺寸与按钮位置一致。
- 关键：人脸核验**任何失败路径都能继续**（DER-07）。
- 验收：摄像头拒绝授权仍能开考。

### T8 · 前端：答题页（两种布局）

- `AttemptPage.vue` + `AnswerSheet.vue` + `QuestionRenderer.vue`。
- 契约：`01` §S4、`02` §8B.3/8B.4
- **样式必做**：一页平铺与单题分页两种都对照原平台截图；答题卡图例、进度条、题号状态色一致。
- 关键：倒计时用服务端时间基准；逐题保存乐观更新；不渲染标准答案。
- 验收：切题不丢答案；刷新回显正确。

### T9 · 前端：结果页 + 答卷详情页

- `ResultPage.vue` + `AnswerPaperPage.vue`。
- 契约：`01` §S6/§S7、`02` §8B.4（AnswerPaperBody 双模式）
- **样式必做**：四格指标、印章、考核点表、题型统计逐块对照原平台截图。
- 关键：只看错题真过滤；三个筛选互不影响。
- 验收：批阅中/已出分两种状态都正确渲染。

### T10 · 前端：批阅模块三页 + 学习任务卡

- `MarkListPage.vue` / `MarkUserListPage.vue` / `MarkPaperPage.vue` + `Home.vue` 学习任务卡。
- 契约：`01` §M1–M4、§Q2、`02` §8B.5
- **样式必做**：批阅列表与原平台表格列一致；打分区位置与交互一致。
- 关键：复用 `AnswerPaperBody` 的 `grading` 模式，不重写答卷渲染。
- 验收：学员/批阅两模式共用组件且样式都正确。
