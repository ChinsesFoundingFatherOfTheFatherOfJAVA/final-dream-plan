# 测练中心·考试管理复刻 后端技术实现方案

> 版本：v1.0 ｜ 日期：2026-10-14  
> 配套：`01-需求文档.md`、`02-技术实现方案-前端.md`、`04-接口文档.md`、`07-建表SQL.md`  
> 工程：`D:\JACK\final_dream\after-end\ExamService`（现有服务，端口 8085；在既有 ExamService 增量扩展）  
> 技术栈：Java 21 + Spring Boot 4.0.8 + MyBatis-Plus 3.5.17 + MySQL 8 + Nacos + Dubbo。

## 1. 技术选型与理由

| 层 | 选型 | 理由 |
|---|---|---|
| Web | Spring Boot 4.0.8 | 后端架构总纲基线 |
| 持久层 | MyBatis-Plus 3.5.17 | 现有 ExamService 基线；简单 CRUD 用 MP，复杂统计 SQL 进 Mapper XML |
| 数据库 | MySQL 8 `final_dream` | 现有业务库 |
| 服务调用 | Dubbo 3.3.6 | 人员、部门、岗位数据通过 StaffManagement Dubbo 契约获取，禁止直表 |
| Excel | Apache POI 5.x | 考试列表、考生、成绩、试题分析导出；复用试卷模块导入/导出基础 |
| PDF | Apache PDFBox 3.0.x + 可分发中文字体 | 答卷详情导出 PDF；Apache-2.0 |
| 二维码 | 前端生成 | 后端只返回安全链接与 token，不在服务端保存图片 |
| 缓存 | 不急引入 Redis | 考试统计以 MySQL 聚合为主；仅链接 token 可使用短 TTL 缓存，二期按需 |
| 定时任务 | Spring `@Scheduled` 或现有任务框架 | 更新考试运行状态、定时发布/结束、清理过期导出文件 |

## 2. 已有实现调研与选型

完整候选见 `观察素材/已有实现调研.md`。

- 不直接接入开源在线考试系统：它们不满足本平台的多服务、分类权限、StaffManagement 数据所有权和 `ExamService` 既有试卷模型。
- 继续使用现有 ExamService 的 `Paper`、`Ques`、`Catalog` 领域能力；考试管理模块只新增考试编排、考生跟踪、考试统计和答卷查看。
- 依赖基础库采用 Apache License 2.0 / MIT：
  - Apache POI：Apache-2.0。
  - Apache PDFBox：Apache-2.0。
  - 若项目已有 PDF 库且许可证兼容，优先复用项目现有库，避免重复依赖。

## 3. 服务边界

### 3.1 本模块拥有

- 考试分类与考试主数据。
- 考试发布配置。
- 考试与试卷的引用、试卷快照。
- 考试考生安排、补考、同步状态。
- 考试尝试、答卷、签名、题目级统计。
- 考试链接、变更通知。
- 考试导出任务与操作日志。

### 3.2 本模块消费

- StaffManagement：
  - 用户查询：按姓名/账号/工号/部门/岗位搜索。
  - 部门树：考试分类权限、部门筛选、人员抽屉。
  - 岗位列表：岗位筛选。
  - 权限快照：判断超管、分类管理员、考试创建者/负责人。
- 试卷模块：试卷详情、发布校验、题目结构、统计基础数据。
- 学员端考试/答题模块：提交答卷、读取变更通知。

### 3.3 禁止事项

- 不在 ExamService 直读 `sys_*` 表；人员、部门、岗位全部走 Dubbo。
- 不在业务工程重建 `ApiResponse / BizException / PageResult`；统一使用 `after-end-common`。
- 不在 XML 中写跨域 JOIN。
- 不把原站接口硬编码复制进代码；抓包授权后只用于校正字段和枚举。

### 4.3 StaffManagement 现有 Dubbo 能力

已阅读 `StaffManagement-api`，部门和岗位能力已经存在，不需要新增基础契约：

## 5. 关键实现设计

### 5.1 考试创建与发布

```
createArrange(draft):
  1. 校验考试名/分类/时间窗
  2. 若 paperMode=select：校验 paperId 存在且已发布
  3. 若 paperMode=new/import：调用 PaperService 创建试卷，取得 paperId
  4. 写入 exam_arrange，publish_status=0，owner_user_id=当前用户或指定负责人
  5. 返回 arrangeId，前端进入发布配置页

publishArrange(arrangeId, publishForm):
  1. 行锁 SELECT ... FOR UPDATE 锁 exam_arrange
  2. 校验 paper 是否存在并已发布；若未发布则调 PaperService.publish
  3. 生成不可变 exam_paper_snapshot（版本号递增）
  4. 保存发布设置/通知设置/更多设置 JSON
  5. 计算 run_status：入时间未到=0，时间窗内=1，结束=2
  6. publish_status=1，published_at=now()
  7. 更新 exam_paper.used_qty 和 exam_paper_use
  8. 写操作日志
```

说明：

- 创建新试卷/导入试卷均复用试卷模块；考试模块不写 `exam_question`。
- `exam_paper_use` 增量补 `ref_id` 指向考试，本模块通过引用方维护。
- 若后续确认试卷发布后不可改，可继续保留快照表以兼容历史数据。
- 已实测原站「发布 / 更新后发布」对应 `POST /ote/arrange/fast-publish`，一次提交基本信息、`examArrangeControl4Put` 和 `notifyConfig4Put`；复刻时映射为 `POST /arrange/{id}/publish`。
- 已发布考试更新时：
  - 允许修改 `name/important/secrecy/catalog_id/entry_start_at/entry_end_at/excellence_score/pass_score_type/publish_settings/notify_settings`、说明、负责人、批阅人、使用试卷和部分更多设置。
  - 禁止修改试卷结构、试卷分类、出卷方式、题目/分值/策略。
  - 禁止修改「防作弊限制」和「学习任务限制」。
  - 「获得证书」本期不实现、不保存。
  - 使用试卷变更只影响后续 attempt 的 `snapshot_id`，不回写历史 attempt。

### 5.2 考生安排

```
addStudents(arrangeId, userIds):
  1. 权限校验：超管/创建者/负责人/分类管理员
  2. 校验考试未结束
  3. 经 StaffManagement 批量查询用户信息
  4. 对每个 userId：
     - 已存在且 deleted=0：跳过
     - 已存在但 deleted=1：复活并重置为未开始
     - 不存在：插入
  5. 若考试已发布，发「安排通知」
  6. 更新 arrange.participant_qty
```

唯一性：

- `exam_arrange_student` 用 `UNIQUE(arrange_id, user_id, deleted)` 防止活跃重复。
- 重新安排时复活历史行，不新增重复历史行。

### 5.3 补考、同步与分析

```
arrangeRetake(arrangeId, studentId):
  - 校验 pass_status!=1? 原站允许未通过/缺考安排；按业务规则
  - 校验 retake_used=0
  - 更新 student.exam_status=4，retake_used=1，last_retake_at=now()
  - 新建 attempt_no+1 的预留 exam_attempt（status=0）
  - 写通知

syncPaper(arrangeId, mode):
  - mode=unanswered: 只选择无 attempt 或未开始的 student
  - mode=all: 对所有 student 创建/更新后续 attempt 的 snapshot_id
  - 不修改已完成 attempt 的 snapshot_id
  - 返回影响人数

analyzeData(arrangeId):
  - 校验考试已完成或已交卷数据稳定
  - 重算 exam_attempt.rank_no
  - 重算 exam_arrange_score_stat
  - 重算 exam_question_analysis_stat
  - arrange.analysis_enabled=1, analysis_time=now()
  - 学员端接口从 analysis_enabled=1 后才返回排名与题目正确率
```

### 5.4 考试运行状态

推荐实现两种方式，按工程现有任务能力选一：

1. 读取列表时按 `entry_start_at / entry_end_at / publish_status` 实时计算显示状态，避免任务延迟。
2. 定时任务每 5 分钟更新 `run_status`，用于筛选和导出。

无论哪种，列表筛选 `runStatus` 不能只信存量字段；可在 SQL 中同时按时间条件计算：

```sql
CASE
  WHEN publish_status = 0 THEN 0
  WHEN NOW() < entry_start_at THEN 0
  WHEN NOW() BETWEEN entry_start_at AND entry_end_at THEN 1
  ELSE 2
END AS run_status
```

### 5.5 考生筛选与列设置

- 筛选参数进入 `POST /arrange/{id}/student/list` body，分页参数在 query。
- 部门/岗位先从 StaffManagement 取 user id 列表或本地快照字段 `dept_id/position_id` 过滤；优先使用本地冗余字段减少跨服务查询。
- 列设置保存在 `exam_user_setting`：

```json
{
  "bizType": "arrange_student_columns",
  "setting": [
    {"key":"account","visible":true,"order":1},
    {"key":"fullname","visible":true,"order":2}
  ]
}
```

### 5.6 导出

导出分两类：

- 小数据量同步导出：直接返回 `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`。
- 大文件/答卷 PDF：创建 `exam_export_task`，异步生成，前端轮询任务状态或下载。

导出类型：

| 类型 | 内容 | 实现 |
|---|---|---|
| `ARRANGE_LIST` | 考试列表 | POI Excel |
| `STUDENT_HIGHEST` | 仅最高成绩 | POI Excel |
| `STUDENT_ALL` | 所有成绩 | POI Excel |
| `STUDENT_ANSWER` | 学员答卷 | PDFBox 生成每个答卷 PDF，再 zip |
| `QUESTION_STAT` | 试题分析 | POI Excel |
| `SIGNATURE` | 签名记录 | POI Excel；签名列插入图片 |

文件名：

```text

考试名称_考生最高成绩_20261014.xlsx
考试名称_全部成绩_20261014.xlsx
考试名称_学员答卷_20261014.zip
```

### 5.7 试题统计与统计分析

统计来源：

- `exam_attempt_answer`：逐题作答明细。
- `exam_question_analysis_stat`：分析数据后聚合，避免每次查询全量明细。
- `exam_attempt`：考试尝试、成绩、状态、时间。
- `exam_arrange_student`：参与人数、通过状态。

统计分析接口在 `analysis_enabled=0` 时可返回实时基础统计，但正确率/排名以最后一次分析为准。

正确率计算：

```text
correctRate = correctQty / answerQty
```

- `answerQty = 0` 返回 `null`，前端显示 `--`。
- 题型维度按 `exam_question.type`。
- 难度维度按 `exam_question.level_type`。
- 考核点维度按 `exam_question_point` 关联；一个题挂多个考核点时，按参与统计的考核点分别计入。

### 5.8 答卷详情

`GET /result/{ueId}` 以 `exam_attempt.id` 定位：

1. 查 `exam_attempt`、`exam_arrange_student`、`exam_paper_snapshot`。
2. 读取快照 JSON 中的题目结构，保证历史答卷不受试卷后续编辑影响。
3. 合并 `exam_attempt_answer` 的考生答案、得分、正误。
4. 从 `exam_question` / `exam_question_point` 读取题目展示字段（若快照已内嵌，则优先快照）。
5. 返回按 `section_index, order_index` 排序的题目列表。

PDF 导出：

- 使用 PDFBox，页面 A4。
- 中文字体随 `resources/fonts/NotoSansCJKsc-Regular.otf` 分发，字体为 SIL OFL 1.1，不与服务代码冲突。
- 选项和解析中 HTML 先解析为纯文本；图片答题场景二期扩展。

### 5.9 变更通知与通用事件通道

```
sendChangeNotice(arrangeId, title, content):
  1. 校验权限和考试状态
  2. 找出当前未移除的 exam_arrange_student.user_id
  3. 写 exam_change_notice 作为考试模块的发送记录/审计记录
  4. 同事务写 exam_notice_outbox，记录通用通知事件与去重键
  5. 事务提交后，由 outbox worker 调 StaffManagement 的通用通知 Dubbo 服务
  6. 通用通知服务负责接收人解析、站内信写入、已读状态和后续短信/邮件/IM 渠道
  7. 返回 noticeId、eventId 和 recipientQty
```

考试模块不再拥有学员已读表；学员端查询和已读状态由通用通知服务负责。详细设计见 `08-通用通知通道设计.md`。

通用通知接口草案：

- `GET /api/sm/notices?readStatus=&sourceService=&current=&limit=`
- `PUT /api/sm/notices/{recipientId}/read`
- Dubbo `NotificationPublishService.publish(NotificationEventDTO)`

### 5.10 权限模型

`ArrangePermissionService` 统一校验：

```text
canView       = 超管 || 创建者 || 负责人 || 分类管理员 || 共享查看者
canEdit       = 超管 || 创建者 || 负责人 || 分类管理员
canDelete     = 超管 || 创建者
canPublish    = canEdit && publishStatus in(0)
canManageUser = canEdit && publishStatus in(1)
canExport     = canView
```

前端通过详情和列表返回的 `permissions` 控制按钮，后端在每个写接口重复校验。

## 7. 事务与一致性

| 场景 | 事务要求 |
|---|---|
| 发布考试 | 锁 arrange + 读/发布 paper + 写快照 + 写引用，同一事务；通知异步 |
| 添加学员 | 批量 upsert + 更新 participant_qty 同事务 |
| 批量移除 | 逻辑删除 + 更新计数 + 写操作日志同事务 |
| 安排补考 | 检查 `retake_used` + 更新 + 新建 attempt 同事务，防重复 |
| 同步试卷 | 批量更新目标 attempt/student 的 snapshot_id，事务或分批幂等 |
| 分析数据 | 分阶段重算，最后写 `analysis_enabled`；失败不改标志 |
| 导出 | 任务创建后异步，不影响主业务事务 |

## 8. 部署要点

- 网关继续路由 `/api/exam/**` 到 `lb://ExamService`。
- 上传/导出文件根目录通过 `exam.files.root` 配置，禁止写入源码树。
- PDF 中文字体放 classpath 或可配置文件目录，部署时确认字体存在。
- 导出临时文件定期清理，任务记录保留 30 天。
- 统计重算可能耗时，批量更新分批提交，避免长事务锁表。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 原站枚举与自设计不一致 | 前端筛选显示错误 | 抓包授权后校正；前端枚举集中管理 |
| 试卷后续编辑影响历史答卷 | 历史数据不可复现 | 发布时快照，attempt 固定 snapshot_id |
| 跨模块人员/岗位查询性能 | 筛选慢 | 本地冗余 user/account/dept/position；复杂筛选走 Dubbo 批量接口 |
| 正确率实时扫描全量作答 | 数据库压力 | 分析任务聚合到 `exam_question_analysis_stat` |
| 大导出 OOM | 服务不稳定 | SXSSF 写 Excel；PDF 分页写；异步任务 |
| 补考并发重复 | 同一考生多次补考 | `retake_used` + 行锁 + 唯一 attempt_no |
| 通知未真正送达 | 学员漏看 | 通知记录 + 站内信 + 学员端未读数量 |
