# 学员端考试 · 功能点与复刻程度对照清单

> 用途：platform-replication 第二步「逐项定复刻程度」的评审底稿。
> 依据：`观察素材/学员端考试-勘探记录.md`（实测）+ `观察素材/学员端考试-配置映射.md`（配置）
> + `04-接口文档.md`（现有契约）。
> **待你逐项确认：每项选 简单 / 中等 / 全部，或「本期不做」。**

## 0. 先决结论（影响整体工作量）

| 事项 | 现状 | 说明 |
|---|---|---|
| 学员答题页 | **完全没有** | 现前端 `views/exam/` 全是管理端，路由都要求 `requiresAdmin` |
| 学员端接口 | **完全没有** | 契约 04 §11 明确「本模块提供消费接口，不实现答题页」 |
| 判分引擎 | **已做**（`QuestionGrader`） | 单选/多选/判断/填空/问答已实现，含按空给分与漏选策略 |
| 考试配置 | 已有骨架，**缺 20+ 项** | 见下表第 3 节 |

> 结论：这是**从零建一个学员端子系统**，不是补几个接口。而现有管理端配置契约已比实际实现完整，可直接复用。

## 1b. 批阅模块（3 个页面，2026-11-10 追加）

> 追加原因：批阅人是「人工兜底」的落点，也是 AI 判分、自动批阅开关的最终闭环。
> 缺了它，自动批阅/智能批阅就是空转——判错的、申诉的、异常的都无处处理。
> 勘探记录见 `观察素材/学员端考试-勘探记录.md` §36–§41。

| # | 功能点 | 原平台实测要点 | 复刻程度 | 本期是否做 |
|---|---|---|---|---|
| M1 | 批阅列表页（考试维度）`arrange/mark/mgmt` | 表格：考试名称/来源/发布日期/安排人数/交卷人数/**待批阅**；操作：查看详情/快速批阅；筛选：考试名/来源/日期区间 | | 做 |
| M2 | 批阅答卷列表（学员维度）`arrange/review/users/mgmt?arrangeId=` | 表格：账号/姓名/部门/岗位/提交时间/用时/**批阅人**/**批阅时间**/得分；操作：查看·批阅／查看·重新批阅；**同一学员多次作答逐条列出**；导出数据；批阅状态筛选 | | 做 |
| M3 | 批阅答卷页 `examresultpaper?ueId=` | 与学员答卷详情页**同一页面**，多出：导出pdf、批阅人信息、**打分区**（对错图标+分值输入）、取消/提交；显示**全部题目**（不默认只看错题） | | 做 |

> 实现建议：**M3 与 P5 做成一个组件的两种模式**（`readonly` / `grading`），避免写两遍。

**批阅人的两个入口（原平台都有，均需复刻）**：

| 入口 | 路由 | 视角 |
|---|---|---|
| 管理端「考试批阅」菜单 | `arrange/mark/mgmt` → M2 → M3 | 全局：所有考试待批阅汇总 |
| 学员端「我的陪练」→ 教学任务 → 考试批阅 | `stu/markInfo?arrangeId=` | 只看自己负责的（批阅人视角精简版） |

## 4. 需要的契约更新（若上述确认）

1. `04-接口文档.md` §11「与学员端答题模块的联动契约」由「本模块不实现」改为**新增学员端子章节**，补 8 个接口：
   - `GET /student/exams`（我的考试列表）
   - `GET /student/exams/{arrangeId}/entry`（入场信息）
   - `GET /student/exams/{arrangeId}/pre-check`（考前校验/声明）
   - `POST /student/exams/{arrangeId}/start`（开始，返回 ueId）
   - `POST /student/attempts/{ueId}/answers`（逐题保存）
   - `PUT /student/attempts/{ueId}/submit`（交卷）
   - `GET /student/attempts/{ueId}/result`（结果）
   - `GET /student/attempts/{ueId}/paper`（答卷详情）

2. **新增批阅模块接口（2026-11-10 追加）**：
   - `GET /exam/mark/list`（批阅列表，考试维度，含待批阅计数）
   - `GET /exam/mark/{arrangeId}/base`（批阅页头部信息）
   - `GET /exam/mark/{arrangeId}/users`（某考试的答卷列表，学员维度）
   - `GET /exam/mark/paper/{ueId}`（批阅答卷详情）
   - `POST /exam/mark/paper/{ueId}`（提交批阅结果：逐题对错+分值）
   - `GET /exam/mark/student/todo`（学员端「教学任务」待批阅列表）

3. `advancedSettings` 补 🆕 标出的键，并明确 `answerView.viewAnswerTimeRange` 的三值语义 + 时间窗字段。
4. 答案格式统一为「选项 id 数组 / 文本数组 + attach」，写进接口文档，避免后续再踩。
5. **批阅人配置与批阅队列的关系**（新增说明）：
   - `reviewerType`（创建人/部门经理/直属经理/指定人/定向）决定「谁能看到并处理」；
   - 自动批阅/智能批阅决定「要不要进人工队列」；
   - 两者互补，不是二选一：任何一份卷都应可被批阅人「重新批阅」。
