# 话术训练业务闭环模块 技术实现方案

> 版本：v1.0（2026-09-24）。工程基线：SpeechTraining（Spring Boot 4 + MyBatis-Plus 3.5.17 + MySQL final_dream）+ front-end（Vue3+TS+Pinia+ECharts，手写 SCSS）+ 组织架构模块（StaffManagement JWT 登录 + sys_* 表，9-23 已交付）。
> 本模块零新增外部依赖、零开源引入（Phase 2 侦察结论：纯既有平台功能增量，自研 SQL 聚合+ECharts 是最短路径）。

---

## 1. 架构总览

```
front-end（既有工程）
 ├─ 管理端 /sparring/newmanage/console/{projectId}/overview|student|studentdetail   （新增 3 页）
 ├─ 学员端 /web/speech/list（改造：指派过滤）/studentReport（新增，复用组件）
 ├─ 路由守卫：JWT 登录态 + act:speech 权限（管理端组）
 └─ 复用组织架构模块：登录页、部门树选人弹窗、员工数据接口

after-end/SpeechTraining（既有工程新增）
 ├─ ProjectStudentController/Service —— 指派增删查 + 邀请选人
 ├─ ProjectStatisticsController/Service —— 概览统计（summary/times/radar/active/students/depts）
 ├─ StudentReportExtController/Service —— 学员详情（tops/attend-record/practice-analysis/dimension-radar）
 ├─ RankService —— 排名（总分+各维度）
 ├─ AccessControl —— act:speech + 创建者双校验
 └─ UserContext 改造 —— mock → JWT（组织架构模块签发）

组织架构模块（StaffManagement，已交付）提供：登录/JWT、sys_user（含禁用状态/部门/岗位）、sys_dept 树、权限点表
```

**鉴权链路**：front-end 登录（组织架构登录页）→ localStorage JWT → axios 拦截器 Authorization 头 → SpeechTraining 网关/过滤器解析 JWT → UserContext（user_id=工号）。原平台"一次性 code 换 token"机制不采用（那是它跨服务隔离的方案，我方单体直接 JWT）。

## 2. 数据模型（DDL 全文见 07-DDL变更清单.md）

### 2.1 新表 `project_student`（指派关系）

```sql
CREATE TABLE project_student (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  project_id BIGINT NOT NULL COMMENT '训练项目ID',
  user_id VARCHAR(64) NOT NULL COMMENT '学员工号(sys_user.user_id)',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  created_by VARCHAR(64),
  UNIQUE INDEX uk_project_user (project_id, user_id),
  INDEX idx_user (user_id)
) COMMENT='训练项目指派学员(硬删,移除后历史训练保留)';
```

### 2.2 既有表改造

| 表 | 变更 | 说明 |
|----|------|------|
| training_project | 无 DDL（responsible_person 列保留不新写） | 负责人语义=created_by_name（FP-57） |
| sys 权限表（组织架构模块） | **无需插入**，复用既有种子 `act:speech`/`act:template`/`act:training` | 权限点由 StaffManagement `DataInitializer` 初始化；`AccessControlServiceImpl` 命中任一即放行，不新增 `sparring:manage` |

### 2.3 统计口径的 SQL 落点（不落表，全部实时聚合）

- 学习次数（学员×项目）= `training_report` 该 user 已生成报告数（status=2）；**注意按会话去重口径不变**（uk_session 一对一）
- 学习时长 = `training_session.duration_seconds` 求和（仅该学员该项目全部会话，含未完成——时长与次数口径分开）
- 完成状态 = 日常：次数≥completion_standard；考核：pass_strategy 判定（单次/累计N/连续N，对 status=2 的报告按 create_time 排序求最大连续达标段）
- 部门模式聚合 = project_student ⋈ sys_user（dept_full_name）GROUP BY dept_full_name
- 活跃分布 = `training_session.start_time` 按 HOUR() 聚合（**跨时钟纪律**：start_time 由 JVM 写，DATE_FORMAT 用应用侧聚合不涉 DB 时钟比较，安全）

## 3. 后端设计

### 3.1 模块划分

| 类 | 职责 |
|----|------|
| `controller/AdminProjectStudentController` | 指派列表/邀请/批量移除/选人数据源（部门树+员工分页） |
| `controller/AdminProjectStatisticsController` | 概览：summary / times-averages / radar / active / students(POST 分页筛选) / depts(POST 分页) |
| `controller/AdminStudentDetailController` | 学员详情：tops（最高分+排名）/ practice-analysis（折线）/ attend-record（训练记录分页）/ radar（第 n 次维度）/ 报告抽屉数据（复用既有报告接口，见 3.4） |
| `controller/StudentSparringController` | 学员端：列表（指派过滤改造既有接口）/ 排名（rank） |
| `service/AccessControlService` | ①模块权限：JWT 解析角色→权限点命中 `act:speech`/`act:template`/`act:training` 任一即放行（`AccessControlServiceImpl.ACT_PERMISSIONS`）②创建者：project.created_by == currentUser；写操作统一 @CheckOwner 或方法首行校验，返回 403 语义（code=403001） |
| `service/PassStrategyService` | FP-42 判定（纯函数 + 单测三策略×边界：空序列/恰好N/断段重计） |
| `service/RankService` | 排名：某项目指派学员 ∩ 已生成报告，按总分或某维度分（training_report_dimension）最高分降序，DENSE_RANK 同分同名次；支持姓名过滤 |
| `service/impl/StudentProjectServiceImpl` | 改造 listProjects：`status=1 ∩ 时间有效 ∩ project_student(user_id=me)`；completed 徽标改调 PassStrategyService |

### 3.2 权限实现要点

- 过滤器：从 Authorization 解 JWT（组织架构模块的签名密钥/公钥，跨模块共享配置）→ UserContext（userId/姓名/权限点集合缓存）。
- **双校验顺序**：先模块权限（403001 无模块权限）再创建者（403002 非创建者禁止修改）。
- 学员端接口只校验登录态；数据隔离 SQL 强制带 user_id 条件（沿用既有纪律）。
- mock 兼容：无 Authorization 头时**开发环境**回落 mock_student_001 并 WARN（历史联调脚本不炸）；生产 profile 关闭回落。

### 3.3 统计服务实现要点

- 907 学员量级全部 SQL 聚合（JOIN + GROUP BY），禁止全量拉内存循环（既有 listProjects 的内存分页模式**不扩散**到统计接口）。
- 学员列表（概览/学员管理两处同构）：一条主查询 `project_student ⋈ sys_user LEFT JOIN (报告聚合子查询) LEFT JOIN (会话聚合子查询)`，筛选条件下推；部门/岗位多选走 id IN。
- 概览雷达"记录"tab = 第 1 次报告的维度平均（firstDataStatistics 语义）；"总均分"= 全部报告维度平均。维度列**动态**：以项目 scoring_dimension 为列透视（SQL 按行返回，Java 侧按维度 map 组装，不写死字段）。

### 3.4 学员详情/报告抽屉复用

- 学员详情页（管理端 studentdetail 与学员端 studentReport）= **同一 Vue 页面组件** `StudentReportPage.vue`，props：projectId + userId（管理端传路由参数，学员端默认当前登录人）。
- 报告抽屉 = 既有 `PracticeReport.vue` 的**内容子组件**（评分明细 ScoreDetail / 对话记录 ChatRecord / 雷达 RadarChart）抽成可复用块 + 新建 Drawer 容器（约 520px 宽，内部窄列自适应、字号不缩）；数据接口直接复用既有 `GET /student/reports/session/{id}`（管理端场景加 userId 参数 + 创建者/权限校验）。
- 对话记录 tab 复用既有 ChatRecord（含改进建议/点赞，点赞接口本模块不动）。

### 3.5 邀请选人弹窗

- 数据源：组织架构模块既有员工分页接口（部门树 sys_dept + 员工列表 sys_user，支持关键词）；弹窗组件参考员工名册已交付的"岗位弹窗多选"交互模式（左树右表勾选）。
- 已指派学员在弹窗中置灰；确认后 `POST /admin/projects/{id}/students`（批量插入，幂等）。

## 4. 前端设计

### 4.1 新增路由

```typescript
// 管理端（ConsoleLayout 子路由，需 act:speech）
{ path: 'newmanage/console/:projectId/overview',  component: ProjectOverview },
{ path: 'newmanage/console/:projectId/student',    component: ProjectStudents },
```

### 4.2 页面要点

- **ProjectOverview.vue**：三卡（统计数字 28px）+ ECharts bar（按次平均分）+ 雷达（tab 记录/总均分）+ ECharts line（活跃 24 点）+ 学员/部门双模式表格。图表空态=覆盖层文案不画 0 值。
- **ProjectStudents.vue**：筛选栏（完成状态下拉/部门弹窗/岗位弹窗/账号状态下拉/关键词）+ 表格 + 邀请弹窗 + 批量删除 + 导出 CSV（UTF-8 BOM 防中文乱码，前端拉全量）。
- **StudentDetail / StudentReportPage**（同构）：信息卡 + 训练分析折线（维度下拉）+ 第 n 次 tab + 雷达 + 查看详情抽屉 + 训练记录表。
- **RankDrawer.vue**：tab=总分+动态维度；DENSE_RANK 数据后端算好直接渲染；"(我)"高亮。
- **详情页头部**：负责人=创建者；参与人数=指派学员数（新增轻量接口或随详情返回）。

### 4.3 既有页面改造

- SpeechList：接口不变（后端已过滤），无 UI 改动。
- EditProject：删"负责人"手填框。
- 路由守卫：管理端组检查 act:speech（取自登录响应的权限点集），无则 403 页；全站未登录重定向组织架构登录页。

## 5. 关键实现难点与对策

| 难点 | 对策 |
|------|------|
| JWT 跨模块（StaffManagement 签发、SpeechTraining 校验） | 沿用组织架构模块 02 文档的密钥共享方案（同一 JWT secret 配置两工程）；解析失败=401 跳登录 |
| 统计接口维度动态透视 | SQL 返回行式（dim_name, score），Java 组装 map；报表抽屉同理复用 |
| 连续达标段计算 | 纯函数 + 单测（序列断段、恰好 N、空）；报告按 create_time 升序，同刻并列按 id |
| 历史数据兼容 | mock_student_001 的会话/报告保留（user_id 不迁移）；该"学员"无指派则列表不显示，报告直链可查 |
| 报告抽屉组件抽取回归 | 抽组件时保持 PracticeReport.vue 既有 DOM/样式零变化（vitest 既有 21 例全绿为闸） |
| 排名同分并列 | SQL DENSE_RANK() OVER (PARTITION BY ... ORDER BY score DESC) |

## 6. 风险清单

| 风险 | 应对 |
|------|------|
| 组织架构模块未上线（仅文档） | P2 实施前先确认该模块编码进度；若未上线，UserContext 保留 mock 回落开关（dev profile），其余功能照常交付 |

| 移除学员后其报告仍占"按次平均分"统计 | 口径决定：统计仅统计**当前指派**学员（与排名范围一致）；决策记录在案（如需含历史另议） |
