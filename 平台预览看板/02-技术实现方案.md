## 1. 总体架构

采用**各域自建统计端点 + 前端并发聚合**（01-需求文档.md 第 6 节 DER-06）：

    管理端 /homepage
        │  Promise.all 并发
        ├── GET /api/sm/admin/stat/users   → StaffManagement(8083)  启用人数
        ├── GET /api/kng/admin/stat/home   → OnlineClassroom(8084)  课程情况 + 学习人数/时长 + 折线
        ├── GET /api/admin/stat/home       → SpeechTraining(8081)   项目情况 + 训练人数/时长 + 折线
        ├── GET /api/act/admin/stat/home   → AtualCombatTraining(8082) 练习人数/时长 + 折线
        └── GET /api/exam/admin/stat/home  → ExamService(8085)      考试情况 + 参考人数/时长 + 折线

为什么不在网关侧或新建服务聚合：后端架构总纲 第 2 节要求「一张表一个所有方，跨域一律走契约」，四域各自拥有自己的统计表，
每个服务只算自己域内的数是最小改动；新建聚合服务需要额外工程、网关路由与部署项，收益仅为前端少三次请求（DER-06）。

## 2. 后端实现

### 2.1 统一响应结构

四个业务域端点返回同一个 data 骨架（字段定义见 03-接口文档.md 第 2 节）：

    {
      "range":    { "from", "to", "granularity", "truncated" },
      "activity": { "activeUsers", "activeHours", "series": [ { "bucket", "activeUsers", "activeHours" } ] },
      "cards":    { 各域自有指标键 }
    }

「各域自有指标键」严格只放本域表能算出的数，不出现他域字段：

| 域 | cards 键 |
|---|---|
| OnlineClassroom | courseTotal、courseNew、studyVisits、studyHours、finishedVisits、commentCount |
| SpeechTraining | projectTotal、projectNew、coveredUsers、studyVisits、finishedVisits、studyRate、finishRate |
| AtualCombatTraining | practiceVisits、finishedVisits、practiceHours |
| ExamService | examTotal、examNew、coveredUsers、attemptVisits、passedVisits、passRate |

StaffManagement 单独一个轻量端点，只返回 enabledUsers 与 totalUsers（03-接口文档.md 第 2.1 节）。

### 2.2 各域查询实现

**通用约束**（后端架构总纲 第 5 节）：单表 CRUD 用 MyBatis-Plus；统计/分组/动态 SQL 进 Mapper XML；
XML 不写跨表 JOIN；跨表数据由 Service 批量查后 Map 组装；外部输入一律 #{} 绑定。

**OnlineClassroom（kng）**
- 主体聚合走一条 SQL：按时间桶 GROUP BY，同时算出 sum(study_len_hours)、count(distinct user_id)、count(*)、
  sum(case when study_status = 1 then 1 else 0 end)，时间桶用 DATE_FORMAT 按 granularity 切换：
  day=`%Y-%m-%d`、month=`%Y-%m`；**week 取该周周一的日期 `%Y-%m-%d`**（用 `WEEKDAY` 回退到周一起点），
  出参再裁成 `MM-DD`。不要用 `%x-%v`（ISO 年+周序号）——它无法按 03-接口文档.md 第 3.1 节还原成 MM-DD 标签（DER-07）。
- 课程总量与本期新增另用两条单表 count（kng_course），不与学习记录 JOIN。
- 评论数直接返回 0（01-需求文档.md 第 6 节 DER-03，受配置键 stat.home.comment-count-enabled 控制）。

**SpeechTraining（st）**
- training_session 按 start_time 分桶聚合：count(*)、count(distinct user_id)、sum(duration_seconds)、sum(case when status = 1 then 1 else 0 end)。
- project_student 只做 distinct user_id 全量统计（覆盖人次），与 session 分开查，Service 层组装学习率/完成率。
- 注意：本域 user_id 存的是 sys_user.account（01-需求文档.md 第 6 节 TBD-02），本期各域独立计数，不做跨域折算。

**AtualCombatTraining（act）**
- act_practice_attempt 按 COALESCE(started_at, created_at) 分桶；活跃时长 = sum(TIMESTAMPDIFF(SECOND, started_at, ended_at) - paused_duration_ms/1000)，
  对 ended_at 为空或为负的值按 0 处理；status 为字符串枚举（completed/cancelled/failed/paused/ready），ready 不计入活跃。
- 完成人次口径 = status = completed 的记录数。

**ExamService（exam）**
- exam_attempt 按 COALESCE(submit_at, created_at) 分桶，过滤 status in (2,3) and deleted = 0；
  参考人次 count(*)、通过人次 sum(case when pass_status = 1 then 1 else 0 end)、考试时长 sum(duration_sec)。
- exam_arrange 的考试总量/本期新增另用两条 count（deleted=0），exam_arrange_student 的覆盖人次用一条 count（deleted=0）。

**StaffManagement（sm）**
- sys_user 单表两条 count：status = 1 的为启用人数，总数为 totalUsers。
- 不涉及 Dubbo 调用，避免统计接口引入跨服务依赖。

### 2.3 参数校验与边界

- from / to 必填，格式 yyyy-MM-dd HH:mm:ss；from 必须早于 to，否则返回参数错误（03-接口文档.md 第 4 节）。
- granularity 取值 day / week / month，缺省 day。
- 跨度超过 stat.home.max-range-days 时按上限截断，响应 range.truncated 置 true（01-需求文档.md 第 5 节）。
- 分桶数超过 stat.home.series-max-buckets 直接返回参数错误，不静默截断。

## 3. 性能

### 3.1 现状数据量（2026-11-17 实测）

| kng_study_record | 0 |
| training_session | 38 |
| training_project | 2 |
| act_practice_attempt | 35 |
| exam_attempt | 10 |
| exam_arrange | 18 |

### 3.2 策略

1. **不建汇总表、不引缓存**（DER-05）：每域 1~3 条聚合 SQL，走索引即可；数据量级远超当前时再评估预聚合。
2. **补索引**：现有热表的时间列基本无索引（只有 user_id / 主键类索引），见 04-索引增补.sql。
3. **不发 N+1 查询**：所有分桶在一个 GROUP BY 里算完，桶的空缺（无数据的日期）由 Service 用区间补零，不再逐日查询。
4. **不做跨库 JOIN**：四域各查各表。

## 4. 前端实现

### 4.1 文件

| 文件 | 职责 |
|---|---|
| src/types/platformStat.ts | 接口返回类型（与 03-接口文档.md 第 2 节字段一一对应） |
| src/api/platformStat.ts | 五个请求封装，全部走 src/api/request.ts（front-end AGENTS 第 3 节铁律 1） |
| src/composables/usePlatformOverview.ts | 时间标签→绝对区间与粒度换算、并发请求、失败降级、响应序号丢弃 |
| src/views/admin/Home.vue | 只替换数据源：模板沿用现有结构，script 接 composable，style 不动 |

### 4.2 换算与并发

- 七个时间标签的换算与粒度选择全部在本文件完成（DER-01），后端只收 from / to / granularity。
- 五个请求并发发起；每个域单独 catch，失败域在结果里标记 failed，页面按 01-需求文档.md 第 4 节降级。
- 顶部合计指标（activeUsers、activeHours）只累加未失败域的数值，并在至少一个域失败时打降级标记。

### 4.3 展示口径

- 大数字继续用 --font-display 600 48px + tabular-nums；单位继续用 --font-outlier 小号（Hallmark Cobalt 口径）。
- 折线图用现有 SVG 换数据不行（点数动态），改用项目已有的 echarts（exam/arrange/components/AnalysisTab.vue、admin/AICombat/SpeechTraining/ProjectOverview.vue 已在用），
  颜色仍取 token 变量，不新增裸色值。
- 总学分卡片显示占位与「暂无数据源」提示；评论数行显示 0 并加提示（DER-02、DER-03）。

### 4.4 质量门

改完必须跑：node scripts/check-sfc.mjs src/views/admin/Home.vue（front-end AGENTS 第 7 节）；
npm run type-check；npm run test。

## 5. 一致性与失败处理

| 场景 | 行为 |
|---|---|
| 某域超时/500 | 该域卡片显示「—」，合计类指标跳过该域，页面其余正常 |
| 连续切换标签 | 前端比对请求序号，只接受最后一次的响应 |
| 后端区间超出上限 | 响应 range.truncated = true，前端在时间筛选旁提示「统计区间已截断」 |
| 空数据 | 所有数值返回 0，series 仍返回按区间的桶序列（值为 0），前端不得显示 NaN |
