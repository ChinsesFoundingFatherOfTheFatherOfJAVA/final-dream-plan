## 1. 背景与范围

### 1.1 现状

首页 front-end/src/views/admin/Home.vue 的「平台总览」区域目前是纯静态假数据（活跃人数 94、学习人数 37、启用人数 974、活跃时长 157.31h、学习时长 55.54h、总学分 198.3、课程总量 1358、项目总量 38、考试总量 1981 等），
六个时间筛选标签（上月/当月/上季度/当季度/上一年/当年/累计）只改 selectedTime 变量，不触发任何查询；两张折线图与三个环形/漏斗图都是固定 SVG。

### 1.2 本期目标

把该区域改为按真实数据查询：时间筛选切换后整块重新取数；六个指标卡、三块情况卡（课程/项目/考试）、两张趋势折线图全部由后端聚合结果驱动。
视觉层（Hallmark Cobalt token、记分牌大数字、切角面板、双系列配色）**保持现状不改**，只把写死的数字换成响应式数据。

### 1.3 不在本期范围

| 项 | 原因 |
|---|---|
| 总学分 | 库里只有「应得学分配置」（kng_courseware.study_score / exam_arrange.reward_credit），没有「用户获得学分」流水表，无法算准。本期卡片保留但显示占位并标注「暂无数据源」（DER-02）。 |
| 评论数 | 全库无评论表。本期恒为 0 并标注（DER-03）。 |
| 课程情况卡的「全部/内部/外部」切换 | 库里没有「内部/外部」来源维度。本期移除该切换控件（DER-04）。 |
| 日汇总表 / Redis 缓存 | 当前数据量极小（见 02-技术实现方案.md 第 3 节），实时聚合足够。量级上来再评估（DER-05）。 |
| 报表中心、平台运营等其他原平台页面 | 不在本次需求内。 |

## 2. 指标口径总表

**口径纪律**：一张表只有一个所有方；本表「所有方」列即该指标的计算位置，任何服务都不得直读他域表（依据 后端架构总纲 第 2 节、第 5 节）。

### 2.1 顶部指标卡（6 张）

| 卡片 | 指标键 | 所有方 | 数据源字段 | 算法 |
|---|---|---|---|---|
| 启用人数 | enabledUsers | StaffManagement | sys_user.status | 条件 status=1 的记录数（不含逻辑删除：sys_user 无 deleted 列） |
| 学习人数 | studiedUsers | OnlineClassroom | kng_study_record.user_id | 统计期内按 start_study_time 归属，distinct user_id |
| 活跃人数 | activeUsers | 四域合计 | 学习 ∪ 训练 ∪ 练习 ∪ 考试 | 各域本期活跃去重人数之和（跨域同一人重复计，TBD-01） |
| 学习时长(h) | studyHours | OnlineClassroom | kng_study_record.study_len_hours | 统计期内记录求和，保留 2 位小数 |
| 活跃时长(h) | activeHours | 四域合计 | 学习/训练/练习/考试时长 | 四域本期时长之和折算小时，保留 2 位小数 |
| 总学分 | totalCredits | —— | 无数据源 | 本期不实现，显示占位（DER-02） |

### 2.2 课程情况卡（OnlineClassroom）

| 行 | 指标键 | 数据源 | 算法 |
|---|---|---|---|
| 课程总量 | courseTotal | kng_course | 全量记录数（不限统计期） |
| 本期新增 | courseNew | kng_course.created_at | 落在统计期内的记录数 |
| 学习人次 | studyVisits | kng_study_record | 统计期内记录条数（按 start_study_time 归属） |
| 学习时长(h) | studyHours | kng_study_record.study_len_hours | 统计期内求和 |
| 完成人次 | finishedVisits | kng_study_record.study_status | 统计期内且 study_status=1 的记录数（口径见 03-接口文档.md 第 3.3 节） |
| 评论数 | commentCount | 无数据源 | 恒 0，前端标注（DER-03） |

### 2.3 项目情况卡（SpeechTraining）

| 行 | 指标键 | 数据源 | 算法 |
|---|---|---|---|
| 项目总量 | projectTotal | training_project | 全量记录数（不限统计期） |
| 本期新增 | projectNew | training_project.created_at | 落在统计期内的记录数 |
| 覆盖人次 | coveredUsers | project_student | distinct user_id（不限统计期，反映项目覆盖规模） |
| 学习人次 | studyVisits | training_session | 统计期内记录数（按 start_time 归属） |
| 完成人次 | finishedVisits | training_session.status | 统计期内且 status=1 的记录数 |
| 学习率 / 完成率 | studyRate / finishRate | —— | 学习率 = 学习人次 / 覆盖人次；完成率 = 完成人次 / 覆盖人次；覆盖人次为 0 时两者均为 0 |

### 2.4 考试情况卡（ExamService）

| 行 | 指标键 | 数据源 | 算法 |
|---|---|---|---|
| 考试总量 | examTotal | exam_arrange | 全量记录数，条件 deleted=0 |
| 本期新增 | examNew | exam_arrange.created_at | 统计期内且 deleted=0 的记录数 |
| 覆盖人次 | coveredUsers | exam_arrange_student | 记录数，条件 deleted=0 |
| 参考人次 | attemptVisits | exam_attempt | 统计期内且 status in (2,3)、deleted=0 的记录数（见 03-接口文档.md 第 3.3 节） |
| 通过人次 | passedVisits | exam_attempt | 上述条件再加 pass_status=1 |
| 考试通过率 | passRate | —— | 通过人次 / 参考人次；参考人次为 0 时为 0 |

### 2.5 两张趋势折线图

| 图 | 系列 | 数据源 | 算法 |
|---|---|---|---|
| 活跃人数/学习人数 | 活跃人数 | 四域合计 | 每个时间桶内各域 distinct 人数之和 |
| 活跃人数/学习人数 | 学习人数 | OnlineClassroom | 每桶内 distinct user_id |
| 活跃时长/学习时长(h) | 活跃时长 | 四域合计 | 每桶内时长合计折算小时 |
| 活跃时长/学习时长(h) | 学习时长 | OnlineClassroom | 每桶内 study_len_hours 求和 |

### 2.6 「活跃」的统一判定

一个用户在本期「活跃」，当且仅当他至少有一条本期业务记录：

| 域 | 判定记录 | 归属时间字段 |
|---|---|---|
| 在线课堂 | kng_study_record | start_study_time |
| 话术训练 | training_session | start_time |
| 实战训练场 | act_practice_attempt，status 不为 ready | started_at，为空时取 created_at |
| 测练中心 | exam_attempt，status in (2,3) | submit_at，为空时取 created_at |

## 3. 时间筛选

### 3.1 周期定义（自然周期，前端换算成绝对区间）

| 标签 | 换算 |
|---|---|
| 上月 | 上月 1 日 00:00:00 至 上月末日 23:59:59 |
| 当月（默认选中） | 本月 1 日 00:00:00 至 请求时刻 |
| 上季度 | 上一自然季度首日 00:00:00 至 该季度末日 23:59:59 |
| 当季度 | 本季度首日 00:00:00 至 请求时刻 |
| 上一年 | 上一年 1 月 1 日 00:00:00 至 12 月 31 日 23:59:59 |
| 当年 | 本年 1 月 1 日 00:00:00 至 请求时刻 |
| 累计 | 2000-01-01 00:00:00 至 请求时刻 |

前端负责把标签换算成 from / to 两个绝对时间戳（DER-01：后端不认「当月」这类语义标签，避免前后端各算一套口径）。

### 3.2 折线粒度

| 区间跨度 | granularity | 说明 |
|---|---|---|
| ≤ 62 天 | day | 每天一个点，标签 MM-DD |
| 63 ~ 400 天 | week | 自然周（周一为起点），标签 MM-DD |
| > 400 天 | month | 自然月，标签 YYYY-MM |

粒度由前端按 3.1 算出的跨度选定并通过参数传给后端；后端只按传入粒度分桶，不得自行改写（DER-01）。

## 4. 交互与降级

1. 切换时间标签 → 并发请求四域统计接口，期间卡片显示加载态（不整页 loading）。
2. 任一域失败 → 仅该域负责的卡片显示「—」，其余正常展示；顶部合计类指标（活跃人数、活跃时长）跳过失败域并在卡片右上角显示降级提示。
3. 连续切换时间标签时，后发请求覆盖先发请求的结果（前端用请求序号丢弃过期响应）。
4. 页面首次进入按「当月」取数。

## 5. 配置项

| 配置键 | 默认值 | 归属 | 说明 |
|---|---|---|---|
| stat.home.max-range-days | 730 | 四域各服务 | 允许查询的最大区间天数（累计口径 2000 年至今会超过，超限时按 730 天截断并在响应 range.truncated 置 true） |
| stat.home.series-max-buckets | 400 | 四域各服务 | 单次返回的最大分桶数，超出则响应 400 参数错误 |
| stat.home.comment-count-enabled | false | OnlineClassroom | 评论数开关，false 时 commentCount 恒 0 |

## 6. 决策与待定

| 编号 | 内容 | 结论 |
|---|---|---|
| DER-01 | 时间粒度与周期换算放前端还是后端 | 放前端：标签→绝对区间、跨度→粒度都在前端算，后端只接受 from/to/granularity |
| DER-02 | 总学分 | 本期不做（无获得学分流水表），卡片显示占位 |
| DER-03 | 评论数 | 无数据表，恒 0 并标注，配置键见 第 5 节 |
| DER-04 | 课程情况卡「全部/内部/外部」 | 无来源维度，本期移除该切换 |
| DER-05 | 是否引入日汇总表与 Redis | 不引入，本期实时聚合 + 索引 |
| DER-06 | 端点落点 | 各域自建统计端点，前端并发聚合（用户 2026-11-17 拍板方案 A） |
| DER-07 | week 分桶的桶键与标签 | 桶键=该周周一 `yyyy-MM-dd`，出参标签 `MM-DD`；废弃 `%x-%v` 写法 |
| DER-08 | 区间超上限时截断哪一端 | 保留**近端**：`from = to - max-range-days`，`to` 原样回显；首页看的是近期规模，砍头会让看板变成旧年空白 |
| DER-09 | 截断与分桶数校验的顺序 | 先截断再校验桶数；截断后仍超上限直接返回 40004，**不做自动上卷**（后端不擅自改前端选的粒度） |
| DER-10 | 统计端点错误码与既有域冲突 | 40001~40004 视为统计端点专用码段；测练中心既有 40002/40003/40004 含义不同，前端按域区分文案，不做全局复用 |
| DER-11 | 各域 card 中 `coveredUsers` 语义 | 在线课堂/考试域为**人次**（记录数），话术训练域为**人数**（distinct user_id）；同名不同义，前端合计或文案不得混用 |
| DER-12 | 学习率/完成率是否封顶 | 不封顶，保留 4 位小数；分子是区间内会话数、分母是全量覆盖人数，比率可能 > 1，属口径事实而非缺陷 |
| DER-14 | 完课率/学习率等派生指标由谁算 | 比率类一律前端派生（分子分母接口都给），接口不返回比率字段；例外：`passRate`、`studyRate`、`finishRate` 已由各域后端给出，前端直接展示 |
| DER-13 | 测练中心活跃人数用 exam_attempt 的哪个身份字段 | 用 `user_id`（跨场次稳定）；`student_id` 是 exam_arrange_student 行主键，重考换行会把同一人重复计数 |
| TBD-01 | 活跃人数跨域严格去重 | 未定；当前为各域相加口径，若要严格去重需各域额外返回 userId 集合 |
| TBD-02 | 话术训练域 user_id 为账号（account）而其余域为用户主键 | 未定；当前各域独立计数不受影响，严格去重时必须先经 OrgQueryService 折算 |

## 7. 验收标准

1. 后端：四域统计接口在统计期内返回 02-技术实现方案.md 第 2 节列出的全部字段，且数值可由 04-索引增补.sql 生效后的明细 SQL 复核一致。
2. 前端：切换七个时间标签，卡片与折线图数据随之变化；任一域断网时其余卡片不受影响。
3. 性能：四域接口在 1 万条 session / 1 万条 attempt 量级下，单次请求 P95 ≤ 300ms（本地库实测值记录在施工记录）。
4. 视觉：Home.vue 的样式段零改动（除新增降级提示与占位标注所需的最小类），Hallmark token 不新增裸色值。
5. 质量门：npm run test 全绿；npm run type-check 通过；改过的 .vue 通过 scripts/check-sfc.mjs。
