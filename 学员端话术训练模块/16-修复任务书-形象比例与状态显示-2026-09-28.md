## FIX-4 雷达图 tooltip 显示原始模板变量（纯前端）

**现象**：所有雷达图（学员练习报告 / 管理端学员详情 / 项目总览"学习雷达"）悬浮显示 `{n_normal|话术一致性} {v_normal|100分}` 这类原始文本。

**根因**：`src/views/student/AICombat/RadarChart.vue`（全站唯一雷达组件，三处复用）L80 `tooltip: {}` 空配置 → ECharts 默认 tooltip 直接回显轴名；而轴名 formatter（L91-108）返回带 rich 标记 `{n_normal|...}` 的字符串，rich 样式定义在 `radar.axisName.rich` 作用域内，**tooltip 不解析这些自定义标记**，原样输出。

**修复**（RadarChart.vue，一处改动三处生效）：
给 tooltip 配显式 formatter 回调，返回纯文本：

```ts
tooltip: {
  formatter: (params) => {
    // params.value 与 indicators 按序对应
    const items = Array.isArray(params.value) ? params.value : []
    return indicators
      .map((ind, i) => `${ind.name}: ${items[i] != null ? items[i] : '-'}分`)
      .join('<br/>')
  }
}
```

（具体以组件内 indicators 变量名为准；也可做成"维度名 + 分值"逐行列表，样式自定，关键是**不再让默认 tooltip 回显轴名 rich 字符串**。）

**验收**：
- Given 任一雷达图 When 鼠标悬浮 Then tooltip 显示"话术一致性: 100分"等可读文本，无 `{n_`/`{v_` 字样
- Given 某维度无分值 When 悬浮 Then 该行显示 `-`，不显示 undefined/null

## FIX-5 学员训练详情"已完成"误判为"未完成"（后端 1 行 SQL + 单测）

**现象**：`/#/sparring/newmanage/console/21/studentdetail?userId=admin`，admin 总分 90、报告数 1、项目完成标准 1 次，页面显示"未完成"；而项目总览完成率却显示 100%（两处自相矛盾）。

**根因**（已实测定位）：`ProjectStatisticsService.reportsForUsers`（L651-663）的 SELECT 只查了 `r.id, r.user_id, r.total_score, r.created_at`，**漏查 `r.status`**。RowMapper 映射出的 `TrainingReport.status = null`，而 `PassStrategyService.isCompleted`（L36-39）里 `Objects.equals(report.getStatus(), 2)` 会把**所有报告过滤掉** → `generated` 恒为空：
- 日常训练分支：`0 >= completionStandard` 恒 false → 永远"未完成"（有报告时）；
- 考核分支：`generated.isEmpty()` 恒 true → 直接 return false。

项目总览/学员列表走 `studentRowsSql` 的 SQL 内 finish_status 计算（L465-468，正确），所以总览正常——只有走 `buildTops`（学员详情页）的路径全军覆没。

**修复**（`after-end/SpeechTraining/src/main/java/jack/digityhuman/speechtraining/service/ProjectStatisticsService.java`）：
1. `reportsForUsers` 的 SELECT 列表补 `r.status`，RowMapper 补 `report.setStatus(rs.getInt("status"))`；
2. **补单测**（防回归）：构造 status=2 的报告列表 → `isCompleted` 返回 true；构造 status=1 的 → false；`reportsForUsers` SQL 层面验证映射后 status 有值（Mockito+jdbcTemplate 不好测 SQL 时，至少给 `PassStrategyService` 补"status=null 的报告应视为未生成"的语义单测并注明该语义依赖 SELECT 包含 status 列）。

**顺带检查**（同一张网捞的鱼）：`reportsForUsers` 的返回还被 `buildTops` 的 reportCount/highestScore 使用，这两个用的是原始列表不受影响；但请全局搜一遍 `reportsForUsers` 的其他调用方，确认没有别处也依赖 status 字段。

**验收**：
- Given 项目 21（日常训练、完成标准 1、admin 有 1 份 status=2 报告）When 打开学员详情 Then 完成状态显示"已完成"
- Given 考核类项目（单次达标策略）学员达标 1 次 When 查看详情 Then 显示"已完成"
- Given 学员无报告 When 查看详情 Then 显示"未开始"（原逻辑保持）
- Given `mvn -o -q test` When 解析 surefire-reports Then 全绿、无回归
