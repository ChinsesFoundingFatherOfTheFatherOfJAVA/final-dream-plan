## #2 AI 生成陪练者形象超时（Dify 模型性能差）—— 读超时放宽到 5 分钟

### 根因（两段链路都要放）
1. **后端**：`DifyWorkflowSupport.runWorkflow` 用的是全局共享 `RestTemplate`
   （`RestTemplateConfig:19` 读超时 **120s** 硬编码），`avatar-gen` 工作流跑得慢直接超时；
   该 RestTemplate 同时服务 `report-scoring`（120s 是按报告智能体调的），**不能全局改**。
2. **前端**：`api/ai.ts:17` `generateAvatar` 的 axios `timeout: 60000`——就算后端放开，前端 60s 先断。

### 修复规格
1. **后端 per-agent 读超时**：`DifyProperties.AgentConfig` 增加可配字段 `readTimeoutMs`（默认 120_000）；
   `DifyWorkflowSupport.runWorkflow` 不再用注入的共享 RestTemplate 直调，改为按 config 的超时构造请求工厂
   （可缓存 `Map<Integer/Long, RestTemplate>` 避免每次 new，或每 agent 一个实例，实现自选但要有注释）。
2. `application.properties` 增加：
   `dify.agents.avatar-gen.read-timeout-ms=300000`（纯 ASCII，注释英文）。
   **report-scoring 不配此键**，保持默认 120s。
3. **前端**：`api/ai.ts` `generateAvatar` 的 `timeout` 60000 → **300000**。
4. 顺带检查：该接口为 loading 长请求，确认按钮 loading 态能持续 5 分钟不被其他逻辑重置（AvatarGenField 的 loading 处理）。

### 验收
- Given Dify avatar-gen 工作流耗时 200s When 前端点 AI生成 Then 后端不超时、前端不超时，生成正常返回并预览。
- Given report-scoring 正常调用 When 生成报告 Then 行为不变（仍 120s 预算）。
- 后端 `mvn -o test` 全绿（若 DifyWorkflowSupport 有既有测试需同步适配构造变化）。

## #3 语音维度未参与评分时，总分仍 100 而非 90 —— 口径变更：未参与维度照占权重

> **后续更正（E-06，2026-10-21）**：本任务书记录的是 2026-09-24 的短期口径，已被后续代码修正取代。
> 2026-10-21 E-06 改为未参与维度不进分子分母。2026-10-26 用户裁定：`speech_speed` 无语音轮记 0 分并占权重，雷达图必须画出；E-06 只保留给其它 `score=null` 维度。本文件仍是历史任务证据，不以这里的验收句为准。

### ⚠️ 这是产品口径变更，不是普通 bug 修复
当前代码行为（`ReportGenerationService:210-220`）是 2026-09-23 轮的**有意设计**（09 台账 #11）：
未参与维度 `score=null` 时 `continue`，既不进分子也不进分母，总分 = Σ(参与维度分×权重)/Σ参与维度权重
——所以"语速适中"未生效时其余维度全 100 → 总分 100。
用户 2026-09-24 实测后确认期望相反：**未参与的维度权重照占、按 0 分计入总分**（其余全 100、语速 10% → 总分 90）。
背景：v1.2 双输入后，语音对话项目的学员可以全程打字躲掉语音考核，旧口径等于"躲掉考核零代价"，
新口径让"该用语音而没用"承担权重代价。

### 修复规格
1. `ReportGenerationService` 总分计算（`:210-236`）：`score == null` 的维度**不再 `continue` 跳过分母**，
   其权重照常累入 `weightSum`，只不进 `weightedSum` 分子（等价于按 0 分计）。
2. `weightSum == 0` 的退化分支（全部维度无权重 → 简单平均）语义不变；
   `scored.isEmpty()` 抛错的兜底也不变（全部维度都无分仍按报告失败处理，不出现 0 分假报告）。
3. **明细文案同步**：未参与维度在 `training_report_dimension` 的 comment 仍写"未参与本次评分及原因"，
   但要补一句让学员看得懂分数为什么被拉低，建议文案：
   「本次没有可用于评分的语音作答，该维度以语音表现为评分依据，未参与本次评分（权重已计入总分）」。
4. 雷达图/评分明细前端**不改**：`score=null` 维度仍按"未参与"展示（不画 0 分尖刺的决策不变），
   变的只是总分数学。

### 验收
- Given 语音对话项目、7 维度权重 40/10/10/10/10/10/10、学员全程文字作答、其余 6 维度均 100 分
  When 生成报告 Then 总分 = 90.0，"语速适中"维度 score=null 且 comment 含权重说明。
- Given 同项目学员用语音作答 When 生成报告 Then 语速维度正常定分、总分口径与旧版一致（回归）。
- Given 纯文字项目（dialogueMode=1）且启用了语音维度 When 生成报告 Then 同样按权重计入（口径统一，不区分项目类型——文字项目本就该把语音维度权重留空或禁用，属管理员配置责任）。
- 单测：补/改 `ReportGenerationService` 相关测试（缺维度、全无分、权重归一）断言新口径。

## #4 陪练者本地上传的形象图被存成了项目封面 —— 表单文件字段串位

### 根因（两处叠加，都在后端）
前端提交（`EditProject.vue:655-666`）：本地替换的形象图以 **`avatarImage` 文件字段**上送、
封面以 **`coverImage` 文件字段**上送，字段名是分明的。问题在后端：

1. **`ProjectFormParser.extractFile`（`common/ProjectFormParser.java:42-52`）**：
   优先名单是 `{coverImage, cover, file, image}`，**不含 `avatarImage`**；用户只传形象图没传封面时，
   落进兜底分支"取**任意**非空文件当封面"→ 形象图被当成封面存进 `/coverImage` 目录。
2. **`AdminProjectController.createWithCover/updateWithCover`**：只调了
   `extractFile → saveCoverImage → req.setCoverImage`，**从未处理 `avatarImage` 文件字段**——
   即本地替换的形象图从来没有落盘逻辑，`virtualTrainer.avatarImage` 提交的是空串（blob: 前缀被置空）。
   （`FileStorageService.saveAvatarImage(byte[])` 是给 Dify 生成图用的字节版，没有 MultipartFile 版。）

### 修复规格
1. **删掉 `extractFile` 的"任意非空文件"兜底**（这是串位的直接根因）：只认 `coverImage`/`cover`（`file`/`image`
   这两个泛化名也不该再收——本表单的文件字段只有封面与形象两个，都有专名）。
   没有封面文件就返回 null，**不许**拿别的文件顶上。
2. **补形象图文件处理**：Controller 两个 multipart 入口增加：
   `MultipartFile avatarFile = request.getFile("avatarImage")`，非空时调
   `FileStorageService` **新增的 `saveAvatarImage(MultipartFile)` 重载**（仿 `saveCoverImage` 写法，
   落 `/avatar` 目录、返回 `/avatar/{uuid32}.{ext}`），并把它写进
   `req.getVirtualTrainer().setAvatarImage(...)`（注意 `virtualTrainer` 可能为 null，需判空；
   优先级：本地文件 > JSON 里的既有 URL）。
3. 更新链路的保留语义核对：`updateProject` 里 virtualTrainer 是**删表重建**，重建行的 avatarImage
   会取 req 值——确保上述赋值发生在 parse 之后、service 调用之前即可。
4. 前端不动（字段名本来就正确）。

### 验收
- Given 只给陪练者形象上传本地图片、封面上传留空 When 保存项目 Then
  项目 `cover_image` 为占位/空（**不是**形象图），`virtual_trainer.avatar_image` 为 `/avatar/xxx.png`，
  学员端训练页左栏显示该图、列表页封面不为该图。
- Given 只上传封面 When 保存 Then 封面正常、形象不受影响。
- Given 两者都传 When 保存 Then 各自正确落库互不串扰。
- Given 都不传 When 保存 Then 封面用占位、形象为空走前端默认图（现状行为回归）。
- Given AI 生成形象（非本地上传）When 保存 Then 走 URL 提交路径，行为与改造前一致（回归）。
