# 12 默认评分维度呈现升级（管理端，FP-31；交 code agent）

> 来源：2026-09-24 用户反馈——原平台默认评分维度的呈现形式是**分档锚点式**（每个维度给 100/80/60/40/0
> 五档具体描述 + 权重，见用户截图），我方默认维度的规则只是一行短句（"分级评分(0/40/60/80/100)"、"按照要点表达即可"），过于简陋。
> **本任务是"呈现形式与文案"的同步，不动 v1.3 的评分架构**（evidence_type / metric_config / 声学注入 / 定分标注机制全部原样）。

---

## 1. 决策口径（已定，勿自行裁量）

| 决策点 | 结论 | 理由 |
|--------|------|------|
| 同步什么 | **规则的文案与呈现形式**：默认维度改用分档锚点式五档描述 | 用户诉求即"呈现形式同步" |
| **不同步**维度集合 | 维持我方 7 个默认维度，**不**改成原平台的 4 个 | 我方 7 维度含语速（evidence=2）与违禁词（后端定分），是 v1.3 已交付能力，砍掉是倒退 |
| **不同步**权重 | 维持 40/10/10/10/10/10/10，不采用原平台的 70/5/5/20 | 原平台 4 维度把 70% 压在话术一致性；我方多出的语音/违禁词维度需要权重。权重本就可在管理端随时改，默认值跟随我方架构 |
| 共有维度的文案 | 话术一致性/表达流利/态度积极/表述清晰四个维度**逐字采用**原平台文案（截图已给全文，见 §3） | 复刻原则：原文案是验收基准 |
| 我方特有维度文案 | 语速适中/礼貌用语/违禁词按同风格补写（§3 已给出终稿） | 原平台没有这三个维度 |

## 2. 改动范围

### 2.1 默认维度文案（前端 `EditProject.vue:443-449` 的 `dimensions` 默认数组）

把 7 个默认维度的 `scoringRule` 换成 §3 的分档锚点文案（多行文本，`\n` 分隔每档）。
`maxlength="200"` 的限制同步放开到 **1000**（见 2.2）。

### 2.2 规则的编辑与展示（管理端评分维度区块）

- **展示态**（默认维度、非编辑中）：`<span>{{ dim.scoringRule }}</span>` 改为按行渲染——
  每行一个 `<div class="rule-line">`（换行符 split），档位行（以"100分：""80分："等开头的行）
  档位词加粗/主题色，其余常规灰字；字号按工程标准（正文 14px、辅助 12-13px）。
- **编辑态**（自定义维度及默认维度的规则可编辑处）：单行 `<input maxlength="200">` 改为
  `<textarea rows="6" maxlength="1000">`，placeholder 提示格式：
  `100分：…\n80分：…\n60分：…\n40分：…\n0分：…`（不强制，自由文本仍合法）。
- 既有交互不变：ruleType 下拉、依据/指标双下拉（v1.3）、启停开关、权重输入照旧。

### 2.3 存储与下游链路（零改动，验收时确认即可）

- `scoring_dimension.scoring_rule` 已是 **TEXT** 列（schema.sql:72），存 1000 字无压力，**无 DDL**。
- 该文案原样进入 Dify 的 `rule` 字段（`toDimensionsJson`）——分档锚点本身就是 04 提示词
  "评分分级锚点"一节的素材，**AI 评分会自然变准**，这是本次升级的隐藏收益。
- "后端已判定"与"语音表现参考"两段标注仍**追加在 rule 尾部**（机制不变，确认追加顺序不被多行文本破坏）。
- `training_report_dimension` 的 comment 等不涉及。

### 2.4 明确不做

- 不做富文本编辑器/Markdown 渲染——纯文本+按行渲染足够；
- 不改报告页（学员端）任何展示——报告展示的是评语不是规则原文；
- 不为"档位解析"写结构化字段（如 level/JSON 数组）——文本即真相，解析留给渲染层 split。

## 3. 七个默认维度的规则文案（终稿）

> 前四个为原平台原文（截图逐字）；后三个为我方按同风格补写。落库文本用 `\n` 连接各行。

**① 话术一致性（权重 40，keypoints，evidence=1）**
```
按照标准话术的要点表达即可。
无需与标准话术完全一致，仅需表达出对应的要点即可。按照要点命中比例得分。
```

**② 表达流利（权重 10，grade，evidence=3——建议随本次从 1 升为 3，配合声学注入）**
```
100分：表达如行云流水，几乎未出现口头禅。
80分：表述整体流畅，有极少量卡顿或口头禅，但不影响沟通节奏和理解。
60分：表述存在少量卡顿或重复，口头禅出现频率稍高，但能完成基本沟通。
40分：表达不连贯，卡顿和重复较多，频繁使用口头禅，显得紧张或准备不足，影响沟通效率。
0分：表述非常困难，长时间停顿，句子破碎，几乎无法顺畅传递信息，沟通难以进行。
```
> ⚠️ evidenceType 1→3 的调整涉及"有语音轮时 rule 会追加声学摘要"（08 §4），属正向增强；若希望本期零行为变化，可保持 1，由用户在管理端自行切换。**默认建议升 3**（文案里的"卡顿/停顿"本来就需要语音数据佐证）。

**③ 态度积极（权重 10，grade，evidence=1）**
```
100分：全程保持高度热情和耐心，能主动挖掘需求，积极提供解决方案。面对抱怨或拒绝时，能保持积极心态并有效引导。
80分：态度友好、有耐心，能积极响应需求。但在面对极端挑战时，积极性或耐心可能略有下降。
60分：态度中立、平和，能完成问答，但缺乏主动意识，多为被动响应，热情不足。
40分：态度略显消极或不耐烦，对问题反应被动，甚至出现辩解或推诿的倾向。
0分：态度消极、冷漠，甚至带有抵触情绪。
```
> 注：原截图 40 分档"辩解或推的倾向"应为"推诿"缺字，落库文本已补全。

**④ 表述清晰（权重 10，grade，evidence=1）**
```
100分：表述逻辑性极强，善用结构词（如"首先、其次"），重点突出，用词精准，毫无歧义。
80分：表述基本清晰，逻辑通顺，但偶尔信息组织不够完美，重点不够突出。
60分：能表达清楚基本意思，但逻辑性稍弱，有时会绕圈子或信息点混乱，需要费力理解。
40分：表述混乱，逻辑不清，前后矛盾，或使用过多专业术语，导致较难理解。
0分：表述完全无法理解，语言混乱。
```

**⑤ 礼貌用语（权重 10，grade，evidence=1；我方补写）**
```
100分：用词得体周到，敬语与礼貌表达贯穿全程（如"您好""请""感谢"），语气令人舒适。
80分：整体礼貌规范，偶有直白表述但不失分寸。
60分：基本使用文明用语，但礼貌表达时有时无，个别语句生硬。
40分：多处用语生硬直白，缺少基本敬语，给人冷淡感。
0分：出现不礼貌甚至冒犯性表达。
```

**⑥ 语速适中（权重 10，formula，evidence=2，metric=speech_speed；我方补写，后端定分）**
```
以学员录音的净发声时长折算语速（字/分钟）：150-250字/分钟为满分，每偏离区间10字/分钟扣5分，扣完为止。该维度由系统按录音自动计算。
参考分档——100分：语速处于150-250字/分钟的理想区间；80分：偏离区间约40字/分钟以内；60分：偏离约80字/分钟以内；40分：偏离约120字/分钟以内；更低：语速明显过快或过慢，已影响信息接收。
```
> 分档数字与后端公式（100 − ⌊偏离/10⌋×5）严格对齐：偏离 0/40/80/120 对应 100/80/60/40。

**⑦ 违禁词（权重 10，deduction，evidence=1，metric=forbidden_words；我方补写，后端定分）**
```
命中项目配置的违禁词即扣分，每次命中扣20分，扣完为止；未命中任何违禁词得100分。该维度由系统按识别文本自动判定。
```

## 4. 验收标准

- Given 新建项目 When 打开评分维度区块 Then 7 个默认维度按分档锚点式呈现（档位词突出、逐行显示），权重 40/10/10/10/10/10/10，依据/指标列与 v1.3 一致；
- Given 编辑自定义维度规则 When 输入多行文本（≤1000 字）Then 保存后回显按行渲染，不截断；
- Given 含"表达流利"(evidence=3) 的语音项目 When 生成报告 Then rule 尾部追加"语音表现参考"标注、Dify 评语风格与分档锚点一致（人工抽查）；
- Given 项目编辑回显 When 重新打开 Then 多行规则完整回显（ TEXT 列 + textarea 双向无损）；
- Given 只改默认文案未改机制 When 回归 Then 04 智能体输出 JSON 契约、总分计算、定分维度行为全部与 11 号任务书修复后基线一致。
- 验证闸口：前端 `npx vue-tsc --noEmit` + `npm test` + `npx vite build`；后端无改动（本轮纯前端 + 文案）。
