# 学员端 AI对练-话术训练 复刻接口文档

**版本**: v1.2（第 5 节：ASR 供应商换豆包、学员端双输入；2026-09-21。v1.1 为 2026-09-15 新增语音对话与陪练者形象接口）
**2026-09-23 修订**：新增 `404 接口不存在` 错误码；5.2 补记 `noSpeech` 与"识别超时"的实测分界；`score` 可为 `null`（维度未参与评分）与其固定文案口径。
**Base URL**: `http://localhost:8080/api`（前端经网关访问 SpeechTraining 服务）
**认证**: JWT Bearer（StaffManagement 统一签发）；开发环境可通过 `SPEECH_AUTH_DEV_FALLBACK_ENABLED=true` 使用 mock 学员 `mock_student_001`，生产必须关闭 fallback。
**统一响应结构**:

```json
{ "code": 0, "message": "success", "data": { } }
```

**错误码**:

| 错误码 | 说明 |
|--------|------|
| 0 | 成功 |
| 1 | 业务异常（message 为提示语） |
| 404 | 接口不存在（`message` 为 `接口不存在: {path}`）——URL 写错/版本不匹配时报这个，不再混进 500 |
| 500 | 服务器内部错误 |

> HTTP 状态一律 200（含 404/500）：判错只看信封里的 `code`，这是全站既有约定，本轮未改。

**通用约定**：
- 时间字段格式 `yyyy-MM-dd HH:mm:ss`（沿用现有 FlexibleLocalDateTimeDeserializer）
- 分页请求参数 `page`（默认 1）、`pageSize`（默认 20）
- 下述所有接口均挂 FP 编号，与需求文档对应
- **消息对象通用字段（v1.1 扩展）**：第 1/2/3 节中所有 message 对象（含 nextTrainerMessage）在 v1.1 起附带 `audioUrl`（string|null，学员录音 URL，仅 inputMode=2 且为学员消息时有值）、`audioDurationMs`（int|null）、`inputMode`（int，1=文字 2=语音，陪练者消息固定 1）；v1.0 示例中未列出，实现时按此补齐

## 1. 学员项目模块（FP-01~04, FP-18）

### 1.1 FP-01/02/03/04 获取学员端项目列表

- **Method / Path**：`GET /student/projects`
- **说明**：分页查询已发布且对学员可见的训练项目，含卡片与状态数据。

**Query 参数**:

| 参数 | 位置 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| page | query | int | 否 | 页码，默认 1 |
| pageSize | query | int | 否 | 每页数量，默认 20 |
| status | query | string | 否 | 项目状态筛选：`not_started`未开始 / `ongoing`进行中（默认）/ `expired`已过期 / `finished`已结束 |
| projectType | query | int | 否 | 类型筛选：0=训练（日常训练）/ 1=考核（通关考试） |
| keyword | query | string | 否 | 项目名称模糊搜索 |

（无分类参数——分类筛选不做）

**响应示例**:

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "records": [
      {
        "projectId": 1306255935862583317,
        "name": "复刻",
        "projectType": 0,
        "coverImage": "https://example.com/cover.jpg",
        "startTime": "2026-09-13 00:00:00",
        "endTime": "2029-09-29 00:00:00",
        "status": "ongoing",
        "completed": true
      }
    ],
    "total": 1,
    "page": 1,
    "pageSize": 20
  }
}
```

**字段说明**:

| 字段 | 类型 | 说明 |
|------|------|------|
| projectType | int | 0=训练（卡片左上蓝色"训练"徽标）/ 1=考核（橙色"考"徽标） |
| status | string | not_started / ongoing / expired / finished（口径见 1.1.1） |
| completed | boolean | 学员是否达标：日常训练=已练次数≥完成标准；考核=按项目 `passStrategy` 判定（单次/累计 N/连续 N）。true 时卡片显示绿色"已完成"徽标 |

**1.1.1 状态口径**（后端实现于 `StudentProjectService.calcStatus`）:

| status | 判定 |
|--------|------|
| not_started | now < startTime |
| ongoing | startTime ≤ now ≤ endTime 且学员未达标 |
| expired | now > endTime 且学员未达标 |
| finished | 学员已达标（与 completed 同源） |

### 2.3 FP-12/20 发送消息（流转判定，核心）

- **Method / Path**：`POST /student/sessions/{sessionId}/messages`
- **说明**：后端调 Dify 话术评分器判定要点命中 → 流转条件复核 → 权重路由。（语音模式项目走 5.2 录音接口，判定逻辑相同；本接口用于文字模式与语音模式的键盘回退输入）

**请求参数**:

| 参数 | 位置 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| content | body | string | 是 | 学员输入文本，1~2000 字 |

**请求示例**:

```json
{ "content": "还没吃饭呢，正准备去吃饭" }
```

**响应示例（未通过 → 撤回+要点提示）**:

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "withdrawn": true,
    "keyPoints": ["吃饭"],
    "passed": false,
    "finished": false,
    "finishedRounds": 0,
    "totalRounds": 1,
    "nextTrainerMessage": null
  }
}
```

**响应示例（通过 → 陪练者继续提问）**:

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "withdrawn": false,
    "keyPoints": ["吃饭"],
    "passed": true,
    "finished": false,
    "finishedRounds": 1,
    "totalRounds": 2,
    "nextTrainerMessage": {
      "messageId": 4,
      "seq": 2,
      "role": 1,
      "content": "那咱们聊聊产品吧",
      "passed": null,
      "withdrawn": 0,
      "likeCount": 0
    }
  }
}
```

**响应示例（通过 → 流程结束）**:

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "withdrawn": false,
    "keyPoints": ["吃饭"],
    "passed": true,
    "finished": true,
    "finishedRounds": 1,
    "totalRounds": 1,
    "nextTrainerMessage": null
  }
}
```

**字段说明**:

| 字段 | 类型 | 说明 |
|------|------|------|
| withdrawn | boolean | true 时前端撤回气泡并弹要点提示弹窗（语音接口里 `noSpeech=true` 时改为提示重说，不弹窗） |
| noSpeech | boolean | 仅语音接口可能为 true：录音没被识别出任何内容（"没听到"），此时 `keyPoints` 必为空，前端提示"刚才没有听到你的声音，请再说一遍"而不是弹要点。文字接口恒 false |
| keyPoints | string[] | 当前学员节点要点列表（弹窗内按 `1、` `2、` 编号展示） |
| finished | boolean | true 时前端跳转 `#/standpracticereport?sessionId=xxx` |

**错误码**：
- `1 会话不存在`
- `1 会话已结束，不能继续发送`
- `1 请输入内容`（content 为空）
- `1 消息长度不能超过2000字`
- `1 本条回答已过期，请重新发送`（v1.2 并发保护：判定期间该会话已被另一次提交推进，前端按普通失败提示，不撤回已生效的消息）
- `1 流程拓扑异常：当前节点没有出边，无法流转` / `1 流程拓扑异常：下游节点不存在` / `1 流程拓扑异常：下游节点类型不合法`

## 5. 语音与形象模块（v1.1 新增，FP-24~28；v1.2 调整）

> **v1.2 变更**：① 学员端**双输入**——录音作答不再限 `dialogueMode`，文字对话项目也能录音；
> ② ASR **供应商由阿里云百炼 Paraformer 换成豆包（火山引擎 SAUC v3）**；
> ③ TTS 播报仍限语音对话项目（未放开）。

### 5.1 FP-24/28 陪练者消息 TTS 合成

- **Method / Path**：`POST /student/sessions/{sessionId}/tts`
- **说明**：为一条陪练者消息合成语音；语音模式（dialogueMode=0）下前端收到陪练者消息后调用。按该会话项目的 virtual_trainer 配置（语言/声音/语速）合成，相同"文本+声音+语速"命中缓存直接返回。

**请求参数**:

| 参数 | 位置 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| messageId | body | long | 是 | 陪练者消息 ID（用于取文本） |

**请求示例**:

```json
{ "messageId": 4 }
```

**响应示例**:

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "messageId": 4,
    "audioUrl": "/audio/tts/a3f8...c9.mp3",
    "durationMs": 3200,
    "cached": true
  }
}
```

- `audioUrl` 返回**相对路径**，前端经 `resolveAssetUrl()` 拼成 `http://localhost:8080/api/audio/tts/...`（后端同时注册了 `{prefix}/**` 与 `/api{prefix}/**` 两套静态映射，直连 8081 或走网关 8080 都取得到）。
- **口型视频 `videoUrl` 为预留字段，本期未实施**：当前 `TtsResp` 不返回该字段，也不存在 `trainer_video_asset` 表或 LipSync 服务。FP-29 已立项，待 GPU/部署和 PoC 验收后按 08 专项方案接入；当前前端按"音频+静态形象图"展示。
- `durationMs` **不是**按固定码率折算：百炼请求 256kbps、实测落盘是 128kbps/22050Hz，按常量折算会把时长算成真实值的一半。
  现由 `Mp3Duration` 跳过 ID3v2 后**逐帧读帧头**码率/采样率累加得出；解析不出有效帧返回 0（宁缺勿错，不给看着合理却差一倍的估算值）。
- 引擎为阿里云百炼 CosyVoice，`speech.tts.model` 必须与音色后缀同代（见 02-技术实现方案 §7）。

**错误码**：`1 会话不存在` / `1 消息不存在或不属于该会话` / `1 该项目为文字对话模式，无需合成` / `1 语音合成失败，请重试`

### 5.2 FP-24/28 学员语音消息（录音上传 + ASR + 流转判定）

- **Method / Path**：`POST /student/sessions/{sessionId}/voice-messages`
- **说明**：上传学员录音 → 后端调 **豆包 SAUC ASR** 转文字 → 走与 2.3 完全相同的流转判定（要点命中/撤回/权重路由/结束）。
  **v1.2 修正短路规则**：只有"识别不出任何内容"（trim 后为空）才不调 Dify，返回 `noSpeech=true`；单字等短回答照常送 Dify 判定。
  **[2026-09-23 实测口径]** 纯静音通常**走不到** `noSpeech`：豆包对无内容音频不回终结包，接口按 `1 语音识别超时，请重试` 失败
  （等待上限 10s，见 02 §6.5）。`noSpeech` 实际只在"服务端回了结果但文本为空"时出现，两条提示不可互相替代。
  **v1.2 起不再校验 `dialogueMode`**：语音对话与文字对话项目的学员都可录音作答。
  ASR 分句时间戳汇总出的每轮声学特征另落 `training_round_acoustic`（不进本接口响应，见 02 §4.5）。

**请求**：`multipart/form-data`

| 参数 | 位置 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| audio | form-data | file | 是 | WAV（16bit 单声道 PCM），时长 ≤ 60s；采样率以文件头为准，后端不假定 16k |

**响应示例（未通过 → 撤回+要点提示）**:

```json
    "keyPoints": ["吃饭"],
    "passed": false,
    "finished": false,
    "finishedRounds": 0,
    "totalRounds": 1,
    "nextTrainerMessage": null
  }
}
```

**响应示例（通过 → 流程结束）**:

```json
  "message": "success",
  "data": {
    "recognizedText": "还没吃饭呢，正准备去吃饭",

    "audioDurationMs": 3600,
    "withdrawn": false,
    "keyPoints": ["吃饭"],
    "passed": true,

    "finishedRounds": 1,

  }

```

**响应示例（没听清 → 提示重说，不弹要点）**:

```json

  "code": 0,
  "message": "success",
  "data": {
    "recognizedText": "",
    "messageId": 6,
    "audioUrl": "/audio/asr/6.wav",
```

**字段说明**：`withdrawn / noSpeech / keyPoints / passed / finished / finishedRounds / totalRounds / nextTrainerMessage` 语义与 2.3 完全一致；区别仅在消息来源为录音（inputMode=2，落库带 audio_url/audio_duration_ms）。

- v1.1 的 `1 该项目为文字对话模式` 已随双输入改造删除。
- 豆包返回的错误码与 logId 只写服务端日志，不进学员端提示文案。

### 5.3 FP-26/28 AI 生成陪练者形象（管理端）

- **Method / Path**：`POST /admin/ai/generate-avatar`
- **说明**：管理端"虚拟陪练者设置"表单的形象生成；调 Dify 生图工作流，图片转存本地文件服务后返回 URL。**输出尺寸固定 1024×1024 方图**（生图插件限制，其他尺寸质量下降），展示侧按 1:1 适配、不裁剪。请求里的 `prompt` 是用户原始描述，后端会追加"人物半身居中、头顶与左右留边"的构图约束后再送 Dify（Dify 工作流内的提示词优化 LLM 节点负责改写为写实英文提示词并保证人脸完整居中）。

**请求参数**:

| 参数 | 位置 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| prompt | body | string | 是 | 形象提示词，2~200 字 |

**请求示例**:

```json
{ "prompt": "中年男性医生，白大褂，专业亲切" }
```

**响应示例**:

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "imageUrl": "/avatar/f2b1c8d4e5f64a7b9c0d1e2f3a4b5c6d.png"
  }
}
```

**错误码**：`1 请输入形象提示词（2~200字）` / `1 形象生成失败，请重试或上传本地图片`

- **超时（2026-09-24 调整）**：后端 Dify 调用按 agent 可配读超时——`avatar-gen` 配置 `dify.agents.avatar-gen.read-timeout-ms=300000`（5 分钟，Dify 生图链路慢），`report-scoring` 未配置时默认 120s；前端本接口 axios 超时 300s（原 60s）。慢属正常，前端 loading 态需容忍 5 分钟。
- `imageUrl` 是**相对路径** `{app.upload.avatar-url-prefix}/{uuid32}.{ext}`（默认前缀 `/avatar`，无日期目录），落库到 `virtual_trainer.avatar_image` 的原样保存；前端经 `resolveAssetUrl()` 拼成 `http://localhost:8080/api/avatar/...` 访问。后端同时注册 `/avatar/**` 与 `/api/avatar/**` 两套静态映射，直连后端或走网关都取得到。

### 5.4b FP-25 评分维度扩展（管理端既有接口变更）

- **说明**：管理端 `POST/PUT /admin/training-project` 请求的 `scoringDimensions[]` 与
  `GET /admin/training-project/{id}` 响应的 `scoringDimensions[]`（同一 DTO `ProjectSaveReq.ScoringDimensionReq` 复用）新增：
  该接口是 `multipart/form-data`，`scoringDimensions` 作为**整体 JSON 字符串**表单提交（`fd.append('scoringDimensions', JSON.stringify([...]))`），
  不是逐下标参数；下面按数组元素描述字段。

| 字段 | 类型 | 位置 | 必填 | 说明 |
|------|------|------|------|------|
| evidenceType | int | 请求 + 响应 | 否（默认 1） | 评分依据：**1=看文字 / 2=看语音 / 3=文字+语音**。取 2 时，本次训练若无任何语音轮次则该维度**不参与评分**（`score=null`、不计入总分权重）。取 3 时（v1.3 起）该维度 rule 会带"语音表现参考"声学摘要注入（见 08 §4） |
| metricKey | string | **请求字段**；响应由服务端反解回填 | 否 | 后端量化指标：`speech_speed` / `forbidden_words` / `tone`（S2 Phase 2 上线后）/ `""`（空＝该维度交给 AI 评分）。服务端 `DimensionMetricConfig.toJson()` 转成 `metric_config` JSON 入库；**白名单外的 key 直接丢弃并 `log.warn`** |
| metricParams | object | 请求字段（v1.3 新增） | 否 | 指标参数：选 `speech_speed` → `{bestMin, bestMax}`（语速满分区间，缺省 150/250）；选 `forbidden_words` → `{deductPerHit}`（每词扣分，缺省 20）；选 `tone` → `{aspect}`（评什么角度，如"热情"）。空/缺 key 用代码默认值；白名单外的参数 key 丢弃并 warn。**管理端参数输入框对应本字段**（08 §5 S0-4，消除"只能改库"） |
| metricAspect | string | 请求字段（S2 Phase 2） | 否（默认"热情"） | 选 `tone` 时的"评什么角度"快捷字段（2~6 字），服务端并入 `params.aspect`；仅 tone 有效，其余指标忽略 |
| metricConfig | string \| null | 仅响应用；**请求带了一律被忽略** | — | 入库的指标配置原文 `{"metric":"speech_speed"}`（可含 `params`）。忽略请求值是为了让前端不必拼半成品 JSON |

请求示例（`scoringDimensions` 片段）：

```json
[
  { "dimensionName": "语速适中", "weight": 10, "ruleType": "formula",
    "evidenceType": 2, "metricKey": "speech_speed", "metricParams": { "bestMin": 150, "bestMax": 250 } },
  { "dimensionName": "违禁词", "weight": 10, "ruleType": "deduction",
    "evidenceType": 1, "metricKey": "forbidden_words", "metricParams": { "deductPerHit": 20 } },
  { "dimensionName": "礼貌用语", "weight": 10, "ruleType": "grade",
    "evidenceType": 1, "metricKey": "" }
]
```

- 管理端 UI 是两个下拉：`依据 = 看文字/看语音/文字+语音`、`定分方式 = AI 评分/语速规则算分/违禁词规则算分/音频模型评语气（S2 后）`，
  维度停用时置灰。回显时 `metricKey` 与 `metricParams` 从 `metric_config` 反解，所以库里已有的配置在页面上看得见、可改回"AI 评分"。
  **v1.3 起**：选定分方式后旁侧展示参数输入框（bestMin/bestMax 或 deductPerHit；tone 为角度输入框），空值=用默认（08 §5 S0-4）。
- `ruleType` 与本次变更无关，但形态需说明清楚以免误读上面示例：**请求**可传字符串码
  （`exact`=1 / `keypoints`=2 / `mixed`=3 / `grade`=4 / `formula`=5 / `deduction`=6，服务端 `getRuleTypeAsInt()` 统一映射，
  也兼容直接传数字）；**响应**是实体里的数字。上面示例取管理端实际发出的形态。
- 读侧容错：库里已是坏 JSON 或未知指标时该维度回落为"交给 AI 评分"，报告**仍正常生成**（配置写错不该让整份报告失败）。
- `params`（如 `{"bestMin":150,"bestMax":250}`）**v1.3 起有界面入口**（`metricParams` 字段上送）；此前只能直接改库。缺失 key 时取代码默认（语速 150-250、违禁词每词扣 20）。
- 兼容性：两列缺省即 `evidenceType=1, metric_config=NULL`，与改造前"按纯文本、由 AI 评分"的行为一致；
  存量项目由 DDL 的 `rule_type=5/6` 回填 UPDATE 自动接上（见 `07-DDL变更清单.md` ①）。
