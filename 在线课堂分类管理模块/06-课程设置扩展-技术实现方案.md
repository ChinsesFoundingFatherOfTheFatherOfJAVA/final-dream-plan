## 2. 数据模型（kng_setting 重构，完整 DDL 见 08）

```sql
kng_setting (
  id          TINYINT PK DEFAULT 1,      -- 恒一行
  score_conf  JSON NULL,                  -- 学分策略（FP-02b）
  cheat_conf  JSON NULL,                  -- 防挂机+特殊设置（FP-02c/02d）
  play_conf   JSON NULL,                  -- 课程播放（FP-02e）
  face_conf   JSON NULL,                  -- 人脸识别（FP-02f）
  updated_by  VARCHAR(32) NULL,
  updated_at  DATETIME
)
```

**JSON 结构定义**（字段命名为本系统自定义，与原平台字段的映射见 §3）：

```
score_conf:
{
  "videoAudio":   { "standardMinutes": 10, "score": 1.0, "applyToAll": false },
  "document":     { "pagesPerScore": 1, "score": 0.1, "standardMinutes": 1,
                    "maxScore": 6.0, "applyToAll": false },
  "microcourse":  { "standardMinutes": 10, "score": 1.0, "maxScore": 10.0, "applyToAll": false },
  "scorm":        { "standardMinutes": 10, "score": 1.0, "applyToAll": false },
  "html":         { "standardMinutes": 10, "score": 1.0, "applyToAll": false },
  "rewardType": 0        // 0=每学完一个课件任务发放 1=学完课程时发放
}

cheat_conf:
{
  "antiIdleEnabled": true,        // 开启防挂机功能
  "mode": 1,                      // 1 模式一 2 模式二
  "checkMinutes": 3,              // 确认在线间隔（分钟）1~60
  "confirmSeconds": 120,          // 模式二确认时限（秒）30~600
  "promptText": "已触发防挂机验证，请点击\"继续学习\"，否则学习将被停止",   // ≤250
  "multiCourseEnabled": true,     // 防多课程同时学习
  "forbidDragEnabled": true,      // 禁止拖拽学习
  "audioBackgroundPlay": false    // 特殊设置-允许音频视频后台播放（FP-02d 独立保存）
}

play_conf:  { "speedEnabled": true, "speedScope": 2, "speedHoursCalc": true }
// speedScope 1=所有课件课程都支持 2=跟随课件或课程各自的功能设置；speedHoursCalc=全局学时倍速开关（v2.1 新增，原平台 multipleStudy 字段）
face_conf:  { "enabled": false }
```

**实体映射方式**（对齐工程既有做法）：`KngSetting` 实体四个字段声明为 `String`，Service 层用 Jackson 序列化/反序列化 + 参数校验（Bean Validation 在 DTO 上做）。**不要**给 String 字段配 JacksonTypeHandler（会二次序列化——工程已知坑）；也可声明为类型化 POJO + `@TableField(typeHandler = JacksonTypeHandler.class)` + `@TableName(autoResultMap = true)`，二选一，推荐前者（显式、好调试）。

**迁移**：v1.0 已建的旧列结构作废。执行 08 脚本：`DROP TABLE IF EXISTS kng_setting` 后按新结构重建 + 插入种子行（表内仅一行默认配置，可安全重建；若担心已保存的配置，先 SELECT 留档再执行——脚本注释已写明）。

## 4. 后端工程（改动点）

```
controller/SettingController.java     # 重构：
  GET  /api/kng/admin/setting                 → SettingService.getAll() 拼 4 块
  PUT  /api/kng/admin/setting/score           → 校验+保存 score_conf
  PUT  /api/kng/admin/setting/cheat           → 保存防挂机 7 字段（保留 audioBackgroundPlay 原值）
  PUT  /api/kng/admin/setting/special         → 仅更新 cheat_conf.audioBackgroundPlay
  PUT  /api/kng/admin/setting/play            → 保存 play_conf
  PUT  /api/kng/admin/setting/face            → 保存 face_conf（开关即时保存）
service/SettingService.java           # JSON 读写 + 参数校验 + 默认值兜底
dto/ScoreConf.java / CheatConf.java / PlayConf.java / FaceConf.java   # 类型化 DTO，Bean Validation
entity/KngSetting.java                # 4 个 String JSON 列
```

要点：
- **读兜底**：任一 JSON 列为 NULL 时返回代码内默认常量（与 08 种子一致），不向前端暴露 null 结构。
- **cheat 与 special 的字段隔离**：`PUT /cheat` 服务端读旧 cheat_conf → 覆盖 7 个防挂机字段 → 保留 audioBackgroundPlay；`PUT /special` 反向只改 audioBackgroundPlay。防止前端状态过期互相覆盖。
- 校验集中在 DTO（@NotNull/@DecimalMin/@Size），错误返回统一 code=1 + 中文 message。

## 6. 关键实现难点与对策

| 难点 | 对策 |
|------|------|
| JSON 列与 MyBatis-Plus 映射 | 实体 String + Service 层 Jackson（避开 TypeHandler 二次序列化坑）；DTO 定义 JSON 结构契约，接口文档与代码同源 |
| cheat/special 部分更新互相覆盖 | 服务端读-改-写，各自只覆盖自己的字段（见 §4） |
| 学分规则五行的动态校验差异 | ScoreConf DTO 分组校验：视频/Scorm/HTML 用 standardMinutes+score；文档加 pagesPerScore/standardMinutes/maxScore；微课加 maxScore；maxScore ≥ score 的跨字段校验放 Service |
| 默认值双份维护（代码常量 + 08 种子 SQL） | 以代码常量为唯一事实源；08 种子仅首次建表用；读兜底保证即使种子缺失也返回默认 |

## 7. 风险清单

| 风险 | 影响 | 应对 |
|------|------|------|
| DROP 重建丢失已保存设置 | v1.0 实现已可能保存过配置 | 08 脚本含留档 SELECT 注释；仅一行数据，重配成本低 |
| 原平台倍速字段映射未实证 | 与原平台语义若偏差（仅影响未来对齐） | 本系统自定义 speedScope 枚举语义明确，自洽 |
| 未来学员端消费 JSON 结构 | 结构即契约 | DTO 即契约文档；如需变更走版本化（新增字段不动旧字段） |
