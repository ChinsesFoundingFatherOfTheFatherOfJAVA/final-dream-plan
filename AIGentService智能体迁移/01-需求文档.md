## 1. 背景与目标

### 1.1 迁移动机（按含金量排序）

1. **稳定性根治（产品底线）**：Dify 部署（10.10.166.13）网络不稳定，自由演练助手的 SSE/WebSocket 频繁断连——核心业务链路依赖控制力最弱的黑盒组件（进程黑盒/插件锁版本/IP 可能漂移），属架构缺陷。用户立场："应用服务正常运行但智能体不稳定，还不如不用"；
   P1 当前先以 `qwen3.8-flash` 替代 Dify 编排，验证链路稳定性。
2. **消除文件传输链路**：主题/案例生成的用户上传材料现在要走"上传→Dify 文件变量→工作流内解析→回调 Java"多跳；自研后 Dubbo 直调数据服务 + 本地 Tika 解析，传输环节全省
3. **可维护性与扩展性**：Dify 迁 IP、智能体功能迭代（如话术生成的 firstSpeaker/narration 修订）都要过 Dify 画布；自研后 agent 与业务代码同仓库同日志同发布
4. **记忆系统归属**：Dify 的 conversation 存在其内部库摸不着，服务端被迫每轮查 DB 拼 inputs + 伪造用户 query（"会话刚开始，用户还没有说话"式补话）；自研后记忆三层化、完全归己

### 1.2 迁移范围（全部 9 个，分三阶段）

| 阶段 | 智能体 | 形态 | 迁移动机 |
|------|--------|------|----------|
| **P1** | 自由演练助手 | ReAct agent（4 工具） | 断连痛点主体，当天见效 |
| **P2** | 主题生成 / 案例生成 | workflow（llm+code，8/4 节点） | 文件传输痛点 |
| **P3** | 场景/大纲/话术生成 ×3、文生图、报告评分、话术评分器 | workflow（3~5 节点直线） | 等价平移收尾 |

### 1.3 明确不迁（留守）

| 组件 | 留守位置 | 理由 |
|------|----------|------|
| TTS（CosyVoice）/ 流式 ASR（豆包 SAUC） | SpeechTraining | 稳定运行中、无断连痛点、流式二进制协议是踩坑资产；搬迁纯增风险。二期统一评估 |
| Dify 平台本身 | 保留至 P3 全量切流后下线 | 灰度期 fallback（§5） |

## 2. 功能需求

### AG-01 AIGentService 应用骨架
- **功能描述**：新建 Spring Boot 应用（用户自建空壳，老模式），注册 Nacos（169.254.180.49:8848），网关加路由 `/api/agent/**`（排在 `/api/**` 兜底前，预留未来前端直连与调试端点）。
- **依赖**：spring-boot-starter-data-redis（复用现成实例 10.100.26.200:6379，与 StaffManagement 部门缓存共用，**key 前缀 `agent:` 隔离**）、Dubbo（工具双轨期用）、WebClient（vllm 调用）。
- **说明（事实修正后）**：P1~P3 全部消费流量为**服务间直连**（AtualCombatTraining/SpeechTraining → AIGentService 内部 HTTP，不经网关）；网关路由仅作预留。
- **验收**：应用启动注册成功；内部接口可被 AtualCombatTraining 直连访问；Redis 连通（PING）。

### AG-02 agent-core 手写引擎（平台层）
- **功能描述**：两类执行引擎 + 公共设施：
  - **WorkflowEngine**：`收参数 → LLM 调用（structured output）→ 可选后处理 → 返回`。覆盖 P2/P3 的 8 个 workflow 型智能体（DSL 里的 code 节点逻辑平移为 Java 后处理函数）
  - **ReActEngine**：`循环{LLM→解析工具调用→执行→回填→继续} 或输出`；迭代上限 80（对齐 Dify 配置）；每步 SSE 事件推送
  - **LlmClient 接口**（强制通道）：`complete(messages, options) → 结构化结果`；现实现 VllmClient（OpenAI 兼容接口）；**将来按 agent 粒度可加 SpringAiClient 等，不渗透平台层**（架构原则：手写基座 + 按 agent 粒度按需引框架）
  - **ToolRegistry**（强制通道）：工具统一注册/描述管理/执行调度（Dubbo 直调或本地 Bean）
- **验收**：用话术生成（最简单 3 节点 workflow）打通 LlmClient→vllm 全链路。

### AG-03 三层记忆系统（P1 核心配套）
- **功能描述**：

| 层 | 载体 | 职责 |
|----|------|------|
| L1 进程内 | Caffeine（或 ConcurrentHashMap + 读写锁） | 活跃会话全量消息列表 + inputs 快照（theme_status/artifact_summary/material_summary），热路径零网络开销 |
| L2 Redis | 现成实例，key `agent:session:{sessionId}`，TTL 7 天 | 会话闲置（30 分钟无活动）从 L1 逐出时序列化持久；恢复会话时反序列化 |
| L3 DB | act_ai_messages / act_ai_session（现有表不动） | 事实源归档；Redis 丢失时降级重建（从 DB 加载拼装，即现有行为） |

- **inputs 缓存**：theme_status/artifact_summary/material_summary 变更时失效重算（工具执行成功后主动失效），非每轮查 DB。
- **根治伪 query**：删除 `SESSION_START_QUERY_NEW/RESUMED` 两个常量；会话开启行为改为 **instruction 系统规则**（"会话首轮主动问候并询问三件事…"，已有类似内容）+ 引擎传 `is_first_turn` 结构化标志；恢复会话由引擎从 L2/L3 装载历史后直接发"请简要说明当前进展"的**系统消息**（非用户消息伪装）。
- **验收**：
  - Given 活跃会话连发 5 轮 When 每轮进来 Then 全程 0 次 DB 查询（日志验证）
  - Given 会话闲置 1 小时后回来 When 恢复 Then 从 Redis 反序列化，对话上下文连续（模型不重复询问已知信息）
  - Given Redis 清空 When 恢复会话 Then 从 DB 重建，功能不丢（体验允许降级为现状）

### AG-04 P1 自由演练助手迁移
- **功能描述**：instruction（4000+ 字状态机）原样平移为代码内常量/资源文件；4 个工具（create_topic/generate_theme/generate_cases/update_artifact）从"HTTP 回调 InternalToolController"改为 **Dubbo 直调 Service**（工具逻辑抽到 Service 层，Controller 过渡期保留）。
- **前端协议（事实修正后）**：前端实际走 **WebSocket 帧协议**（`/api/act/ws/chat?sessionId=` + WsFrameEncoder 事件帧：user-message-ack → session-start → message-start → part-start/part-content/part-end → session-finish，工具 bizType 事件以 data part 交织其中）——**WS 端点与帧编码全部留守 AtualCombatTraining，前端零改动**。AIGentService 对上游暴露**内部流式 HTTP 接口**，SSE 事件格式克隆 Dify 协议（agent_message/message_end/error），消费端 NativeAgentClient 平移 DifyAgentClient 代码结构（onChunk→writeText 逐字流转 WS part-content）；工具 bizType 事件仍由工具执行侧（AtualCombatTraining）直推本地 WS，不经 AIGentService 回传。
- **验收**：现有自由演练全流程回归（新建主题→规划→生成→案例→收尾）逐项通过；断线重连场景（杀连接再续）服务端可恢复。

### AG-05 P2 主题/案例生成迁移
- **功能描述**：DSL 平移为 WorkflowEngine 任务；**素材链路改造**：用户材料的文件/文本经 Dubbo 从 AtualCombatTraining 直取 + 本地 Tika 解析（参照媒体处理模块 MaterialExtractService），不再走 Dify 文件上传。
- **验收**：生成质量对齐现状（提示词不变）；素材从上传到可用的链路耗时对比有量化下降（目标 >50%）。

### AG-06 P3 六个 workflow 平移
- 场景/大纲/话术生成（含 v1.2 的 firstSpeaker/narration/陈述句规则提示词）、文生图、报告评分、话术评分器——照 DSL 等价改写，提示词 100% 复用。
- **验收**：每个智能体与 Dify 版输出对比抽样通过。

### AG-07 双轨灰度与切换
- **配置开关**（Nacos 动态配置）：`agent.<name>.provider=dify|native`，默认 dify；逐智能体切 native；P3 全切后 Dify 下线。
- **回退**：native 异常率超阈值（监控项）时配置切回 dify，分钟级。
- **验收**：开关切换不重启生效；dify/native 双跑期间同一输入结果可对比。

## 3. 非功能需求
- token 成本零变化（同一 vllm 同一模型 Qwen3-30B）
- SSE 断线自愈：客户端重连续传（服务端保留会话态，见 AG-03 L1/L2）
- 全链路日志：agent 每轮迭代（prompt 摘要/工具调用/耗时）进应用日志，traceId 贯穿

## 附录A. 不做的事项及原因

| 项 | 原因 |
|----|------|
| Spring AI / LangChain4j 做平台框架 | 体量（600~900 行）不值抽象税；黑盒调试与 Dify 痛点同构；见 02 §2 选型原则 |
| TTS/ASR 迁入 | 稳定系统不折腾，二期评估 |
| 一次性全迁 | 双轨维护窗口风险集中，P1 先解痛点 |
| 8 个 workflow 提前重写 | 无痛点零收益，P3 排队 |
| 自建向量库/RAG | 当前无消费场景；知识空间立项时按 agent 粒度引框架 |
