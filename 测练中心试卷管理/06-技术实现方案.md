## 3. 关键实现设计

### 3.1 同源写入（FP-10/13）

```
PaperQuesService.addQuestion(paperId, draft, sectionIndex):
  1. 调 QuesService.save(draft)  → exam_question 入库（libId=卡片归属库，默认默认题库）
  2. INSERT exam_paper_question(paperId, quesId, score, sectionIndex, orderIndex=组内max+1)
  3. 冗余计数维护：paper.totalScore += score; totalQuesQty += 1

pickFromLib(paperId, quesIds, scoreMap):  # 从题库选题
  逐题 INSERT exam_paper_question（不复制题目；校验试题存在且未删）

编辑已发布固定卷（FP-14 边界）:
  允许字段白名单：content/summary/questionItems(内容+数量+答案)/explainText
  拒绝：score/libId/levelType/point 关联变更（后端校验 40040）
```

### 3.2 大题分组与编号（FP-10）

- `section_index = 题型值`（0单选…5组合）；题目排序 order_index 组内递增。
- 前端渲染：`SELECT ... ORDER BY section_index, order_index` → 按题型分组；中文序号（一、二、三…）按组首次出现顺序计算；删除整组/拖拽后自动重排（后端只存题型值+order，前端算编号——**两级拖拽**：大题拖拽=重排 section 分组序（前端维护 groupOrder 到 paper.group_order JSON 列，可选）；小题拖拽=重排组内 order_index）。

### 3.3 策略矩阵与上限快照（FP-08/09）

```
StrategyService:
  读取: GET strategy/{paperId} → 关联库列表+JSON 反序列化
  来源设置: POST setsource {libs:[{libId, pointIds?}], sourceType} → 全删全插 exam_paper_strategy
  上限快照: 进入页面时对每库执行 COUNT(lib_id,type,level_type,disabled=0,deleted=0) 写入 MaxQty 字段
  单元格更新: PUT updatecell {libId, levelType, field:singleQty|needQty|singleScore..., value}
    → 反序列化该库 JSON → 改对应字段 → 整条写回（对齐原平台 updatecount/updatescore 形态）
  quesMode 切换: PUT paper.ques_mode；矩阵维度由前端按 quesMode 渲染，数据不丢（JSON 全字段保留）
  统计: 试题数/总分 = Σ(Qty×Score) 按当前 quesMode 生效字段计算（后端计算接口供前端轮询或前端本地算+保存后刷新）
```

### 3.4 发布（FP-14）

```
publish(paperId):
  buildType=随机: 校验任一策略 Qty>0 → 任一 Score>0 → status=4（错误码对齐 2151045/2151048 语义）
  buildType=固定: 校验关联题数>0 → 每题 score>0 → status=4
  发布后写 release_time；随机卷策略/来源接口对 status=4 全部只读（后端 40050）
```

### 3.5 快速出卷解析（FP-12）

复用题库 ExcelQuestionParser，扩展：分值列（必填，写入关联 score）、多选漏选得分列（`-`=不漏选得0 / 数字=统一得 / `n/n/n`=按漏选数量均分→miss_score_type=2）、填空顺序列（有序/无序→no_order_mark）+ `答案&&备选答案` 语法（备选答案存 answer_content 备选段）。整卷归属库=第②步选择的库。

## 6. 实施顺序建议

1. 建表（08 SQL）+ 实体/Service 骨架
2. 试卷分类树 + 列表 + 创建/编辑抽屉（复用验证）
3. 固定卷编辑页（大题画布+题卡+同源写入）——先固定卷（复用度高）
4. 管理页 + 跨模块跳转（题库详情页 quesId 支持）
5. 随机卷编辑页（策略矩阵+来源三入口+快速抽题）
6. 发布流（校验链+双形态发布后状态）→ 概览/引用/共享/批量/快速出卷

## 7. 风险清单

| 风险 | 影响 | 应对 |
|------|------|------|
| 策略 JSON 并发写（多单元格快速失焦） | 合并丢失 | 单元格更新按 paperId+libId 行锁（SELECT FOR UPDATE）串行合并 |
| 题库删题级联 | 试卷引用悬空 | 删题时检查 exam_paper_question：有引用则阻止并提示"该试题已被试卷引用"（对齐原平台删除语义）；已发布试卷引用的题强制阻止 |
| 同源写入双计数漂移 | 列表试题数与实际不符 | 写操作同事务维护 paper 冗余计数 + 上线跑重算脚本（08 附） |
| 大题拖拽排序复杂 | 排序错乱 | section_index 不变+组内 order_index 重排；大题整体排序本期用 paper.group_order JSON 兜底 |
| 发布后编辑白名单绕过 | 已发布卷结构被改 | 后端字段级校验（40040）+ 前端隐藏双保险 |
| 上限快照过期 | 输入超过实际库存 | 保存时后端再校验一次实际 COUNT（超限 40060） |
