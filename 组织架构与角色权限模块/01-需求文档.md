> 版本：v1.0（2026-09-23）

## 1. 项目概述

在自有平台（front-end + gateway + 各后端微服务）中复刻绚星平台的「我的企业」下两个模块：

1. **组织架构 → 员工名册**：左侧部门树 + 右侧用户列表（多条件筛选、行操作）
2. **角色权限**：角色管理（列表/创建/编辑/删除/详情/权限勾选）+ 角色人员管理（成员授权/取消授权）

同时将现有 StaffManagement 应用（目前仅从 Oracle 视图只读查询员工信息）改造为**用户与权限中心**：

- MySQL 新建用户/角色等表，定时任务从 Oracle 增量同步员工为系统用户（初始默认密码）
- 提供登录认证（JWT），作为**整个系统的统一登录账号源**，前端全站拦截
- 原 Dubbo 员工查询接口保留，数据源改为 MySQL

**范围边界**：参照平台原页面有大量功能（创建员工、导入导出、锁定账号、兼职部门、角色等级、用户组、管辖范围、数据权限等）本期均不做，完整清单见附录 A。

## 2. 术语与角色

| 术语 | 说明 |
|------|------|
| 超级管理员（超管） | 内置 admin 账号 + 可被设置超管标记的用户。拥有全部功能权限，无需勾选 |
| 管理端 | 顶栏含"我的企业"入口的管理界面（员工名册、角色权限、AI 实战训练场等） |
| 学员端 | /study 下的学员页面（我的陪练、AI 对练等） |
| 权限点 | 菜单级权限，对应管理端一个页面/菜单项 |
| 默认密码 | 配置文件中固定的初始密码字符串（BCrypt 加密入库），重置密码即回到默认密码 |
| 增量水位 | Oracle 视图 LASTCHANGE 字段的最后同步值，用于增量拉取 |

**系统角色**：

| 角色 | 权限边界 |
|------|----------|
| 超级管理员 | 全部管理端菜单可见可操作；可设置/取消他人超管；内置 admin 不可被禁用/删除 |
| 普通管理用户 | 由所属角色的权限点决定可见菜单（如仅"角色权限"） |
| 普通员工（学员） | 仅学员端功能；登录后跳学员端首页 |

## 3. 功能需求（按模块组织）

### 3.0 登录认证模块（StaffManagement）

#### FP-21 统一登录
- **功能描述**：全站（管理端+学员端）统一登录页，账号（工号，无工号者手机号）+ 密码（默认密码）登录，JWT 鉴权。
- **前置条件**：用户已由 Oracle 同步任务创建（或内置 admin）。
- **页面/组件拆解**：
  - 新增 `/login` 路由登录页（独立页面，不进任何 Layout）
  - 登录表单：账号输入框、密码输入框（可显示/隐藏）、登录按钮
  - Pinia `auth` store：token、用户信息、权限码列表、超管标识
  - `request.ts` 拦截器改造：所有请求带 `Authorization: Bearer <token>`；响应 40101 时清除 token 并跳 `/login`
  - `router.beforeEach` 全局守卫：无 token → 跳 `/login`；访问管理端路由需具备对应权限码或超管标识；学员端路由仅需已登录
- **交互流程**：
  1. 用户访问任意路由 → 守卫发现无 token → 重定向 `/login`（记录来源路由，登录后回跳）
  2. 输入账号密码提交 → 后端校验（BCrypt 比对）→ 失败提示"账号或密码错误"；账号被禁用提示"账号已被禁用，请联系管理员"
  3. 登录成功 → 返回 token + 用户信息 + 权限码列表 → 前端存 localStorage
  4. **按权限跳转**（已确认）：超管或拥有任一管理端权限点 → 管理端首页 `/homepage`；无任何管理端权限的普通员工 → 学员端 `/study/home`
- **验收标准**：
  - Given 未登录用户访问 `/udp/orgoumgmt` When 页面加载 Then 重定向到 `/login`
  - Given 正确账号+默认密码 When 提交登录 Then 返回 token 且按权限跳转到对应端首页
  - Given 被禁用账号 When 登录 Then 提示"账号已被禁用"且不签发 token
  - Given token 过期 When 任意请求返回 40101 Then 前端清除凭证并跳转 `/login`

#### FP-21.1 修改密码
- **功能描述**：登录后可在顶栏用户下拉菜单"修改密码"（旧密码 + 新密码 + 确认新密码）。不强制首登改密。
- **验收标准**：
  - Given 已登录用户 When 输入正确旧密码与合规新密码 Then 修改成功，旧 token 继续有效至过期
  - Given 旧密码错误 When 提交 Then 提示"原密码错误"

### 3.1 组织架构 - 员工名册（/udp/orgoumgmt）

页面整体布局：左侧为「我的企业」二级侧栏（仅两个菜单：组织架构→员工名册、角色权限），中间为部门树面板，右侧为用户列表区。点击顶部导航"我的企业"进入本模块（原平台跳转 `https://train.chinajack.com/udp/#/orgoumgmt`，我们对应路由 `#/udp/orgoumgmt`）。

#### FP-01 部门树（左侧面板）
- **功能描述**：展示部门层级及对应人数；支持输入名称搜索部门；点击部门后右侧列表联动查询该部门（含子部门）的用户。
- **页面/组件拆解**：部门树面板（约 240px 宽）：搜索输入框 + 树（层级缩进、展开/收拢箭头、部门名+人数）。
- **交互流程**：
  1. 进入页面 → 树默认展开第一层，根节点（如"杰克科技学习平台"）显示总人数，默认选中根节点并查询全部用户
  2. 输入部门名称 → 实时过滤树节点（命中节点及其父链保留并展开，其余隐藏）
  3. 点击节点 → 高亮，右侧列表按该部门（含所有子部门）过滤，分页重置到第 1 页
- **验收标准**：
  - Given 部门树已加载 When 输入"营销" Then 仅显示名称含"营销"的节点及其父链
  - Given 点击部门 X When 右侧列表刷新 Then 仅显示部门 X 及其子部门下的用户，总数与树节点人数一致
  - Given 某部门无用户 When 点击该部门 Then 右侧显示空状态（保留表头，提示"暂无数据"）

#### FP-02 顶部按钮区 —— 不做（见附录 A）

#### FP-03 筛选：岗位（弹窗多选）
- **功能描述**：点击"岗位"筛选控件，右侧弹出岗位选择页面供用户选择、搜索岗位（多选，超越原平台的增强项）；不提供"所属分类"条件。
- **页面/组件拆解**：岗位选择弹窗（Drawer/Dialog，从右侧滑出）：
  - 搜索条件：岗位名称（输入框，模糊搜索）
  - 岗位列表：复选框 + 岗位名称 + 人数，分页（每页 20 条）
  - 底部：已选 N 项 + 取消 / 确定
- **交互流程**：点击筛选栏"岗位"→ 弹窗打开（默认第 1 页，未勾选）→ 勾选一个或多个岗位 → 确定后筛选栏显示已选岗位名（多个逗号分隔，超长省略），列表按所选岗位（OR 关系）过滤；再次打开弹窗回显已勾选；支持清除已选（筛选栏 × 或清空）。
- **数据来源**：岗位列表 = 用户表 distinct 岗位名（含每个岗位的用户数），随 Oracle 同步自动更新。
- **验收标准**：
  - Given 打开岗位弹窗 When 搜索"经理" Then 列表仅显示岗位名含"经理"的岗位及对应人数
  - Given 勾选 2 个岗位 When 点击确定 Then 右侧列表仅显示这 2 个岗位的用户
  - Given 已选岗位 When 点击筛选栏清除 Then 列表恢复为不限岗位

#### FP-04 筛选：启用/禁用
- **功能描述**：下拉选择"全部/启用/禁用"过滤用户状态。
- **验收标准**：Given 选择"禁用" When 列表刷新 Then 仅显示状态为禁用的用户，禁用状态行有视觉区分（如置灰）。

#### FP-05 筛选：锁定账号 / 兼职部门 —— 不做（见附录 A）

#### FP-06 筛选：字段搜索（下拉+输入框）
- **功能描述**：一个下拉框（选项：姓名/账号/工号/邮箱/手机号/职级）+ 一个输入框组合搜索，按所选字段模糊匹配。默认选中"姓名"。
- **验收标准**：
  - Given 选择"手机号"输入"138" When 查询 Then 返回手机号含"138"的用户
  - Given 切换筛选字段 When 输入框清空 Then 需重新输入后才过滤

#### FP-07 筛选：是否超级管理员
- **功能描述**：下拉选择"全部/是/否"过滤超管用户。
- **验收标准**：Given 选择"是" When 查询 Then 仅显示超管用户。

#### FP-08 用户信息列表
- **功能描述**：展示字段（顺序固定）：**姓名、账号、工号、手机号、邮箱、部门、岗位、职级、角色、入职时间、状态、操作**。
  - 账号 = 工号（无工号者 = 手机号）；工号列无工号显示 "-"
  - 部门显示完整层级，分隔符为下划线，如 `杰克集团_杰克科技股份_公共关系部_椒江公共关系部_基建组`
  - 角色 = 该用户全部角色名，逗号分隔（如 `平台管理员,培训管理员`），无角色显示 "-"
  - 状态 = 启用/禁用
  - 入职时间格式 `YYYY-MM-DD`，无数据显示 "-"
- **数据字段与列的映射**：以 02 文档 `sys_user` 表字段为准（name / account / employee_no / mobile / email / dept_path / position_name / job_grade / 角色聚合 / entry_date / status）。
- **验收标准**：
  - Given 用户存在多角色 When 列表展示 Then 角色列显示"角色A,角色B"，超长省略并悬浮显示完整
  - Given 任一字段值超过列宽 When 渲染 Then 文本省略号截断，鼠标悬浮 tooltip 显示完整值
  - Given 字段无值 When 渲染 Then 显示 "-"（不允许空白单元格）

#### FP-09 表格交互（列宽与滚动）
- **功能描述**：与原平台一致的列宽规格（实测）：**每列统一 160px，操作列 210px**，总宽超出可视区域时**表格横向滚动**（滚动条始终可见，支持鼠标滚轮横向滚动/拖动），姓名等关键列是否固定跟随滚动不做要求（本期全部列随横向滚动）。
- **验收标准**：
  - Given 窗口宽 1366px When 列表渲染 Then 内容区出现横向滚动条，可左右滚动查看所有列
  - Given 单元格内容超长（如完整部门层级）When 渲染 Then 显示省略号，悬浮显示完整内容（不撑破列宽）

#### FP-10 行操作
- **功能描述**：操作列提供：**禁用/启用、重置密码、删除、设置超管**。
  - 禁用/启用：按用户当前状态互斥显示（禁用用户显示"启用"）；禁用后该用户无法登录
  - 重置密码：确认弹窗"确认将该账号密码重置为默认密码？"→ 重置为配置的默认密码
  - 删除：二次确认弹窗 → 物理删除用户及其角色关联（已确认：若 Oracle 侧仍在职，下次同步会以默认密码重新创建）
  - 设置超管：设置/取消超管标记；仅超管可见此操作；admin 内置账号不可被禁用/删除/取消超管
- **验收标准**：
  - Given 启用用户 When 点击"禁用"并确认 Then 状态列变"禁用"，该用户登录被拒绝
  - Given 任意用户 When 点击"重置密码"并确认 Then 其密码变为默认密码，用默认密码可登录
  - Given 超管 When 对普通用户点击"设置超管" Then 该用户成为超管，登录后可见全部菜单
  - Given 内置 admin When 查看行操作 Then 不显示禁用/删除/取消超管（保护规则）
  - Given 删除用户 When 确认 Then 用户从列表消失且其角色关联同步清除

#### FP-11 分页
- **功能描述**：列表底部右侧分页：总条数、页码跳转、每页条数切换（20/50/100，默认 20）。
- **验收标准**：Given 共 978 条用户 When 每页 20 Then 显示 49 页；切换筛选条件时分页重置到第 1 页。

### 3.2 角色权限（/udp/role）

页面布局：左侧「我的企业」二级侧栏（同 3.1），内容区为左右两栏：左栏角色列表，右栏角色详情。角色人员管理为独立页面（原平台路由 `/#/role/user/mgmt/{id}`，我们对应 `#/udp/role/users/{id}`）。

#### FP-12 角色列表（左栏）
- **功能描述**：角色名称搜索 + 创建按钮 + 角色列表（角色名、人数）。
- **交互流程**：输入名称实时/回车过滤；点击角色 → 右侧展示详情；默认选中第一个角色。
- **验收标准**：
  - Given 角色列表 When 搜索"管理" Then 仅显示名称含"管理"的角色
  - Given 点击角色"导师" When 右栏刷新 Then 展示"导师"详情

#### FP-13 创建角色
- **功能描述**：点击"创建"右侧滑出表单：**角色名称（必填，≤20 字）、角色说明（≤500 字）、备注（多行文本）**，提交完成创建（舍弃原平台"角色等级"字段）。
- **交互流程**：创建 → 表单校验（名称必填、重名提示）→ 提交成功 → 关闭表单、列表刷新并选中新角色。
- **验收标准**：
  - Given 未填名称 When 提交 Then 提示"请输入角色名称"，不发请求
  - Given 名称与已有角色重复 When 提交 Then 提示"角色名称已存在"
  - Given 填写完整 When 提交 Then 新角色出现在列表，创建人为当前登录人，创建时间为当前时间

#### FP-13.1 编辑角色 / FP-13.2 删除角色
- **功能描述**：详情页可编辑名称/说明/备注（点"编辑"进入表单，回显当前值）；角色可删除，但**角色下仍有授权用户时禁止删除**（提示"该角色下仍有 N 名用户，请先取消全部授权"）。
- **验收标准**：
  - Given 角色"导师"有 0 人 When 删除并确认 Then 角色从列表消失
  - Given 角色"培训管理员"有 28 人 When 点击删除 Then 提示禁止删除且角色保留

#### FP-14 角色详情（右栏）+ 功能权限树
- **功能描述**：展示：角色名称、角色人数（旁有"角色人员管理"链接，点击跳转 FP-15 页面）、创建信息（创建人+创建时间）、角色描述、**功能权限勾选区**。
- **权限树（菜单级，已确认静态菜单树）**，勾选数据存角色-权限关联，**点击即时保存**（无保存按钮）：
  ```
  管理端
  ├── 首页（管理端首页，所有可进管理端的用户默认具备，不作为权限点）
  ├── 组织架构
  │   └── 员工名册（org:employee）
  ├── 角色权限
  │   └── 角色管理（role:mgmt）
  └── AI实战训练场
      ├── 话术训练中心（act:speech）
      ├── 话术模板（act:template）
      └── 实战训练场（act:training）
  ```
  - 权限点控制管理端菜单显示与路由进入；不控制按钮级；不涉及数据范围
  - 前端菜单按当前用户权限码动态渲染（超管=全部）
- **交互流程**：勾选某权限 → 立即调用接口保存（乐观更新，失败回滚并提示）；取消勾选同理。已拥有该角色的用户下次登录（或刷新）后菜单生效。
- **验收标准**：
  - Given 角色无"员工名册"权限 When 勾选 Then 保存成功，拥有该角色的用户登录后可见"员工名册"菜单
  - Given 勾选保存失败（网络异常）When 处理 Then 复选框回滚为未勾选并提示错误
  - Given 普通管理用户 When 登录 Then 左侧/二级菜单仅显示其角色权限对应的菜单项；直接输入无权限路由被拦截提示无权限

### 3.3 角色人员管理（/udp/role/users/{roleId}）

#### FP-15 角色人员列表页
- **功能描述**：独立页面，顶部标题"角色人员管理"+ 返回按钮；按钮：**添加成员、批量操作（批量取消授权）**；筛选：**选择部门（部门树下拉）、账号状态（全部/启用/禁用）、姓名/账号（下拉切换字段+输入框搜索）**；列表字段：**姓名、账号、状态、所在部门、所在岗位、添加人、添加时间、操作（取消授权）**；每行带复选框，分页同 FP-11。
- **验收标准**：
  - Given 角色有 28 名成员 When 进入页面 Then 列表展示 28 条，字段完整（部门/岗位为空显示 "-"）
  - Given 勾选 3 名成员 When 点击"批量操作→批量取消授权"并确认 Then 3 人被移除，列表刷新、人数-3
  - Given 单行点击"取消授权"并确认 Then 该用户被移除出角色
  - Given 筛选部门"COE室" When 查询 Then 仅显示所在部门为 COE室（含子部门）的该角色成员

#### FP-16 添加成员弹窗

### 3.4 后端改造（StaffManagement）

#### FP-17 MySQL 用户表 + Oracle 增量同步
- **功能描述**：final_dream 库（10.100.26.200）新建 sys_user / sys_department 等表；定时任务从 Oracle 视图 `JACKSHR.V_BD_JACKMES_INFO` 增量同步员工为系统用户。
- **同步规则（已确认）**：
  - 频率：每晚凌晨 2:00 增量；首次上线手动触发全量；另提供管理接口手动触发（无页面按钮）
  - 增量依据：Oracle `LASTCHANGE` 字段 > 本地水位
  - 新用户：插入 sys_user，**初始密码 = 配置的固定默认密码**（BCrypt 加密），状态启用，来源 ORACLE
  - 已有用户：更新基础字段（姓名/部门/岗位/职级/手机号/入职时间等），**不覆盖密码、状态、超管标记、角色关联**
  - 离职处理：Oracle 在职标识/状态变为离职 → 本地 status 置为禁用（不删除）
  - 手动删除的用户：若 Oracle 侧仍在职，下次同步会重新创建（默认密码）——已确认接受
  - 部门：同步任务同时维护 sys_department（层级、路径、人数统计按启用用户计）
- **验收标准**：
  - Given 首次全量同步 When 完成 Then sys_user 记录数与 Oracle 视图一致，所有人可用默认密码登录
  - Given Oracle 中员工 A 改了部门 When 次日同步 Then 本地 A 的部门字段更新
  - Given Oracle 中员工 B 离职 When 次日同步 Then 本地 B 状态变禁用、无法登录
  - Given 手动修改用户 C 为超管 When 次日同步 Then C 的超管标记保留
  - Given 同步执行中 Oracle 不可达 When 处理 Then 记录失败日志、保留旧水位，本地数据不受影响

#### FP-20 超级管理员机制
- **功能描述**：内置超管账号 admin（应用启动时 seeding，账号名/初始密码可配置），is_super_admin=1，不可禁用/删除/取消超管；超管拥有全部功能权限且权限树对其全勾选展示（只读）；仅超管可执行"设置超管"操作。
- **验收标准**：
  - Given 全新部署 When 服务启动 Then admin 账号存在，用配置初始密码可登录且为超管

## 4. 非功能需求（均为用户确认项）

- **密码安全**：BCrypt 存储；登录失败不提示具体是账号还是密码错误；连续失败锁定策略本期不做
- **性能**：员工名册查询为分页接口，部门树单次加载（约 1400 节点）；Oracle 全量同步 3.4 万人需分批（如 500/批）+ 事务
- **兼容性**：Chrome/Edge 现代浏览器；1920/1366 宽度下表格横向滚动正常
- **前端工程约定**：不引入 Element Plus，全部手写 SCSS；ID 一律 string（防 JS 长整型精度丢失）；字号标准：正文 14px、辅助 12-13px、按钮/列表 15px、页标题 22px、统计数字 28px
