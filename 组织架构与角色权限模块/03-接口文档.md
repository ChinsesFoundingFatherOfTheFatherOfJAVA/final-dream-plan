> 版本：v1.2（2026-09-28，v2.1 变更回写；契约变更清单见 §4）
> 服务：StaffManagement（经网关路由 `/api/sm/**` → lb://StaffManagement）
> 配套文档：《01-需求文档》《02-技术实现方案》，接口均标注对应 FP 编号。
> v1.2 为**破坏性变更**（部门树响应结构、users/成员查询部门参数、删除用户行为），前端调用方须同步改造。

## 1. 通用约定

### 1.1 Base URL

- 开发环境：`http://localhost:8080/api/sm`（经网关 8080）
- 前端 axios baseURL 沿用 `/api`（相对路径，见 front-end/src/api/request.ts），调用形如 `request.post('/sm/auth/login', ...)`
- **网关 `/api/sm/**` 路由已落地**（`order=-1`，位于 `/api/**` 兜底之前）；也可直连服务端口联调：
  StaffManagement 正常实例 `http://localhost:8083/api/sm`；agent 自测用的隔离实例 `http://localhost:8093/api/sm`
  （不起 Nacos 注册，见《02》§6.6）。

### 1.2 鉴权方式

- 除 `POST /api/sm/auth/login` 外，全部接口要求请求头：`Authorization: Bearer <JWT>`
- JWT（HS256）payload：`{ "userId": "1", "account": "40028497", "name": "贾瑞涛", "isSuperAdmin": false, "exp": <秒级时间戳> }`
- 过期时间默认 12 小时（配置 `sm.auth.jwt-expire-hours`）

### 1.3 统一响应结构

```json
{ "code": 0, "message": "ok", "data": { } }
```

- `code = 0` 成功（前端 request.ts 已按此判断，成功直接返回 data）
- 分页响应 data 统一为：`{ "list": [...], "total": 978, "page": 1, "size": 20 }`
- 不分页的列表（部门树、角色列表、权限树、职级、同步状态）data 为 `{ "list": [...] }`——
  同样包一层 `list`，让前端只有一种取值方式
- **业务失败一律 HTTP 200 + 非零 code**（2026-09-23 实施时确定）：HTTP 状态码只用来区分
  "服务端真的出错了"（5xx）与历史接口的 400，不用来表达 40101/40902 这类业务语义。
  原因：request.ts 的响应拦截器只在 2xx 分支读 `data.code`，非 2xx 会被 axios 提前 reject，
  "看到 40101 就清凭证跳登录页"会失效。**前端不要按 HTTP 状态码判断登录失效。**

### 1.4 错误码总表

| code | 含义 | 触发场景 |
|------|------|----------|
| 0 | 成功 | |
| 40001 | 参数错误 | 缺少必填项、格式非法；**含** query 参数绑定失败（`size=abc`、`status=LEFT` 这类类型/枚举不符）与请求体不是合法 JSON（含非 UTF-8 字节） |
| 40101 | 未登录或 token 失效 | 无 Authorization 头 / token 过期或非法 / 签名不匹配（前端需清除凭证跳登录） |
| 40102 | 账号或密码错误 | 登录校验失败（不区分账号/密码错，避免账号枚举） |
| 40103 | 账号已被禁用 | 禁用用户登录 |
| 40301 | 无权限 | 非超管调用超管接口（设超管、触发/查询同步） |
| 40401 | 资源不存在 | 用户/角色/权限/部门 ID 无效或查不到 |
| 40901 | 角色名称已存在 | 创建/编辑角色重名 |
| 40902 | 角色下仍有用户，禁止删除 | 角色人数 > 0 时删除 |
| 40903 | 内置超管账号禁止该操作 | 对 admin 禁用/删除/取消超管 |
| 40904 | 原密码错误 | 修改密码 |
| 40905 | 用户仍是训练项目负责人，禁止删除 | 删除用户时该账号仍是任一 training_project 的 responsible_person / created_by（v1.2 新增；同步任务遇此场景静默跳过并记 skipped，不报此码） |
| 50001 | 服务器内部错误 | 未预期异常，message 为固定提示，堆栈只在服务端日志 |
| 50301 | Oracle 同步相关失败 | ① 触发同步时已有任务在跑（"已有同步任务正在执行"）；② 同步本轮失败（异步执行，失败原因看 `GET /admin/sync/status` 的 `errorMsg`） |

> 40001 的 message 是一句固定文案（"请求参数格式不正确…"/"请求体格式不正确…"），不回显用户输入；
> 由 service 主动抛出的参数错误（如 `searchField` 取值不支持）会带上具体说明。

失败响应体固定为 `{ "code": <非0>, "message": "<中文说明>", "data": null }`。其中 40101 由
servlet 过滤器（`JwtFilter`）直接写出，请求根本进不到 Controller——所以它的 message 恒定，
不要试图在登录接口之外的地方拿到更细的原因。

### 1.5 分页与排序约定

- `page`：页码，从 1 起，默认 1；传 0/负数/非数字以外的越界值会被纠正为 1（非数字才是 40001）
- `size`：每页条数，默认 20，前端只给 20/50/100；**超过 100 会被静默纠正为 100**（不报错，防止 URL 手输把页面打白）
- 各列表的实际排序（本期不支持自定义排序）：

| 列表 | 排序 |
|------|------|
| 员工名册 / 添加成员候选 | `user_id` 倒序（新账号在前） |
| 角色成员 | `sys_user_role.added_at` 倒序（新加的在前） |
| 角色列表 | `role.id` 正序（= 创建先后） |
| 部门树 | `department.id` 正序（同步按层级写入，父在前） |
| 权限树 | `sort` 正序、同值按 `id` |
| 岗位列表 | 该岗位用户数倒序，同数按岗位名 |
| 同步状态 | 记录 `id` 倒序（最近一轮在前） |

### 1.6 通用字段类型约定

- **所有 id（userId/roleId/permissionId/deptId）在 JSON 中均为 string**（防 JS 长整型精度丢失）
- 时间：`DATETIME` → `"2026-09-23 15:20:00"`；日期：`"2026-09-18"`
- 状态：用户 `status`：`1` 启用 / `0` 禁用（**v1.2：仅在职员工的启停；离职用户不存在于库中**）；空值字段一律返回 `null`（前端显示 "-"）

## 2. 接口列表

### 2.1 认证模块

#### FP-21 登录

- **Method / Path**：`POST /api/sm/auth/login`
- **说明**：账号+密码登录，签发 JWT，返回用户信息与权限码（免鉴权）。
- **请求参数**：

| 参数 | 位置 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| account | body | string | 是 | 账号（工号，无工号者手机号） |
| password | body | string | 是 | 密码明文（HTTPS 传输） |

- **请求示例**：
```json
{ "account": "40028497", "password": "Jack@123456" }
```
- **响应示例**：
```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9.eyJ1c2VySWQiOiIxMjM0IiwiYWNjb3VudCI6IjQwMDI4NDk3IiwibmFtZSI6IuizhOm7mOeOiSIsImlzU3VwZXJBZG1pbiI6ZmFsc2UsImV4cCI6MTc1ODYxMjM0NX0.xxxx",
    "user": {
      "userId": "1234",
      "account": "40028497",
      "name": "贾瑞涛",
      "isSuperAdmin": false,
      "status": 1
    },
    "permissions": ["act:speech", "act:template"]
  }
}
```
> `permissions` 为该用户全部角色的权限码并集；超管返回 `["*"]`（前端视为全量）。
- **错误码**：`40001 账号和密码都要填写`、`40102 账号或密码错误`、`40103 账号已被禁用`

#### FP-21.2 当前登录人

- **Method / Path**：`GET /api/sm/auth/me`
- **说明**：返回当前 JWT 对应账号的身份与权限码，供前端刷新、路由守卫和菜单恢复使用；权限码实时查库，不固化在 token 中。
- **请求参数**：无（从 `Authorization: Bearer <JWT>` 解析）。
- **响应示例**：
```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "userId": "1234",
    "fullname": "贾瑞涛",
    "permissions": ["act:speech", "exam:queslib"]
  }
}
```
- **错误码**：`40101 未登录或登录已过期`

#### FP-21.1 修改密码

- **Method / Path**：`POST /api/sm/auth/change-password`
- **说明**：修改当前登录用户密码。
- **请求参数**：

| 参数 | 位置 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| oldPassword | body | string | 是 | 原密码 |
| newPassword | body | string | 是 | 新密码，6-32 位 |

- **请求示例**：
```json
{ "oldPassword": "Jack@123456", "newPassword": "MyNew@2026" }
```
- **响应示例**：
```json
{ "code": 0, "message": "ok", "data": null }
```
- **错误码**：`40904 原密码错误`、`40001 新密码长度不合规`

### 2.2 部门模块

#### FP-01/FP-22 部门树

- **Method / Path**：`GET /api/sm/admin/departments/tree`
- **说明**：返回全量部门（平铺数组，前端按 `deptPath` 前缀递归建树），含各级用户数；keyword 可选过滤。**v1.2 响应结构变更**。
- **请求参数**：

| 参数 | 位置 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| keyword | query | string | 否 | 部门名模糊过滤；为空返回全量 |

- **响应示例**：
```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "list": [
      { "deptId": "1", "deptCode": null, "deptName": "杰克科技股份", "deptPath": "杰克集团_杰克科技股份", "parentPath": null, "userCount": 19482 },
      { "deptId": "2", "deptCode": null, "deptName": "营销军团", "deptPath": "杰克集团_杰克科技股份_营销军团", "parentPath": "杰克集团_杰克科技股份", "userCount": 120 },
      { "deptId": "3", "deptCode": "107010304", "deptName": "华东2区", "deptPath": "杰克集团_杰克科技股份_营销军团_欧洲战区_华东2区", "parentPath": "杰克集团_杰克科技股份_营销军团_欧洲战区", "userCount": 12 }
    ]
  }
}
```
> **v1.2 字段说明**：
> - `deptPath`（**新增，建树唯一依据**）：节点完整路径；父节点路径 = 子节点路径去掉最后一段 `_xxx`。**`parentCode` 字段已废弃**（合成节点无编码，链路不可靠），前端一律按 `deptPath` 建树。
> - `deptCode`：Oracle 组织编号；**中间层合成节点（无直属员工的部门）为 `null`**（部门管理页显示 "-"），有直属员工的部门非空。
> - `userCount` = 该节点（含所有子部门）**全部用户数**（v1.2 口径：不限状态，在职即计数）。
> - 树根为合成节点「杰克科技股份」（`deptCode=null`，`parentPath=null`），**不再有**"杰克科技学习平台/经销商"等原平台顶层节点（只同步股份子树）。
> - `keyword` 过滤时保留"命中节点 + 其全部祖先链"，**命中节点自己的下级不展开**；带 keyword 的返回按层级重排，父一定在子之前。
> - 数据为清理重同步后的结果（《02》§6.4.1）；未同步的全新环境返回 `{"list": []}`，带 `deptId` 的用户查询回 `40401`。

### 2.3 用户模块（员工名册）

#### FP-04/06/07/08/11 用户分页查询

- **Method / Path**：`GET /api/sm/admin/users`
- **说明**：员工名册列表、添加成员弹窗共用此接口（多条件组合，条件间 AND，岗位多选间 OR）。
- **请求参数**：

| 参数 | 位置 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| page | query | int | 否 | 默认 1 |
| size | query | int | 否 | 默认 20 |
| deptId | query | string | 否 | **部门节点 ID（v1.2：替代原 deptCode）**，查该部门**含子部门**用户——后端按节点 dept_path 前缀展开子树（`_` 显式 ESCAPE） |
| status | query | int | 否 | 1 启用 / 0 禁用；缺省=全部 |
| searchField | query | string | 否 | 搜索字段：`name`/`account`/`employeeNo`/`email`/`mobile`/`jobGrade`（默认 name） |
| keyword | query | string | 否 | 搜索关键字，对该字段模糊匹配 |
| positionNames | query | string[] | 否 | 岗位名列表（多选，逗号分隔或重复参数，OR 关系） |
| isSuperAdmin | query | int | 否 | 1 是 / 0 否；缺省=全部 |

- **请求示例**：`GET /api/sm/admin/users?page=1&size=20&deptId=2&status=1&searchField=name&keyword=贾&positionNames=大客户销售经理,市场经理`
- **响应示例**：
```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "list": [
      {
        "userId": "1234",
        "name": "贾瑞涛",
        "account": "40028497",
        "employeeNo": "40028497",
        "mobile": "+86-16638426624",
        "email": null,
        "deptCode": "D011",
        "deptName": "欧洲战区",
        "deptPath": "杰克科技股份_营销军团_欧洲战区_大客户业务组",
        "positionName": "大客户销售经理",
        "jobGrade": "P5",
        "roleNames": ["培训管理员"],
        "entryDate": "2026-09-18",
        "status": 1,
        "isSuperAdmin": false,
        "builtin": false
      }
    ],
    "total": 1,
    "page": 1,
    "size": 20
  }
}
```
> `deptPath` 用 `_` 分隔完整层级——Oracle `组织全名称` 原生就是这个分隔符（C-4 实测确认），前后端都不做转换；
> `roleNames` 为该用户全部角色名数组（前端逗号拼接，无角色时是空数组）；`email` 恒为 null（C-1 实测：视图无邮箱列，
> 且同步不写该列），前端显示 "-"。
> **v1.2**：列表只含**股份子树在职员工**（范围外子公司与离职者不落库）；`deptId` 传不存在的节点回 `40401`。
> **`builtin`（新增）**：是否内置超级管理员账号（= 手工创建 + 账号等于 `sm.auth.admin-account`）。
> 前端据此隐藏"禁用/删除/取消超管"三个入口——不能用 `isSuperAdmin` 判，别的用户也可以被设为超管。
> 对 `builtin=true` 的用户调用那三个接口会回 `40903`。
>
> 注意 `searchField` 传了不支持的取值（不在上面 6 项内）是 `40001`，不会静默按姓名兜底。

#### FP-10 启用/禁用用户

- **Method / Path**：`POST /api/sm/admin/users/{userId}/status`
- **说明**：切换用户状态；禁用用户无法登录（token 到期前旧 token 仍有效，见风险 R-3 说明）。
- **请求参数**：

| 参数 | 位置 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| userId | path | string | 是 | 用户 ID |
| status | body | int | 是 | 目标状态 1 启用 / 0 禁用 |

- **请求示例**：
```json
{ "status": 0 }
```
- **响应示例**：
```json
{ "code": 0, "message": "ok", "data": null }
```
- **错误码**：`40401 用户不存在`、`40903 内置超管账号禁止该操作`（对 admin 传 0）

#### FP-10 重置密码

- **Method / Path**：`POST /api/sm/admin/users/{userId}/reset-password`
- **说明**：将用户密码重置为系统默认密码（BCrypt 重新入库）。
- **请求参数**：仅 path 参数 `userId`，无 body。
- **响应示例**：
```json
{ "code": 0, "message": "ok", "data": null }
```
- **错误码**：`40401 用户不存在`

#### FP-10 删除用户

- **Method / Path**：`DELETE /api/sm/admin/users/{userId}`
- **说明**：物理删除用户，**同一事务级联清理（v1.2 扩展）**：sys_user_role + sys_user + project_student（该用户作为学员的项目指派行）。若该用户仍是任一训练项目的负责人（responsible_person）或创建者（created_by）→ 返回 `40905` 拒绝删除，需先转移/处理项目。其历史训练会话/报告保留（含姓名快照，报告直链可查）。若 Oracle 侧仍在职，下次同步会以默认密码重新创建（前端删除确认弹窗需提示此点）。
- **请求参数**：仅 path 参数 `userId`。
- **响应示例**：
```json
{ "code": 0, "message": "ok", "data": null }
```
- **错误码**：`40401 用户不存在`、`40903 内置超管账号禁止该操作`、`40905 用户仍是训练项目负责人，禁止删除`（v1.2 新增，message 形如"该用户仍是 2 个训练项目的负责人/创建者，请先处理项目"）

#### FP-10/FP-20 设置/取消超级管理员

- **Method / Path**：`POST /api/sm/admin/users/{userId}/super-admin`
- **说明**：设置或取消超管标记。**仅超管可调用**（JwtFilter 校验）。
- **请求参数**：

| 参数 | 位置 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| userId | path | string | 是 | |
| isSuperAdmin | body | boolean | 是 | true 设置 / false 取消 |

- **请求示例**：
```json
{ "isSuperAdmin": true }
```
- **响应示例**：
```json
{ "code": 0, "message": "ok", "data": null }
```
- **错误码**：`40301 无权限`（非超管）、`40401 用户不存在`、`40903 内置超管账号禁止该操作`（对 admin 传 false）

### 2.7 同步模块

#### FP-17 手动触发同步

- **Method / Path**：`POST /api/sm/admin/sync/trigger`
- **说明**：手动触发同步任务，**仅超管可调用**。`full=true` 全量（忽略水位），`full=false` 增量。同步在后台线程执行，接口立即返回。
- **请求参数**：

| 参数 | 位置 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| full | query | boolean | 否 | 默认 false（增量） |

- **请求示例**：`POST /api/sm/admin/sync/trigger?full=true`
- **响应示例**：
```json
{ "code": 0, "message": "ok", "data": { "triggered": true } }
```
> `triggered=true` 只表示"已提交到后台线程"，**不代表同步成功**——全量 3.4 万行要跑几十秒到分钟级，
> 接口不会挂着等。结果一律回 `GET /admin/sync/status` 看。
- **错误码**：`40301 无权限`（非超管）、`50301 已有同步任务正在执行，请等待上一轮结束`（进程内 `AtomicBoolean` 互斥）

#### FP-17 同步状态查询

- **Method / Path**：`GET /api/sm/admin/sync/status`
- **说明**：最近 10 次同步记录（排查用，仅超管）。
- **响应示例**：
```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "list": [
      {
        "syncType": "INCREMENT",
        "watermark": "2026-09-22 18:03:12",
        "total": 142,
        "inserted": 3,
        "updated": 138,
        "deleted": 1,
        "skipped": 0,
        "status": "SUCCESS",
        "errorMsg": null,
        "startedAt": "2026-09-23 02:00:00",
        "finishedAt": "2026-09-23 02:00:41"
      }
    ]
  }
}
```
> `syncType`：`FULL` / `INCREMENT`；`status`：`SUCCESS` / `FAILED`。
> **v1.2 字段变更**：`disabled` 废弃（离职不再置禁用），新增 `deleted`（离职/调出范围被删除的用户数）与
> `skipped`（因仍是训练项目负责人被保护跳过的删除数——非 0 时需人工处理项目归属）。
> `watermark` 是本轮续接到的位置，**首轮全量或库里还没有任何 SUCCESS 记录时为 `null`**
> （表里存的是 `1970-01-01` 占位值，只为满足列的 NOT NULL，不会当成真实水位读回去）。
> `FAILED` 记录同样带 `errorMsg` 和已推进到的位置，但下一轮的水位仍取上一条 SUCCESS——失败不漏人。
- **错误码**：`40301 无权限`
