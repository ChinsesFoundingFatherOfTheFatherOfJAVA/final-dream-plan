# 编排智能体 · 四个工具的描述优化（2026-09-18）

> 背景：实测对话链路正常但**工具零调用**（`/v1/chat-messages` 200、助手正常回复、我的工具端点 0 次调用）。
> 小模型（Qwen3-30B-A3B）选择工具主要依赖工具描述与参数说明，因此先把这四处文字补齐/重写。
> 配套：04a-DifyDSL-编排智能体.md（原始 OpenAPI schema）、07-实现说明与偏差记录.md D21。

## 0. 两处非文字设置（比描述更关键，务必一起改）

| 设置 | 现状 | 改为 | 原因 |
|------|------|------|------|
| `traceId`、`sessionId` 的**必填**开关 | 必填（required: true） | **关闭（非必填）** | schema 里必填但绑定变量解析为空时，Dify 会在发起 HTTP 前判定"必填缺失"而**直接不调用工具**——这正是"零调用"的最可能原因。关闭后即使为空也会调用，我的端点会返回明确错误，便于定位 |
| `traceId`、`sessionId` 的**参数说明** | null | 「系统自动注入，请勿填写、不要编造；留空即可」 | 避免模型自行编造 ID（我会按设计拒绝编造值） |

> 变量绑定仍是正解：开始节点建 `session_id` / `trace_id` 两个变量（名字必须与 Java 注入的 inputs 一致），
> 4 个工具的这两个参数都绑到它们。Java 侧已注入这两个输入（实测 chat-messages 容忍未声明输入）。

## 1. create_topic

**工具描述**

```
创建或重命名训练主题草稿。
【何时调用】① 当前没有主题（theme_status=new）且用户已给出明确方向（主题方向 + 至少一个训练目标），
或材料摘要已足以判断方向 → 立即调用，无需征得用户同意；② 用户要求修改主题名称或描述时。
【何时不要调用】已有主题、只是要调整场景/客户画像/冰山/评估维度内容时——改内容请用 generate_theme。
【调用后】在回复中告知"已为你创建草稿主题《主题名》"，并继续细化目标。
```

**参数说明**

| 参数 | 说明 |
|------|------|
| traceId | 系统自动注入，请勿填写、不要编造；留空即可 |
| sessionId | 系统自动注入，请勿填写、不要编造；留空即可 |
| topic | 主题名称，专业凝练，如"柔性智造销售话术训练""订单运营职能实战演练"，不超过 50 字 |
| description | 主题描述一句话，格式为"训练目标 + 训练人群" |

## 2. update_artifact

**工具描述**

```
以 JSON-Patch 增量更新主题产物。
【何时调用】仅用于结构性小改动，例如修改某份材料的"学员可见"属性、替换材料列表。
【何时不要调用】场景单元、客户画像、冰山模型、评估维度的内容修改一律走 generate_theme
（keepExisting=true），禁止自己编造 JSON 补丁去改场景内容。
```

**参数说明**

| 参数 | 说明 |
|------|------|
| traceId | 系统自动注入，请勿填写、不要编造；留空即可 |
| sessionId | 系统自动注入，请勿填写、不要编造；留空即可 |
| patches | JSON-Patch 数组，op 固定为 full_replace；path 形如 /materials；value 为替换后的完整值 |

## 3. generate_theme

**工具描述**

```
生成或重新生成完整的训练主题配置（场景单元、客户画像、冰山模型、评估维度与权重）。
【何时调用】① 用户已明确同意开始生成（如"可以""开始生成""没问题""就按这个来"），且你已在聊天中
给出场景规划方案；② 更新模式下用户要求改动场景/画像/维度内容时（此时 keepExisting=true）。
【调用后】只在回复中说"正在生成训练主题配置，请稍候…"（可用引用块），真实结果由右侧面板实时推送；
禁止预先描述或编造生成结果。同一时间只允许一个生成任务在跑，若右面板显示仍在生成，提醒用户稍候。
```

**参数说明**

| 参数 | 说明 |
|------|------|
| traceId | 系统自动注入，请勿填写、不要编造；留空即可 |
| sessionId | 系统自动注入，请勿填写、不要编造；留空即可 |
| goal | 核心训练目标一句话，由你从对话或材料中总结 |
| audiences | 训练人群，JSON 数组，如 ["销售代表"] |
| materialSummary | 材料要点摘要，无材料时传空串 |
| keepExisting | true=在现有内容基础上局部调整（更新模式）；false=全新生成 |

## 4. generate_cases

**工具描述**

```
为场景单元生成实战案例（对练剧本）。
【何时调用】主题配置已生成完成，且用户同意生成案例时。
【用法】支持一次批量生成多个场景：scenarioIds 留空表示全部场景（推荐用法，不要逐个征询用户）。
每完成一个场景会推送一次事件，右侧面板会逐个出现案例。
【调用后】只说"正在生成实战案例，右侧面板将逐个更新"；禁止编造案例名称、角色或台词。
```

**参数说明**

| 参数 | 说明 |
|------|------|
| traceId | 系统自动注入，请勿填写、不要编造；留空即可 |
| sessionId | 系统自动注入，请勿填写、不要编造；留空即可 |
| scenarioIds | 要生成的场景 ID 数组，如 ["sc-01","sc-02"]；留空=全部场景 |
| difficulty | 难度：0=按场景特点自定（用户未指定时传 0）；1=简单；2=中等；3=困难 |

## 5. 改完后我做什么

重跑对话链路（清实例 → 起单实例 → 发一条明确指令的消息），判定标准两条：
1. 我的工具端点日志出现 `create_topic 新建草稿主题`（或端点返回的错误原因）；
2. 管理端主题列表出现智能体提到的那条新主题。

若仍是零调用，则按用户要求"再想办法"，可选方向（按代价从低到高）：
① 把 `generate_theme`/`generate_cases` 触发词写进系统提示词的操作化步骤（模型更倾向按步骤走）；
② 在编排应用的开始节点前加一个"关键词路由"条件分支，用代码节点判断"用户是否明确要求生成"，
   命中则直接进 Agent，否则走普通回复——绕开模型自主决定；
③ 改为"Java 侧关键词兜底"：我在收到用户消息时判断是否含生成意图，命中就直接调用工作流（不依赖 Agent 决策），
   Agent 只负责对话与解释。这是最可靠但最"重"的方案，需要你确认产品语义是否接受。
