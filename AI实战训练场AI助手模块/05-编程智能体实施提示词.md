1. 人工：执行 06-建表SQL（8 新表 + 2 表小改）
2. 人工：Dify 导入 3 份 DSL → 发布 → **打样**（真材料跑通全链路，见文末打样清单）→ 3 个 key 填入 properties

## 提示词 A：后端编程智能体

```
你要在 D:\JACK\final_dream\after-end\AtualCombatTraining（Spring Boot 4.0.8 / Java 21 / MyBatis-Plus 3.5.17，已有管理端代码）中实现「AI 设计助手」模块后端。

【必读（按序）】
1. 01-需求文档.md —— FP-30~43 范围与验收标准（GWT）
2. 03-接口文档.md —— HTTP 接口 + WS 协议规范 + bizType 事件字典 + artifact schema 与校验规则（实现以此为准，协议帧逐字段照抄线上格式）
3. 02-技术实现方案.md —— 架构、8 张新表、关键流程（5.1~5.5）、难点对策
4. 06-建表SQL.md —— DDL（已执行，实体字段必须与列逐列比对）
5. 04a-DifyDSL-编排智能体.md 末尾「Java 侧对接要点」—— Dify OpenAPI 调用与 SSE 映射

【任务清单】
A. 基础设施：
   · pom 加 spring-boot-starter-websocket
   · DifyProperties（base-url + 3 个 app key，properties 纯 ASCII 占位）
   · 线程池：generateExecutor（core=2，生成任务）、publishExecutor 复用既有
B. websocket 包：WsChatHandler（TextWebSocketHandler）、WsSessionRegistry（sessionId→Set<Session>，多端广播）、
   WsFrameEncoder（帧构造：事件序列/seq 单轮递增/part index 递增/messageId 服务端生成 xxx_0 格式；心跳 ping 20s，80s 无 pong 关闭）
C. controller/AssistantController：POST /api/act/assistant/sessions（建/查会话+返回 artifact）、
   GET .../sessions/{id}/messages（cursor 分页：limit+nextCursor，按 created_at+db_id）、
   POST .../files（multipart 存 ./act-files/，类型白名单）、POST .../asr（百炼 Paraformer，复用 SpeechTraining 模式，SDK 返回判空——历史教训）
D. controller/InternalToolController：4 个工具端点（03 文档 §2.5，路径 /api/act/internal/tools/*，仅内网）：
   · create_topic：建/改草稿 + 回填会话 theme_id + 推 topic-changed
   · update_artifact：JSON-Patch（op=full_replace 按 path 定位替换，fastjson2）+ 推 artifact-updated
   · generate_theme：受理即返回，异步调 Dify 主题生成工作流（blocking 300s）→ ArtifactSchemaValidator 校验（03 §3.5 规则，失败把错误拼入参重试 1 次）→
     应用到工作区 artifact（materials 保留）→ 推 artifact-generated in_progress（生成中先推）→ completed/failed
   · generate_cases：受理即返回，逐场景（并发 2）调案例生成工作流（120s）→ 单场景重试 1 次 →
     每场景合入 artifact.scenarios[].cases + 推 case-generated；difficulty=0 时按方案 04c 要点 4 的规则映射
E. dify 包：DifyAgentClient（POST /v1/chat-messages streaming：SSE 解析 agent_message/message_end/error/conversation_id 回存；
   inputs={theme_status, artifact_summary: 结构摘要非全量, material_summary}）、DifyWorkflowClient（POST /v1/workflows/run blocking）、
   DifyEventTranslator（SSE chunk→part-content，80ms 节流聚合）
F. WsChatHandler 主链路（02 方案 5.1）：chat 帧→落库→ack→（confirm 走 ConfirmService；其余进 Dify）→事件流→助手消息落库（含 data 块）
G. service/ConfirmService：幂等（content_hash 比对）→ 事务翻译落库（先删当前版本场景/维度/画像/案例旧行再插；
   维度引用展开：全局维度+dimensionWeights → 每场景独立 act_evaluation_dimension 行）→ 推 save-success
H. 发布初始化：POST publish（校验有 confirmed 内容且状态∈{0,3}）→ status=1 → publishExecutor 逐案例编译 act_drill_script
   （compiled_payload=角色全量+开场白+场景摘要+维度ID列表，纯 Java 组装无 LLM）→ 全成 status=3 + 建 act_theme_version
   （复制逻辑复用既有保存流程）→ GET script-progress（total=案例数）→ POST publish/retry（仅 failed）
I. 全部 Dify 调用记 act_ai_call_log

【工程红线（历史教训，违反必返工）】
- 实体字段与 DDL 列逐列比对（多列=Unknown column 直接炸）；JSON 列实体用 String+JacksonTypeHandler（List<String> 场景另按 MP 规范）
- 落库方法 builder/setter 显式传参，禁长参数列表
- properties 纯 ASCII；DashScope SDK 同步 call 返回 null 即失败必须判空
- 统一响应 {code,message,data}；code=0 成功
- 关键类/方法中文 Java 注释；实现与 02 方案有偏差时先停下与用户确认并同步文档

【验收】
1. mvn compile + 全部单测通过（至少覆盖：帧构造 seq/part 语义、SchemaValidator 通过/拒绝、确认幂等、维度展开正确性、
   script-progress 进度计算、confirm 并发幂等）
2. 写一个 WS 集成测试脚本（或 curl 脚本）走通：建会话→连 WS→发 chat→收到完整事件序列
3. 逐条核对 03 接口文档请求/响应字段名与实现一致（含 WS 帧的每个字段名）

【禁止】
- 不访问线上平台 train.chinajack.com
- 不改动 SpeechTraining 工程；gateway 无需变更（WS 走既有 /api/act 前缀，需确认网关支持 WS upgrade，若不支持向用户报告需加配置而不是自行改）
- Dify 调用只在对话/生成发生（发布编译不调 Dify）
```

## 打样清单（人工，Dify 导入 3 份 DSL 后执行——**编码前必做**）
