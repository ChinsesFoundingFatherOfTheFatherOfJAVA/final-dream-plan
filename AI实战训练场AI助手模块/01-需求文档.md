## 1. 项目概述

复刻绚星「AI实战训练场」的 **AI 设计助手**：通过多轮对话创建/修改训练主题，聊天区（左）+ 主题产物面板（右）双栏交互，产物在对话中持续演进，点「确认」才落库，草稿自动创建、发布后异步初始化剧本。

**技术路线（已定案）**：Dify 1.10.1（编排+生成）+ Java 自建三平面协议（会话/WS 消息事件/artifact 版本化）+ Vue3 前端。业务逻辑（版本、落库、事件、初始化）全部收在 Java，Dify 只负责理解与生成。

**协议忠实度原则**：WS 消息与事件格式逐字段照抄线上（HAR 实证）。有意偏离只剩流式输出做 50~100ms 节流聚合（线上逐 token 碎片化）。2026-09-17 的「剧本单产物」已于 2026-10-27 收回，发布按线上每案例两份剧本计数。

## 2. 术语

| 术语 | 含义 |
|------|------|
| 会话（session） | 一个主题绑一个会话，对话历史持久化，重进恢复 |
| artifact | 主题的结构化 JSON 快照（8 顶级字段），版本化存储 |
| 工作区版本 | 对话中持续修改的 artifact 版本，确认前不落业务库 |
| 确认（confirm） | 右面板「确认」按钮，将 artifact 翻译落库到业务表 |
| 块（part/part 块） | 消息内容的组成单元：text / file / data(action) |
| 编排智能体 | Dify Agent（side_free），对话主入口，挂 4 个工具 |
| 剧本编译 | 发布后的异步初始化：案例 → 可练习的剧本结构存储 |

## 3. 功能需求

### FP-30 入口跳转

- **功能描述**：三个入口进入 AI 助手对话页：
  1. 列表页「+ 创建新主题」（替换原占位提示）
  2. 详情页头部「AI 设计助手」按钮（替换原占位提示）
  3. 场景单元管理「+ 通过 AI 助手添加」（替换原占位提示）
- **路由**：`/sparring/freesimulate/assistant/:themeId?`（themeId 可空=新建）。新建时无左历史、无右面板（纯聊天直到方向明确）。
- **验收标准**：
  - Given 列表页 When 点击「+ 创建新主题」Then 进入对话页，themeId 为空
  - Given 已有主题详情页 When 点击「AI 设计助手」或「+ 通过 AI 助手添加」Then 进入对话页且携带该主题 ID
  - Given 主题已结束 When 点击入口 Then 允许进入查看历史，但输入框禁用（只读会话）

### FP-31 会话建立与恢复

- **功能描述**：
  - 新建：前端 `POST /api/act/assistant/sessions {themeId?}` → 返回 sessionId（新建主题场景由后端在收到 topic-changed 时回填 theme_id）
  - 恢复：带 themeId 进入时后端按 theme 查会话，存在则复用，不存在则新建
  - 建立后连接 WS `/api/act/ws/chat?sessionId=xx`，连接成功自动发送 `common-session-start` action（params: sessionId + projectId）
  - 历史消息：`GET /api/act/assistant/sessions/{id}/messages?limit=1000`（cursor 分页，照线上）
- **验收标准**：
  - Given 新建入口 When 进入 Then 建会话+连 WS+发 session-start，助手发出开场白（Dify 编排智能体首答）
  - Given 已有主题已有会话 When 重进 Then 历史消息完整恢复（含事件块渲染），右侧面板按当前 artifact 呈现
  - Given 同一主题多端打开 When 同时连接 Then 两端均能收到事件（会话注册表多 Session）

### FP-32 聊天界面（左侧）

- **功能描述**：
  - 消息流：用户气泡 / 助手气泡（markdown 渲染，含表格）；事件块渲染为卡片：文件解析卡片（"正在解析→解析完成"）、生成中提示（"> 正在生成中等难度的实战案例，请稍候..."）、结果概览等（**事件 data 块在消息流中按线上行为内联展示文本性 content，其余仅驱动右面板**）
  - 输入框：多行文本 + 发送按钮（空内容禁用）+「上传资料」按钮 +「语音输入」按钮
  - 文件上传：选择文件 → `POST /api/act/assistant/files`（multipart）→ 拿 fileId → 以 file 块发送（含 name/fileType/fileSize）
  - 语音输入：按住/点击录音（复用 useRecorder，16kHz WAV）→ `POST /api/act/assistant/asr` → 文本回填输入框，用户确认后发送
  - 助手回复期间输入框禁用；顶部"AI 生成内容仅供参考"声明（照线上）
- **验收标准**：
  - Given 输入文本 When 发送 Then 用户气泡立即出现，助手流式回复（打字机效果）
  - Given 上传 pptx When 上传完成 Then 用户侧出现文件消息，助手回复"解析成功"摘要（事件块显示解析中→完成两态）
  - Given 点击语音输入并说话 When 松开 Then 识别文本回填输入框（<2 字提示重试）
  - Given 助手生成中 When 再次输入 Then 输入禁用（防并发）

### FP-33 主题产物面板（右侧）

- **功能描述**：
  - 布局：主题名标题 +「确认」按钮（紫色主按钮）+ 五 Tab：培训材料 / 场景单元 / AI角色类型 / 冰山模型 / 评估标准
  - **展开时机**：主题方向明确（topic-changed 事件）后页面分左右两栏；此前纯聊天
  - 数据源：artifact JSON；实时更新（artifact-updated / artifact-generated / case-generated 事件驱动增量渲染）
  - 培训材料 Tab：材料卡（文件名/类型/大小）+「学员可见」开关（visibility 字段）+ 提示文案
  - 场景单元 Tab：单元卡（序号/名称/限时/案例数）+ 展开 13 项内容 + 实战案例卡（角色/难度/开场白）
  - AI角色类型 Tab：客户画像卡（类型/典型特征/决策关注点/沟通风格/常见痛点）
  - 冰山模型 Tab：水面以上（知识/技能）+ 水面线 + 水面以下（角色/自我概念/特质/动机）+ 模型说明
  - 评估标准 Tab：维度卡（名称/权重/解释/三档评分标准）+ 通过分数线（passScore）
  - 「确认」按钮：点击 → 确认弹窗（新建:"确认保存当前内容"；已发布更新:"确认更新已发布主题"文案，照线上）→ 发 confirm action → save-success 后提示成功
- **验收标准**：
  - Given 方向明确 When topic-changed 到达 Then 页面切分左右两栏，右面板出现主题名
  - Given artifact-generated in_progress When 事件到达 Then 右面板对应 Tab 数据渐次出现（不整页刷新）
  - Given 案例生成完成 When case-generated 到达 Then 对应场景单元卡出现"1 个案例"+案例详情
  - Given 点击确认并确认弹窗 When save-success 返回 Then 成功提示；详情页场景单元已可见（仍草稿）
  - Given 五个 Tab When 切换 Then 各 Tab 内容与 artifact 字段一一对应渲染

### FP-34 WS 消息与事件协议

- **功能描述**：照抄线上（详见 03-接口文档 §3 WS 协议规范）：
  - 客户端帧：`{type:"chat", payload:{message:{id,role,content:[块],sender}}, traceId, spanId}`、`{type:"pong"}`；块类型 text/file/data(action)
  - 服务端帧：事件序列 `user-message-ack → session-start → message-extra-info → message-start → N×(part-start → part-content×M → part-end) → session-finish`；心跳 server `ping`（客户端 20s 内回 pong）
  - data part 的 delta 为 data_delta（JSON 字符串流式），text part 为 text_delta
  - seq 每轮从 1 递增；messageId 服务端生成（助手消息 `xxx_0` 后缀格式照抄）
  - **节流**：Java 侧把 Dify chunk 按 50~100ms 聚合后推送
- **验收标准**：
  - Given 发送 text 块消息 When 服务端处理 Then 完整事件序列到达且 seq 连续
  - Given 服务端 ping When 到达 Then 客户端自动回 pong（超时断线有重连提示）
  - Given data part 流式 When 各 delta 拼接 Then 拼接结果为合法 bizType JSON

### FP-35 Dify 编排智能体（side_free）

- **功能描述**：Dify 1.10.1 Agent 应用（对话主入口）。系统提示词定义：角色（Nova，实战演练项目设计助手）、阶段流程（背景了解→目标确认→场景规划（先在聊天给方案征询）→触发生成→产品档案询问（可跳过）→案例生成→收尾）、工具使用规则、事件文案规范（"正在生成…"渐进提示）。挂 4 个工具：
  1. `create_topic`（HTTP 工具→Java）：参数 topic/description → 建草稿 → 事件 topic-changed
  2. `update_artifact`（HTTP 工具→Java）：参数 patches(JSON-Patch 数组) → 工作区更新 → 事件 artifact-updated
  3. `generate_theme`（HTTP 工具→Java 触发，Java 调主题生成工作流）：参数 goal/audience/materialSummary/currentArtifact → 事件 artifact-generated(in_progress→completed)
  4. `generate_cases`（HTTP 工具→Java 触发，Java 循环调案例生成工作流）：参数 scenarioIds/difficulty → 逐场景事件 case-generated
- **验收标准**：
  - Given 新会话首条 session-start When 到达 Then 编排智能体返回开场白（询问行业/对象/目标或邀请上传材料）
  - Given 用户给足方向 When 编排智能体判定 Then 自动调用 create_topic（不征询确认），随后追问目标细节
  - Given 用户说"开始生成" When 编排智能体 Then 调 generate_theme，聊天中先给场景规划表再触发生成
  - Given 生成完成 When 编排智能体 Then 汇报概览（场景/画像/维度数量）并进入下一阶段建议
  - Given 用户要求调整（如"把场景1改成…"）When 理解 Then 调 update_artifact 或重新 generate_theme

### FP-36 主题生成智能体（Dify 工作流）

- **功能描述**：Workflow 应用。输入：goal/audience/materialSummary/existingArtifactJson（更新模式）。分步生成（LLM 节点串行）：场景单元列表（含 13 项+行为目标+dimensionWeights）→ 客户画像（2~4 个）→ 冰山模型（六层）→ 评估维度（全局 3~6 个，权重合计 100，三档评分标准）→ 代码块聚合为完整 artifact JSON 输出。Java 侧 schema 校验（8 顶级字段+必填子字段+维度权重合计=100），失败带错误重试 1 次。
- **验收标准**：
  - Given 输入目标+人群 When 工作流执行 Then 输出合法 JSON（Py/Java 双端校验通过），场景数 4~7、每场景维度引用存在于全局维度表
  - Given schema 校验失败 When 重试 Then 第二次输出修正；两次失败则事件标记 failed 并在聊天中告知
  - Given 更新模式 When existingArtifactJson 非空 Then 仅变更相关部分，保留用户已确认内容基调

### FP-37 案例生成智能体（Dify 工作流）

- **功能描述**：Workflow 应用，单场景输入：scenarioJson + difficulty + customerProfile。输出单案例结构：scriptName（"A：B"式标题）/actorName/actorPosition/actorType/actorPersonality/actorCommunicationStyle/scriptBackground/scriptOpening（含情绪/动作舞台指示）/difficulty。Java 逐场景循环调用（并发 2），每完成一个触发 case-generated 事件。
- **验收标准**：
  - Given 批量指令"4 个场景都生成" When 编排智能体 Then 一次 generate_cases 调用完成全部场景（实测线上支持，不逐个征询）
  - Given 单场景生成 When 完成 Then case-generated 事件含 scriptName/difficulty/scenarioId
  - Given 某场景生成失败 When 重试 1 次仍失败 Then 该场景标记失败并在聊天中告知，其余不受影响

### FP-38 artifact 版本化存储

- **功能描述**：`act_ai_artifact` 表：artifact_id + version_no + content(JSON) + status(working/confirmed) + confirmed_at。对话期间修改 = 更新当前工作区行（version_no 不变，等于线上"对话中不产生新版本"）；确认 = 该行标记 confirmed + 生成确认版本号。**一个主题一条 artifact 主记录，版本自增**。
- **验收标准**：
  - Given 对话中多次修改 When 未确认 Then 只有工作区行变化，业务表（场景单元等）无任何写入
  - Given 确认 When 成功 Then artifact 行 status=confirmed；再次对话修改则基于 confirmed 内容新开工作区版本
  - Given 重进会话 When 未确认的修改存在 Then 右面板展示工作区版本（未确认修改不丢失）

### FP-39 自动建草稿

- **功能描述**：编排智能体判定"方向明确"（用户给出主题方向，或文件解析完成提取出方向）即调 create_topic → Java 建 act_theme 草稿行（默认主题设置：joinMode=1/difficulty=2/practiceMethods 全选等）+ 回填会话 theme_id + 推送 topic-changed 事件。**无需用户确认**，列表页立即可见（草稿态）。
- **验收标准**：
  - Given 新建会话 When 方向明确 Then 草稿主题出现在列表页（含名称/描述，统计为 0）
  - Given 草稿主题 When 打开详情页 Then 显示基本信息+默认设置，场景单元 0 个
  - Given 会话已有 theme_id When 再次 topic-changed（改名）Then 更新主题名称/描述（不重复建）

### FP-40 确认落库

- **功能描述**：confirm action 到达 → Java 事务：artifact 标记 confirmed → 翻译落库：
  - scenarios → act_scenario_unit（主题当前版本号 + 13 项字段 + **行为目标 behavior_goals JSON** + dimensionWeights 暂存）
  - 全局维度按场景引用展开 → act_evaluation_dimension（每场景独立行，权重取 dimensionWeights）
  - customerProfiles → act_customer_profile（新表）
  - cases → act_case_script（新表，关联场景单元）
  - materials → act_ai_material（新表）
  - act_theme 冗余字段同步（名称/描述/画像数 customer_profile_count）
  → 推送 save-success 事件（含 ex_id=主题ID）
- **验收标准**：
  - Given 确认 When 事务提交 Then 详情页场景单元/维度/内容设计四计数全部按 artifact 呈现，主题仍为草稿
  - Given artifact 中维度 A 被场景 1(40%)/场景 2(30%) 引用 When 落库 Then 两场景各有独立维度行且权重正确
  - Given 重复点击确认（并发）When 第二次到达 Then 幂等拒绝（已 confirmed 不重复落库）

### FP-41 发布与初始化

- **功能描述**：
  - 草稿态详情页头部按钮组变为：「发布主题」（火箭图标）+「AI 设计助手」（已实现的暂停/结束等按钮不出现，已实现页面需按状态调整按钮可见性——**对既有管理端的小改造**）
  - 发布弹窗（照线上：主题名/场景数/参与学员/预估时间 ≈ 场景数×2 分钟 + 三条说明）
  - `POST /api/act/admin/theme/{id}/publish` → 先校验已确认内容且当前版本至少有 1 个实战案例；不满足则拒绝，不改状态、不升版本。通过后 status=发布中(沿用现有枚举 1) → 异步任务把每个已确认案例落成一份对练剧本 → 全部成功才 status=已发布(3) + **创建 act_theme_version 业务版本记录**（AI 路径版本在发布时产生）+ 冗余同步
  - 进度接口：`GET /api/act/admin/theme/{id}/script-progress` → `{total: 当前版本案例数, completed, failed, progress, status}`；前端 5s 轮询（线上 60s，内网保持 5s）
  - 详情页蓝色初始化横幅按场景数显示（已完成场景/场景总数）→ 完成绿横幅也用场景数。进度接口的 `total` 不拿来念成场景数
- **验收标准**：
  - Given 草稿+已确认内容+至少 1 个案例 When 发布 Then 状态发布中 → 轮询进度 0→100 → 自动已发布 + 版本历史 +1
  - Given 已确认内容但当前版本没有案例 When 发布 Then 拦截提示"请先在 AI 助手中生成并确认实战案例"，状态与版本不变
  - Given 未确认任何内容 When 发布 Then 拦截提示"请先在 AI 助手中确认内容"
  - Given 某案例编译失败 When 重试 1 次仍失败 Then 进度接口标 failed，横幅显示"初始化失败，请重试"，可点击重发
  - Given 已发布主题 When 再次进入 AI 助手修改并确认 Then 确认后内容更新（版本内场景覆盖），再发布走同一初始化流程

### FP-42 材料上传与解析

- **功能描述**：上传接口存本地 `act-files/`（FileStorageService 模式）→ file 块入会话 → Java 调 Dify 文档提取（或本地 Tika，见技术方案）提取文本 → 摘要（>3 万字截断+首尾摘要）存 act_ai_material + artifact.materials 更新 → parse-file 事件（status 0→1）→ 编排智能体获得材料摘要上下文。
- **验收标准**：
  - Given 上传 2.6MB pptx When 解析完成 Then 助手能基于材料内容答复（材料摘要进入上下文），右面板培训材料 Tab 出现该文件
  - Given 开关「学员可见」When 切换 Then artifact.materials[].visibility 更新并事件同步
  - Given 不支持的格式（如 exe）When 上传 Then 前端拦截（限 ppt/pptx/doc/docx/pdf/txt/md）

### FP-43 既有管理端联动改造

- **功能描述**：
  1. 列表页/详情页三个 AI 入口从"占位提示"改为真实跳转（FP-30）
  2. 主题设置·内容设计页「进入 AI 设计助手调整内容」按钮接真实跳转
  3. 内容设计四计数中 customerProfileCount 改读真实值（确认落库后来自 act_customer_profile count；未确认时读 artifact）
  4. 详情页按钮组按状态调整：草稿=[发布主题+AI设计助手]；发布中=[AI设计助手+导出报表(禁用)]；已结束=[导出报表]
  5. 状态枚举不变（0草稿/1发布中/3已发布/4已暂停/5已结束），发布中=初始化中
- **验收标准**：
  - Given 各状态 When 打开详情页 Then 按钮组按上表呈现，占位提示全部消失
  - Given 确认落库后 When 打开内容设计页 Then 客户画像显示真实数量

## 4. 非功能需求

- **费用保护**：Dify 调用按次计费（vllm 自建实为资源成本），Java 侧所有 Dify 调用记录 act_ai_call_log（会话/智能体/入参摘要/耗时/token），供审计。
- **可替换性**：Dify 的三个应用 key 全部配置化（application.properties），Java 通过 Dify OpenAPI（`/v1/chat-messages`、`/v1/workflows/run`，blocking + streaming）调用，不依赖 Dify 私有 SDK。
- WS 鉴权：sessionId 即凭证（内网系统，与管理端现状一致），后续统一登录体系时补 token。
- 前端 ID 一律 string；SCSS 手写；vue-tsc 通过。
- properties 纯 ASCII。
