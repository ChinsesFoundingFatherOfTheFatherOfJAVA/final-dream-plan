## 1. 背景与范围

把课件管理交付时的两个"仅存储/占位"升级为真实现：

1. **转码 worker**：视频/音频课件发布后自动 ffprobe 回填元数据（时长/分辨率）+ ffmpeg 单档 HLS + 抽 16k wav；转码管理页（截图21/22）转正
2. **AI 字幕管线**：ASR（百炼 paraformer-v2）→ SRT（简中）→ qwen 翻译（繁/En/Vi）→ 四语言 SRT 落盘；字幕管理页（截图23/24）转正；编辑字幕抽屉（截图26）从占位转正

**明确依赖既有实现**：课件上传合并（`/api/kng/admin/upload/merge`）、kng_courseware 表、发布状态机（本专项的 kng_media_job **取代** PublishSimulateJob 的模拟逻辑）、转码/字幕管理两页的骨架。

## 2. 功能需求

### MT-01 元数据自动回填（ffprobe，同步）
- **触发**：课件上传**合并完成时**（merge 接口内同步执行，毫秒级）；编辑页追加文件同样触发。
- **行为**：ffprobe 读取时长（秒，回填 standardMinutes/standardSeconds——**仅当表单值为空或 0 时回填，不覆盖用户已填值**）、分辨率、编码格式、文件大小；写 kng_courseware 新列 media_width/media_height/media_codec（元数据列）。
- **效果**：发布表单的"标准时长"在文件上传后自动填好（视频/音频类）；文档类无变化。
- **验收**：
  - Given 上传 12分52秒视频 When 合并完成 Then 表单标准时长自动显示 12分52秒
  - Given 用户先手填 10分0秒 When 上传视频合并 Then 保持 10分0秒（不覆盖）

### MT-02 转码 job（异步 worker）
- **触发**：视频/音频类课件**发布时**（POST courseware 接口内投递 kng_media_job type=transcode）；取代原 PublishSimulateJob 模拟。
- **行为**（worker 进程/线程执行）：
  1. 状态 pending → running
  2. ffmpeg：源文件 → **单档 HLS**（原清晰度，m3u8+ts 分片，output 目录 `/kng-files/transcode/{coursewareId}/`）
  3. ffmpeg：抽音频 → 16kHz 单声道 wav（`/kng-files/audio/{coursewareId}.wav`，供 MT-03）
  4. 成功 → success，记录耗时；失败 → failed，记录 stderr 尾部 500 字符入 error_msg
- **发布状态机改造**：原"定时30s模拟"改为——发布后课件 status=**发布中**，**转码 success 后置已发布**；转码 failed 后**保持发布中**（列表可见，转码管理页可见失败原因，可重试），原发布流程的"解析中"提示文案不变。
  - 文档/图片/压缩/HTML/外链类：无转码 job，发布后走原逻辑（成功即已发布——保留一个轻量延迟或直接已发布，见 02 §决策）
- **并发与幂等**：worker 并发上限 2（配置）；同一课件同类型 job 未终结时不重复投递（幂等键 courseware_id+type+活跃状态）。
- **验收**：
  - Given 发布 10 分钟视频 When 转码中 Then 转码管理页"转码中"tab 可见该课件；完成后移出且课件变已发布；m3u8 可通过 `GET /api/kng/admin/courseware/{id}/play` 播放
  - Given 转码失败（损坏文件） Then 转码管理"转码失败"tab 显示，失败原因列有内容；点【重试】重新投递

### MT-03 AI 字幕 job（管线）
- **触发**：视频/音频类课件发布成功（转码 success 后自动串联，**且**课件 ai_subtitle_enabled=true）转码时已产出 wav；或编辑页开启 AI字幕开关后手动触发（入口：编辑字幕抽屉的【生成字幕】按钮，见 MT-05）。
- **管线步骤**（kng_media_job type=subtitle，状态机含细分 stage）：
  1. pending → running(stage=asr)：wav 上传 OSS 临时对象（`kng-asr-tmp/{coursewareId}.wav`，预签名 URL，**用完即删**）→ 调百炼 paraformer-v2 异步转写（提交 task_id → 轮询）→ 取结果 JSON
  2. stage=srt：JSON sentences → SRT（简中）落盘 `/kng-files/subtitles/{coursewareId}/zh.srt`
  3. stage=translate：SRT 按块批量（50条/批）喂 qwen（繁體中文/English/Tiếng Việt 三语言，prompt 要求仅译文、保持序号与时间戳结构）→ 落盘 ha.srt/en.srt/vi.srt
  4. success：kng_courseware.subtitles_flag=1；OSS 临时对象删除
  5. 任 stage 失败 → failed + error_msg + 已删临时文件；**ASR/翻译分开重试**（失败 stage 重跑，SRT 已生成的语言不重翻）
- **模型与切换**：默认 paraformer-v2（0.288元/h，句级毫秒时间戳）；配置项 `asr.model` 可切 fun-asr（0.79元/h）；**ASR 引擎接口抽象**（输入 wav 路径→输出中间 JSON{sentences:[{begin_ms,end_ms,text}]}），未来 FunASR 本地实现同接口即可替换（内网约束当前已确认允许出网，本地化不启动）。
- **验收**：
  - Given 开启AI字幕的视频发布转码完成 When 字幕管线跑完 Then 字幕管理"识别中"tab 经历可见后清空；/kng-files/subtitles/{id}/ 下四语言 SRT 齐全且时间戳格式正确
  - Given 管线在翻译阶段失败 When 重试 Then 仅重跑翻译，zh.srt 不变
  - Given 同课件重复触发字幕 When 已有活跃 job Then 拒绝重复投递

### MT-04 转码管理页转正
- 数据源改为 `POST /api/kng/admin/media/jobs`（查 kng_media_job type=transcode）：
  - **转码中 tab**=running/pending；列=名称/分类/上传日期/已转换时间(=now-running_start，实时)/分享者/备注(空)/操作【重试】(仅 failed 行)
  - **转码失败 tab**=failed；多"失败原因"列（error_msg 截断展示，悬浮全量）；"查看常见出错原因"链接→静态提示弹窗（常见原因清单文案照原平台推断，标注）
- 搜索（名称/分类/分享者）+分页同现有骨架。
- **验收**：Given 无转码任务 Then 两 tab 均空态；Given 有失败任务 When 重试成功 Then 移回转码中直至成功。

### MT-05 字幕管理页与编辑字幕抽屉转正
- **字幕管理页**：数据源改 kng_media_job type=subtitle；识别中 tab=running/pending（列=名称/分类/开始时间/操作人/操作）；识别失败 tab=failed+失败原因+【重试】。
- **编辑字幕抽屉**（课件管理截图26 的完整实现）：
  - 左侧视频预览：`<video>` 播放 m3u8（hls.js，工程已有播放诉求时引入；**无字幕轨**纯预览）
  - 右侧语言 tab（简体中文/繁體中文/English/Tiếng Việt）+ 字幕条目列表（时间戳 mm:ss + 文本 + 行内编辑铅笔）
  - 行内编辑：点铅笔→该行变输入框→失焦/确定保存（整语言 SRT 重写落盘）
  - 底部【取消】【保存】：保存=当前语言全部编辑持久化（保存中语言粒度）
  - 新增【重新生成字幕】按钮（右上角，二次确认"将覆盖现有字幕"）→ 重投 MT-03 job
- **验收**：
  - Given zh.srt 300 条 When 打开抽屉 Then 简中 tab 渲染 300 行，切繁中 tab 显示 ha.srt 内容
  - Given 编辑第 5 条文本 When 保存 Then 重新打开抽屉显示新文本，时间戳不变

### MT-06 播放接口（HLS）
- `GET /api/kng/admin/courseware/{id}/play`：返回 `{playUrl}`（m3u8 相对路径，经静态资源映射或流式接口）；详情页/编辑字幕抽屉的视频预览消费。
- 转码未完成/非视频类：返回 code=1"暂无可播放内容"。

## 3. 非功能需求
- 转码不阻塞发布后课件的管理操作（编辑/移动等照常）
- 百炼轮询间隔 5s、超时 30 分钟；qwen 单批失败重试 2 次
- 全部 SRT 为标准格式（`1\nHH:MM:SS,mmm --> HH:MM:SS,mmm\n文本`），与原平台抓包实测一致
- 成本护栏：单课件字幕管线成本 = ASR(≈0.29元/h×时长) + 翻译(≈0.05元)；日志记录每次调用用量

## 附录A. 不做的功能点及原因

| 项 | 原因 |
|------|------|
| 多清晰度 HLS（1080p/720p 双档） | 拍板单档；后续需要再扩 |
| OpenCC 繁体转换 | 拍板纯 qwen（繁体是真翻译非字符转换，对齐原平台实测） |
| FunASR 本地部署 | 内网约束确认允许出网；ASR 接口已隔离，需要时可加本地实现 |
| 字幕说话人分离（diarization） | 培训视频单人主讲为主，暂不需要 |
| 水印/加密流（原平台 drm 痕迹） | 不在本次范围 |
| 词级时间戳展示 | 句级即可满足字幕 |
| 字幕管理"开始时间/操作人"真实语义外字段 | 沿用列表列即可 |

## 附录D. PoC 任务书（两段）

### PoC-1：ffmpeg 本地验证（半天，零成本）
拿一个 5 分钟真实培训视频（mp4），在 OnlineClassroom 部署机（或本机）执行并记录：
1. `ffprobe -v quiet -print_format json -show_format -show_streams 视频.mp4` → 确认时长/分辨率/编码可稳定取到
2. `ffmpeg -i 视频.mp4 -c:v libx264 -c:a aac -hls_time 10 -hls_playlist_type vod out.m3u8` → 记录转码耗时；浏览器 hls.js 播放 m3u8 验证可播
3. `ffmpeg -i 视频.mp4 -ar 16000 -ac 1 audio.wav` → 记录 wav 大小（估算 OSS 临时上传体积）
4. 检查 ffmpeg 构建的许可（`ffmpeg -version` 看 --enable-gpl）：**必须 LGPL 构建**；若带 GPL 换 OpenH264 方案
**产出**：命令记录+耗时数据+许可结论。

### PoC-2：ASR+翻译双线对比（半天，<1 元）
用 PoC-1 的 wav（手工传 OSS 或任意公网 URL）：
1. paraformer-v2（免费额度内）与 fun-asr 各转写一次（dashscope Transcription.async_call），记录：准确率（人工抽听对比 10 句）、句级时间戳质量、端到端耗时
2. 取 zh 结果前 50 条转 SRT，qwen 翻繁/En/Vi 各一次，检查结构保持（时间戳/序号不变率）
3. 输出对比表：准确率/耗时/成本/时间戳精度 → 回填附录C，确认生产默认模型
**产出**：对比表+SRT 样例文件（存观察素材目录）。
